# T-060 — Fix macOS flake in watcher test `reports_external_edits`

Owner: Claude (lead, Rust owner). Branch: agent/claude/T-060. Worktree: isolated
`watcher-ci-fix`. Reviewer: Codex (cross-review required before merge).

Context: GitHub CI run 36671387173 passed on Windows and Linux. On macOS it failed at
`src-tauri/src/vault/watcher.rs:342`, where the first batch received did not contain `ext.md`.
The test assumed that the first asynchronous watcher batch holds the target file. macOS
FSEvents can deliver unrelated startup/root events first.

Goal: make the test wait, up to a bounded deadline, for a batch that mentions the expected
visible file. Leave production watcher semantics unchanged unless there is evidence of a
runtime defect.

Owned files:
- src-tauri/src/vault/watcher.rs (the `#[cfg(test)]` module only)
- .agents/briefs/T-060.md, .agents/handoffs/T-060.md
- the T-060 row in .agents/TASKS.md

Out of scope: runtime watcher code, dependencies, CI workflows, retries in CI, `#[ignore]`,
and weakening the assertion.

Acceptance criteria:
- `reports_external_edits` collects batches until one contains `ext.md` or 5 s elapse. On
  timeout it panics and prints every batch it received.
- A deterministic helper test shows that unrelated first batches do not falsely pass, that a
  target which never arrives fails at the deadline with diagnostics, and that the match is on
  exact paths.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` pass on
  Windows/Linux/macOS CI.

Test commands (run from `src-tauri/`):
- `cargo test vault::watcher`
- `cargo fmt --check`
- `cargo clippy --all-targets -- -D warnings`
- `cargo test`
