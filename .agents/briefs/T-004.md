# T-004: Markdown editor with live preview and autosave (Phase 0)

**Owner:** codex · **Branch:** `agent/codex/T-004` · **Base:** `main`

## File ownership

You may create or edit **only** `src/features/editor/**`. Everything else is read-only for you. If you need a change elsewhere, describe it in your handoff note instead of making it.

## Contract you build against (read these first)
- `src/ipc/types.ts`: use `backend` from `src/ipc`: `readFile`, `writeFile(path, content, expectedModifiedMs)` (rejects with `{ code: "Conflict" }` if the file changed on disk), and `onVaultChanged`.
- `src/App.tsx` renders `<Editor key={activePath} path={activePath} />` in `.content`, so a new path remounts the editor. Export `Editor` (props: `{ path: string }`) from `src/features/editor/index.tsx`, replacing the stub.
- `src/styles/theme.css` defines the CSS variables. Use them only. Put your styles in `src/features/editor/editor.css`.
- The CodeMirror 6 packages are already installed (`@codemirror/state`, `view`, `commands`, `language`, `lang-markdown`, `language-data`, `search`, `autocomplete`, and `@lezer/highlight`). Do **not** add dependencies.

## Requirements
1. **CodeMirror 6** with Markdown (GFM), code-block highlighting through `@codemirror/language-data`, history, search (Ctrl+F), the default keymaps, line wrapping, and a readable centered column (max width about 760px). The note title (file name without `.md`) is shown above the editor.
2. **Obsidian-style live preview.** On lines that don't contain the cursor or selection, hide the Markdown syntax marks and show the formatted result:
   - heading `#` marks (heading sizes scale by level)
   - `**bold**`, `*italic*`, `~~strike~~`, `` `inline code` ``
   - `[text](url)` shows only the link text, styled as a link
   - blockquote `>` marks get a left border
   - bullet markers render as `•`
   - `---` renders as a horizontal rule
   - fenced code blocks get a background, and the fence lines are dimmed

   **Task items** `- [ ]` / `- [x]` render as a checkbox widget, and clicking it toggles the text. On the active line(s), the raw Markdown is shown. Implement this with `ViewPlugin` decorations built from the syntax tree (`syntaxTree`), only for visible ranges.
3. **Autosave**: save 500 ms after the last change, and also flush on blur and on unmount. Always pass the last known `modifiedMs` as `expectedModifiedMs`, and update it from the `WriteResult`. Show a small status in the title bar: `Saved` / `Saving…` / `Unsaved changes`.
4. **Conflicts**: if `writeFile` rejects with `Conflict`, stop autosaving and show a banner, *"This note changed on disk."*, with two buttons:
   - **Reload from disk**: discard local edits.
   - **Keep my version**: write without `expectedModifiedMs`.
5. **External changes**: subscribe to `backend.onVaultChanged`. If a `created` or `modified` change includes this path:
   - with no unsaved edits, reload silently and keep the cursor position (clamped to the document length).
   - with unsaved edits, show the conflict banner.

   If a `removed` or `renamed` change includes this path, show *"This note was moved or deleted."* and pause autosave, with a **Save here anyway** button.
6. **Theme** the editor using only the CSS variables (so it follows light/dark automatically), with a monospace font for code.
7. It must handle a 1 MB note without typing lag.

## Tests (required)
Use Vitest + Testing Library in `src/features/editor/*.test.tsx`. Mock the backend with the in-memory one:

```ts
const mem = vi.hoisted(() => ({ b: null as null | import("../../ipc/memoryBackend").MemoryBackend }));
vi.mock("../../ipc", async (orig) => {
  const mod = await orig<typeof import("../../ipc")>();
  const { createMemoryBackend } = await import("../../ipc/memoryBackend");
  mem.b = createMemoryBackend({ "Note.md": "# Title\n\nHello **world**" });
  return { ...mod, backend: mem.b };
});
```

`mem.b.externalWrite(path, content)` simulates an outside edit. `EditorView.findFromDOM(el)` gives you the view so you can dispatch edits.

Cover: loading content; autosave after the debounce (use fake timers) writes to the backend; flush on unmount; a silent reload on an external change with no local edits; the conflict banner when there are local edits, plus both of its buttons; and the moved/deleted banner. Also unit-test the live-preview decoration builder as a pure function over an `EditorState`: which ranges are hidden on inactive lines and not on the active line.
