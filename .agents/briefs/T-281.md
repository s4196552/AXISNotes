# T-281: make the "local only" AI check unbypassable

Wave 1 of the improvement plan the human approved on 2026-11-25 (security audit finding).

## Problem

- `is_local_url` (`src-tauri/src/ai/mod.rs`) decided whether an endpoint is on this
  computer with string checks: `host.starts_with("127.")`, and the host split only on `/`
  and `?`. These counted as local: `http://127.0.0.1.evil.com/v1`,
  `http://evil.com#.localhost`, `http://evil.com\.localhost`, `http://localhost@evil.com`.
  Notes in "AI: local models only" folders could then go to a remote server.
- `endpoint_problem` (`src-tauri/src/ai/settings.rs`) accepted `http://` for any host, so
  API keys and notes could cross the network unencrypted.
- reqwest follows redirects by default, so a local server could redirect a request to a
  remote host.

## Do

1. Parse with `url::Url`. Local = http/https, no user info, host a loopback IP
   (127.0.0.0/8, `::1`), exactly `localhost` or ending in `.localhost`. Unparsable = not
   local.
2. Refuse saving `http://` unless local; show the error in the provider settings UI.
3. Local providers: no redirects. Remote providers: redirects never to a different host
   class.
4. Tests for every bypass URL, `[::1]`, `localhost:11434`, `127.0.0.1:1234/v1`,
   `foo.localhost`, uppercase hosts and trailing-dot `localhost.`.
5. Keep the note that localhost doesn't prove on-device inference; don't widen what
   counts as local.
