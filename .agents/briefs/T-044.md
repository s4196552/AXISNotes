## Acceptance criteria

1. Two concurrent `serve` starts: exactly one holds the lock; the other exits 3; the launcher
   helper returns ready with one `instanceId`.
2. Kill Connect (`taskkill /F`): lock released; next ensure-running starts a new instance with
   a new `instanceId`; old-instance requests get 409 `stale-instance`.
3. Impostor on the old manifest port (test HTTP server) is treated as unavailable; no secret
   is revealed (assert request carried only signature headers).
4. Every pre-check and signing vector passes against the live server via raw HTTP: Origin,
   Referer, Sec-Fetch-*, OPTIONS, wrong Host (`localhost:<port>`, attacker domain), missing/
   bad signature, skew > 60 s, replayed nonce, revoked client, pending-approval client (401
   for everything except `connect/status`), `bootstrap` on any path other than
   `connect/status` and `/pair` (401).
5. Hub-scoped client cannot register as notes; notes client cannot `projects.write`
   (only `members.write` for `notes` refs); `apps.approve` only for hub.
6. Registration with endpoint `http://localhost:…`, a non-loopback address, a path, or an
   endpoint whose describe signature/instance/descriptor mismatches is rejected.
7. Project create/update/members/delete: stale revision → 409; replay same op → same result;
   same op different payload → 409; recreate tombstoned ID → 409; deleting a project makes
   zero adapter calls (assert the fake adapter received no request).
8. Federated search with fake adapters (fast, slow 2 s, erroring, not registered, semantic
   unsupported) returns within 2.6 s with ready/unavailable(timeout)/unavailable/unsupported
   groups in fixed order; memberFilter contains only that app's refs.
9. Backup → modify → restore reproduces projects/tombstones/operations; all clients must
   re-pair; `export` JSON contains no secret material (grep for key bytes/base64). A client
   revoked after the backup is still revoked after restore.
10. Log file contains no request bodies, snippets, secrets or signatures (test writes known
    canary strings and asserts absence).
11. Idle exit after the configured idle period (test override `AXIS_CONNECT_IDLE_SECS`).
12. `icacls` smoke check on the home directory passes (see S2-D06).
13. Launcher cases of S2-D07 through `axis-connect-client` with a counting spawn hook:
    first install (one spawn, pair, register); Connect running + never-paired app (zero
    spawns, pair); invalidated credential while running (zero spawns, re-pair); revoked
    (state `unpaired`/`revoked`, no further `/pair` until `pair_again`); restore with apps
    closed (fresh bootstrap key read, re-pair, no spawn loop); restore while an app runs
    (one spawn, re-pair); hung lock holder with no manifest (one spawn exits 3, `unavailable`
    / `connect-unverifiable` within 6 s); impostor on the old port (one spawn, impostor
    receives only a bodyless status request).
14. Pairing response bytes contain no plaintext secret (capture the raw HTTP response and
    assert the unsealed secret's bytes and base64url forms are absent); a tampered
    `sealedSecret` is rejected by the client and no credential is stored.
