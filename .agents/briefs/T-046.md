## Build

1. **Policy editor** (Settings → AI → Source permissions, and the file tree context menu):
   list rules from `suiteAiPolicy()` grouped by path, origin badge (policy/legacy), invalid
   rules shown in red with the error and "AI blocked here". Edit a rule: mode, operations
   (read/suggest/apply; suggest/apply force read), executions (on-device/private-server/cloud),
   models (pick exact candidates from `suiteAiCandidates()`, showing provider name, model ID,
   endpoint host and endpointId, or explicit "Any model"). Save with `suiteAiSetRule` and the
   current `fileRevision`; on `Conflict` reload and tell the user; on
   `WideningNeedsConfirmation` show the diff and a second explicit confirm, then resend with
   `confirmWidening: true`. Never widen without that second step.
2. **Effective policy view** for a selected path (`suiteAiEffective`): the chain root → file,
   the intersection result, and a plain sentence ("Only on-device model llama3.3:8b may read
   this; nothing may apply changes").
3. **Candidates and evidence**: each candidate's execution location, verified/unverified and
   evidence method/time; "Re-check" calls `suiteAiProbe`; "This endpoint is a private server"
   / "treat as cloud" call `suiteAiDeclareLocation`. No "treat as on-device" control exists.
4. **Plan display** (AskAi, FixText and other AI dialogs in `src/features/ai/**`): show the
   decision and each blocked candidate with its reason before sending; disable Send when denied.
5. **Migration notice**: when `migration` is non-empty, a dismissible-per-revision banner in
   AI settings listing each stricter interpretation (e.g. Journal/Public now local-only).
6. **Enforcement label**: `enforcement === "native-v1"` → "Enforced by AXISNotes"; `"demo"` →
   persistent "Demo — AI permissions are not enforced" banner in every policy view. Never show
   the enforced label for demo.
7. **AXIS Connect settings**: toggle (`suiteSetEnabled`), status from `suiteStatus()` and the
   `suite://status` event with human text for each state (not-installed, unavailable,
   pending-approval "approve AXISNotes in AXIS Hub", read-only vault), no endpoint or secret shown.
8. **Project badges**: note header strip and file-tree dots from `suiteProjectsFor`; refresh on
   `suite://projects-changed`; "stale" styling when Connect unavailable; add/remove membership
   from the note header menu (`suiteProjectAddMember/RemoveMember` with the project revision;
   on conflict reload). Badges never change note content. Integration disabled → nothing shown.
9. **Relink dialog**: for missing and ambiguous resources surfaced by status/command results,
   list candidates and offer "Same note" (`suiteRelink`) and, for ambiguous, "Different note"
   (`suiteDetach`); never preselect or auto-confirm.
10. **Legacy rule writers** (S2-D29a): Settings folder rules (`AiSettings.tsx`) and the file
    tree "AI access" menu (`FileTree.tsx`) call `suiteAiSetLegacyRule` with the config
    revision, then reload the config store (`useConfig.getState().load()`); widening uses the
    same two-step confirmation as item 1. On `suite://ai-rules-preserved` reload the config
    store. No UI path writes `ai.folders` through `writeFile`.
11. **AI-output insert** (S2-D33): Ask AI insert, Fix text apply, note handwriting insert,
    note diagram insert and the canvas handwriting/diagram inserts call
    `suiteAiApply(runId, destinationPath)` first and insert only on success; show the
    returned `notice` ("… will also follow Medical's AI rules …") and let the user cancel
    before inserting. On any rejection (unknown/expired `runId`, denied check,
    `ProvenanceLimit`) show the fixed message and insert nothing; for `ProvenanceLimit` the
    message says the destination already follows 256 sources' AI rules and suggests another
    destination or clearing provenance. Effective policy view shows `provenance` chain
    entries and a "Clear AI provenance" action that uses the two-step widening confirmation.
12. **Connect states**: `unpaired` with reason `revoked` shows a "Pair again" button
    (`suitePairAgain`); `unavailable` shows its reason text.

## Acceptance criteria (Vitest + Testing Library against memoryBackend)

1. Every control above renders from memory backend fixtures; demo banner shown; the enforced
   label is absent under `demo` and present when a test stub returns `native-v1`.
2. Widening flow requires two explicit actions; a single click never sends
   `confirmWidening: true` (assert calls).
3. Invalid/unavailable policy renders a blocked state; Send disabled in AI dialogs when the plan
   decision is denied; blocked candidates listed with reasons.
4. No "on-device" declaration control exists (query by role/text).
5. Badges: disabled → none; ready → names/colours; unavailable → stale; deleted project removed
   after a `suite://projects-changed` event; badge actions never call `writeFile`.
6. Keyboard access for all new controls; labels for screen readers.
7. Existing AI, file tree, editor and settings tests still pass unchanged or with justified
   updates listed in the handoff.
8. Legacy rules: setting/removing a folder rule from Settings and from the file tree calls
   `suiteAiSetLegacyRule` and never `writeFile` with changed `ai.folders` (assert calls);
   removal requires the two-step confirmation.
9. For each of the six insert call sites and each rejection kind (unknown/expired `runId`,
   denied check, `ProvenanceLimit`): a rejected `suiteAiApply` inserts nothing (editor
   document, `editNote` calls and canvas scene unchanged) and shows its message; a
   successful one inserts once, after the call resolves; the notice is shown and Cancel
   inserts nothing.
10. Revoked state shows "Pair again", and clicking it calls `suitePairAgain` exactly once.
