# T-278: never overwrite a broken settings file

Wave 1 of the improvement plan the human approved on 2026-11-25 (research of every aspect of the project).

`useConfig.load()` (`src/app/config.ts`) fell back to `DEFAULT_CONFIG` on any read or parse error, and the next `update()` wrote it over the user's file. That erased `ai.folders` privacy rules, which the Rust layer deliberately fails closed on. `update()` also wrote on every slider tick, and failed writes became unhandled rejections from 27 `void update(...)` callers.

Done when:
- An unreadable or invalid file is kept and backed up, writes are blocked, and a banner offers Try again or Use defaults.
- Changes are saved after a short pause, one save at a time, and flushed before a vault switch, closing or an update install.
- A failed save is shown.
- Tests cover each of these.
