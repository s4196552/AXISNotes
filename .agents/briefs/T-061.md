## Context

Hosted run 36672935411 at 98e7f8e passes all three `check` jobs. The `e2e-linux` job built
and launched the real app under tauri-driver/WebKitWebDriver/Xvfb, but 17 tests passed and
36 failed across all 8 specs. Observed symptoms (see the T-042 handoff and job
https://github.com/s4196552/AXISNotes/actions/runs/36672935411/job/109752696514):

- Many title/grid/sidebar text assertions receive an empty string from `getText()`.
- Intercepted clicks.
- Missing completion (autocomplete) UI.
- A timeout while setting up AI settings.

The same 53 tests pass on native Windows (WebView2/msedgedriver). The cause is not
established. It may be WebKitWebDriver text extraction, real Linux rendering/layout, focus or
click interception, fixture readiness, or an app bug. Do not assume it is WebDriver-only.

## Goal

Find the proven cause of each failure class with evidence. Then make the minimal E2E or CI
change that fixes each class while keeping every visible-UI assertion. Reach a fully green
hosted run, including `e2e-linux`, with Windows native E2E still green.

## Out of scope / forbidden

- App runtime files: `src/**`, `src-tauri/**`, capabilities, permissions, IPC/API surface,
  `tauri.conf.json`.
- Dependencies, `package.json`, the lockfile and `docs/DECISIONS.md`. A GitHub Action used
  only for artifact upload (`actions/upload-artifact`) is allowed. Name its major version in
  the handoff.
- Skipping or removing tests and specs. No `.skip`, no platform gating, no `continue-on-error`
  and no retries used to mask failures.
- Weakening assertions. Do not replace visible-text checks with `textContent`/`innerHTML`
  checks that would pass on hidden or unrendered content. Do not raise timeouts without a
  measured cause.
- Changing native-input coverage (real keyboard/clicks through WebDriver) or the AI privacy
  checks (`never` folder rules, memory-only keys, mock provider).
- If evidence shows an app runtime bug, stop. Record the evidence and a proposed narrowly
  scoped follow-up task in the handoff. The lead will create and assign it separately.

## Required approach

1. **Capture before changing.** Add a bounded failure hook in `wdio.conf.ts`, such as
   `afterTest` on failure. For each failure, write the following to a directory under
   `e2e/artifacts/` or `$RUNNER_TEMP`:
   - a screenshot;
   - `document.title`;
   - an outerHTML excerpt of the failing selector, truncated to a fixed size;
   - `innerText` and `textContent` for that selector;
   - `isDisplayed`, `getElementRect`/`getBoundingClientRect`;
   - computed `display`, `visibility`, `opacity`, `content-visibility`, `font-family` and
     `font-size`;
   - `document.activeElement`;
   - the element at the click point (`document.elementFromPoint`) for intercepted clicks;
   - the window size.

   Cap the number and size of artifacts. Never dump environment variables, config-directory
   contents or keys.
2. **Version capture.** In `e2e-linux`, log the versions of the following before the tests
   run:
   - the OS image;
   - `webkit2gtk-4.1` and `webkit2gtk-driver` packages;
   - `WebKitWebDriver --version`;
   - tauri-driver (`cargo install --list`);
   - Node/pnpm, Xvfb and the screen geometry.
3. **Upload artifacts** with `if: failure()` (or `always()` for the bounded version log) and
   short retention. Artifacts must contain only fixture-vault data.
4. **Minimal probe.** Add one focused probe spec or helper that opens a seeded note and grid
   and checks the editor title text and one grid cell. Compare `getText()`, `innerText`,
   `textContent`, `isDisplayed` and the rect. This separates a WebKit text-extraction problem
   from content that is truly not rendered.
5. **Classify every failing test** into one of these classes, and record which one in the
   handoff:
   - (a) empty `getText` on visibly rendered content;
   - (b) content not rendered or not yet ready;
   - (c) click intercepted or wrong focus;
   - (d) AI setup readiness;
   - (e) other, or an app bug.
6. **Fix only proven causes.**
   - Readiness: use condition-based waits (`waitUntil` on the visible state). Do not use
     fixed sleeps.
   - Class (a): use a shared helper that still requires `isDisplayed()` and a non-zero rect
     before it reads rendered text.
   - Class (c): wait for the overlay to clear, scroll into view or adjust the window size.
     Each change must reference the captured evidence.
   - Every helper must behave identically on Windows.

  - a table that lists all 36 originally failing tests with class, evidence (artifact or log
    reference) and fix;
  - the captured runner/driver/WebKit versions;
  - the exact commands run, with their results.
- No assertion removed or weakened, and no test or spec skipped. The total test count is
  ≥ 53, plus any probe tests.

- Full local Windows native Tauri E2E passes on the final commit.
- Failure artifacts are bounded, uploaded only from CI, and contain no secrets or environment

- No files outside the ownership list changed (`git diff --stat 36a2a25..HEAD`).
- Claude has written a genuine review in `.agents/reviews/T-061.md` that approves the final
  commit. Only then does the lead integrate.
