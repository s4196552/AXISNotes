# T-282: signed updates and publish guards

Wave 1 of the improvement plan the human approved on 2026-11-25 (`docs/research/improvements-2026-11-25.md`). The security audit of the same day rated the folder updater the top risk.

## Problem

- The updater (`src-tauri/src/updates.rs`, `updates_commands.rs`) trusted `latest.json` and only checked a SHA-256 kept in the same folder as the installer.
- `auto_install` and `check_on_launch` defaulted to on, and the NSIS installer is unsigned. Anything that can write to the updates folder (`%USERPROFILE%\AXISNotes Updates`, or a NAS share) could run code on the next launch.
- `scripts/publish-update.ps1` built whatever was in the working tree, with no checks and no tag. The folder holds about 114 installers (2.4 GB). Only `v0.3.0` and `v0.3.1` are tagged.

## Do

1. **Signed manifest.** Sign `latest.json` with Ed25519 and embed the public key in the app. Verify the signature over the manifest bytes (version, file name and SHA-256) before offering or installing. An unsigned or invalid manifest is shown as "available, not verified" for a manual install only, and is never installed automatically. Tests: valid, tampered version, tampered hash, missing signature, wrong key.
2. **Key handling.** `publish-update.ps1 -NewKey` generates a key pair. The private key lives outside the repository (`%APPDATA%\AXISNotes\update-signing.key`, ACL'd to the user) and is never committed. Generate the real pair once, embed the public key, and record the key's location and the backup reminder in the handoff.
3. **Publish guards.** Refuse on a dirty tree (untracked files ignored), when not on `main`, or when `pnpm lint`, `pnpm typecheck` or `pnpm test` fail (`-SkipChecks` for emergencies, logged). Sign the manifest, create the annotated tag `vX.Y.Z` (no push), and keep only the 10 newest installers (`-Keep N`).
4. **Defaults.** Keep `check_on_launch` on; automatic install only for verified manifests.
5. **Authenticode.** Optional `-CertThumbprint` calls signtool; otherwise warn. Don't buy or create certificates.

## Done when

- `cargo test` and `pnpm lint && pnpm typecheck && pnpm test` pass in the worktree.
- A dry run of the script on a dirty tree refuses (output shown in the review).
- Brief, handoff, review and a TASKS.md row are written; merged into `main` with `--no-ff`.
- No real publish and no push. The lead ships one patch after Wave 1 using the script.
