## Build

1. **Sections**: nested tree with name, colour, icon (Lucide allowlist or emoji), create,
   rename, delete (items move to parent or are deleted only after explicit confirmation),
   drag and keyboard move/sort (Alt+↑/↓, Ctrl+[ / Ctrl+]), cycle prevention surfaced as an
   error from the backend.
2. **Items**: add wizard per kind — website (URL, opening: Hub session / default browser /
   browser + profile), application (pick .exe via native dialog command exposed by T-047, args
   list editor one argument per row, never a single command string), shortcut (.lnk), file,
   folder, registered URI (scheme registration flow with explicit confirmation), AXIS resource
   (pick from federated search). Custom icon/logo upload via the T-047 asset command; named
   presets for Google Stitch and Open Design as ordinary website shortcuts.
3. **Launch UI**: click/Enter launches by item ID; errors shown plainly; websites open in a
   session tab strip showing the session name, with an always-visible "Open in browser" button.
4. **Sessions & browsers**: manage sessions (create/rename/clear with confirmation), pick
   detected browsers and profiles, register custom browser executables.
5. **Projects**: list/create (generates `prj_` ID via the backend helper), edit name/colour/icon
   with revision conflict handling, delete with a confirmation that states "content is not
   deleted", membership list with ready/missing/unavailable states and a relink hint that
   opens the owner app.
6. **Federated search**: query box, keyword/semantic mode selector (semantic only when an app
   advertises it; otherwise the group shows "unsupported"), grouped results by app with
   explicit unavailable/unsupported states, plain-text snippets, open action, project filter.
7. **Connected apps**: list pairings with status; approve pending pairings (explaining the
   same-user limitation in one sentence); revoke.
8. **AI organisation suggestions**: hidden when AI is off; shows exactly what will be sent
   (names/kinds, domains only if opted in), then a reviewable diff of moves/new sections with
   per-change checkboxes; Apply sends only checked changes.
9. **Demo label**: when the memory backend is active, a persistent "Demo — nothing is launched"
   banner.

## Acceptance criteria (Vitest + Testing Library, memory backend)

1. Gaming section with Spotify (website/Hub session), Discord (application with args list) and
   VALORANT (application) can be created and reordered by keyboard alone.
2. Args editor never joins arguments into one string (assert backend payload is an array).
3. Two Facebook shortcuts with two sessions show different session names; Open in browser is
   visible for every website item.
4. Scheme registration requires the confirmation step; denied schemes show the backend error.
5. Project delete confirmation text states content is preserved; conflict reloads the project.
6. Search shows a ready group, an unavailable group and an unsupported group simultaneously;
   empty ready group reads "No results", distinct from unavailable.
7. AI review applies only checked changes; nothing is sent when AI is off.
8. All controls reachable by keyboard; icons have accessible names.
