## Acceptance criteria

1. Attach Biology.md to a test project, rename it in the app, move its folder, delete
   `index.db` and restart: `resolve` returns the same `ResourceRef` as `ready` with the new path.
2. External rename while closed → `missing` with a relink candidate; no automatic rebind; after
   `suite_relink` the old ref resolves `ready`. Watched delete then create at the old path →
   new ID, old ID `missing`. Offline (watcher stopped): append edit → same ID; delete and
   recreate with unrelated content → `ambiguous` with that file as candidate; recreate with a
   retained `^blockId` → same ID; changed file under 3 distinct lines → `ambiguous`;
   `suite_detach` then mint → new ID; `identity.json` contains none of the canary lines.
3. Copy the vault folder and open the copy while the original exists → refs `ambiguous` until
   the user chooses; duplicated task `^blockId` → `ambiguous`.
4. `suite_task_anchor` refuses when the line or revision changed; appends ` ^xxxxxx` otherwise;
   `notes.set-task-completed` replay returns the same result; different payload → conflict;
   stale revision → conflict; crash injected between journal and write recovers correctly.
5. Webview-originated `write_file` to `.axisnotes/suite/identity.json`,
   `.axisnotes/suite/provenance.json` or `.axisnotes/ai-policy.json` fails (unit test + E2E in
   T-049). Legacy rules (S2-D29a tests, all six): generic write removing `Medical: never` +
   hotkey change → hotkey saved, `never` still on disk, AI still denied, event emitted;
   generic `never`→`any` and `local`→`any` → rule unchanged; generic write while current
   config is malformed → refused, bytes unchanged; stale-store narrowing survives a folder-icon
   write; native removal without confirmation → `WideningNeedsConfirmation`, bytes unchanged;
   native narrowing without confirmation → applied.
6. Policy: medical (on-device only, exact Ollama model) + study (cloud OpenAI model + local)
   together → only the exact local model allowed; OpenAI candidate blocked before any request
   reaches the mock server (assert zero requests); fallback to a disallowed provider blocked.
7. Localhost gateway / cloud-proxied Ollama model / failed probe → unverified → denied for
   on-device-only sources; legacy `local` folder behaves the same.
8. Unparseable `config.json`, `"sometimes"`, unknown policy version, unknown field, empty
   lists, deleted-after-seen policy file → all deny with status explaining why.
9. Legacy `Journal: local` + `Journal/Public: any` → Public is local-only; migration note lists it;
   `config.json` bytes unchanged after open.
10. Changing a provider base URL changes `endpointId` and existing allowlists stop matching.
11. Adapter server: every pre-check and signing vector passes over raw HTTP; Hub-originated
    mutation rejected; Notes works with integration disabled, with Connect killed mid-session,
    and with the Connect binary absent.
12. No key, secret, signature or note content in logs (canary test), DOM-facing IPC payloads, or
    URLs.
13. Provenance (S2-D33): Medical-derived summary applied into local-only `Local/Summary.md`;
    widen `Local` to cloud (confirmed); run with `Summary.md` + cloud model → blocked with
    reason `provenance`, mock cloud receives zero requests. Tighten Medical to deny →
    `Summary.md` denied for all. Source deleted / renamed / ambiguous → still restricted.
    Destination renamed → still restricted. Clear without `confirmWidening` refused. Unknown
    or expired `runId` or denied check → error, provenance unchanged. Invalid
    `provenance.json` → all AI denied. Cap boundary vectors (S2-D33, sources `S001`–`S257`):
    exactly 256 unique sources → all 256 entries preserved with their IDs; reapplying
    recorded IDs → still 256; adding `S257` → `ProvenanceLimit`, `provenance.json` bytes and
    revision and `identity.json` unchanged; tighten `S001` (first) to deny → `Summary.md`
    denied for every model; restore, tighten `S256` (last) → denied; mock cloud receives zero
    requests; a file with 257 entries for one destination, or an entry without `resourceId`
    → all AI denied.
14. Connect states (M2, with the T-044 build): never-paired Notes with Connect already running
    pairs without spawning; revoked Notes shows `unpaired`/`revoked` and does not re-pair until
    `suitePairAgain`.
