# T-293 review: live AI on canvases

**Verdict: approve** (Claude, self-verification under the 2026-11-10 rule)

## What changed

- **Connector canvas tools** (`src-tauri/src/mcp/canvas.rs`, `tools.rs`, `mod.rs`):
  - `read_canvas` lists each live element with its id, type, rounded position and size, text or label, non-default colors, note path (cards), and `from`/`to` (arrows). Labels are folded into their shape or arrow.
  - `create_canvas`, `add_to_canvas` and `change_canvas` are write tools, so they're offered only when "Allow changes" is on.
  - `add_to_canvas` adds labelled rectangles, ellipses and diamonds, free text, note cards and arrows by id. Ids can be the caller's own or ones already on the canvas. Shapes without a position go in a grid to the right of the existing content.
  - `change_canvas` moves, resizes, relabels and recolors elements. Arrows are re-routed to follow their shapes, and an empty text removes a label. Deleting a shape also deletes its label and its arrows.
  - Elements are written as complete Excalidraw elements, so the file is a valid scene whether or not the app is open. Every edit raises the element version and sets a new nonce.
  - Writes are read, edit, then write with an mtime check. A write that lands in between is retried twice on the new version, which is safe because edits are by id.
  - Canvases in folders kept from cloud AI are refused (same message for missing and hidden). So are note cards of notes Claude can't see.
- **Live merge** (`src/features/canvas/liveMerge.ts`, `Canvas.tsx`, `useFileDocument.ts`):
  - `useFileDocument` takes an optional `absorb`. On an outside change, and on a save conflict, the canvas merges the file into the mounted scene instead of remounting Excalidraw.
  - With no unsaved edits, the file's version is taken as is. With unsaved edits, each element keeps whichever side changed it last (Excalidraw's `reconcileElements`). An element the file no longer has is removed unless it was edited here since.
  - Each merge is one undo step. Images in the file are added.
  - Text flagged `customData.axisRemeasure` is measured with the real font (`restoreElements` with `refreshDimensions`), centered in its shape or on its arrow, and the shape grows if the text doesn't fit. This happens on merge, and on open for files changed while the canvas was closed.
  - New outside additions are scrolled into view only when none of them is already visible.
- **Live diagram maker** (`DiagramMaker.tsx`, `lib/diagram.ts`, `Canvas.tsx`, `diagrams.css`):
  - On canvases, "Draw on the canvas as it's written" is on by default. `partialGraph` reads the complete nodes and edges from the streaming JSON. Mind-map nodes appear once they are linked to the center.
  - The canvas redraws the draft at a fixed origin with `CaptureUpdateAction.EVENTUALLY`, so undo takes back the finished diagram as a whole.
  - The checked graph replaces the draft and the dialog closes. A failed or stopped run removes the draft.
  - While drawing, the dialog shrinks to a status card in the corner.

## Findings

None blocking. Known limits:

1. Sizes written by the connector are estimates until the app shows the canvas; it then measures them. While the app is closed, a long label can overflow its box in other Excalidraw viewers.
2. The app writes the file again after each outside change, because Excalidraw adds fields and reorders keys. Concurrent writes are handled by the retry on each side.
3. Live drafts are autosaved like any other edit. If the app closes mid-stream, the partial diagram stays on the canvas.
4. The in-app AI chat can't draw on canvases yet. That needs tool use in the chat and is a separate task.
