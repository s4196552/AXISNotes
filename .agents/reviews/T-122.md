# Review: T-122 (tab, dashboard widget and card dragging with pointer events)

**Verdict:** approve

Human request (2026-10-21): check tab and dashboard tile dragging in the real app and switch them to pointer drags
if broken.

## Evidence

- T-121 showed, with a real OS mouse drag, that HTML drag and drop is swallowed in the Windows app (Tauri's native
  file-drop handling). Tabs, dashboard widgets and pinned cards used the same HTML drag and drop.
- The real-mouse check of tabs before this change is **not valid**: the synthetic mouse input went to another
  application in the foreground (the human's game), not AXISNotes, so it proved nothing. Real mouse input was
  stopped there; all later checks send events into the test app's page only (DevTools protocol), never the OS
  mouse. The tabs' brokenness is inferred from the shared mechanism, not separately reproduced.

## Change

- `src/app/usePointerDrag.ts` (new): a pointer-event drag hook (5 px threshold, Escape cancels, the click ending a
  drag is swallowed, grabbing cursor via `body.pointer-dragging`), plus `dropBeside` (the `[attr]` item under the
  pointer within a root, and which half; full-width items split top/bottom).
- `src/features/tabs/TabBar.tsx`: tabs and group chips drag through the hook; the drop target (tab half, chip,
  empty bar = end) is found from the element under the pointer, with the same rules as before (a tab next to a
  grouped tab joins the group; onto a chip lands before the group).
- `src/features/dashboard/Dashboard.tsx`: widgets (by their grip while customizing) and pinned cards (while
  customizing) drag through the hook; old HTML helpers removed.
- `src/styles/app.css`: dragging cursor.
- Tests updated to pointer drags (tabs, dashboard), plus `src/app/usePointerDrag.test.tsx`.

## Findings

None blocking.

- Dragging a tab onto a canvas or into a note (HTML path data) is gone; it couldn't work in the Windows app.

## Checks

- `pnpm lint`, `pnpm typecheck`: pass. `pnpm vitest run --maxWorkers=4`: 82 files, 679 tests pass.
- Release build, events sent into the page (DevTools protocol mouse press/move/release):
  - Tabs: the second "Other" tab dragged past "Third" → order Other, Third, Other. The release over Third's close
    button didn't close it (click swallowed).
  - Dashboard (Home, Customize): Pinned dragged by its grip onto Calendar → order Pinned, Calendar, Today's tasks,
    Day schedule, saved to the vault config.
  - Pinned cards weren't dragged in the real app (none pinned in the test vault); same hook and `dropBeside`,
    covered by the component test.
- No Rust changes.
