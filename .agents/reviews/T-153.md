# T-153 - Claude verification

Verdict: approve.

Reviewed the full diff `main...agent/claude/T-153`.

Bug: rendering an invalid ```mermaid block made `mermaid.render` draw its "Syntax error in text / mermaid version 11.17.2" bomb graphic into a scratch element it appends to `<body>` (`#daxis-mermaid-N`), then throw without removing it. Each failed render left one more graphic below the app window's content (the user's screenshot).

Fix (`src/features/diagrams/mermaid.ts`):
- Every `initialize` call (first load and theme switch) now passes `suppressErrorRendering: true`, so Mermaid throws instead of drawing the error diagram. The options are shared in one `OPTIONS` constant, so a theme switch can't drop the flag.
- `renderMermaid` removes the scratch elements (`#d<id>`, `#<id>`) in a `finally`, so nothing is left even if Mermaid fails partway. On success Mermaid has already removed them. The returned SVG string is inserted by the caller after this runs, so the removal can't touch it.
- Callers keep their own messages unchanged: the editor block shows "This diagram has an error: …" and the diagram maker shows its own error.
