# Review: T-105 — Dashboard polish, a shared tree index and a real-app WDIO spec

**Verdict:** approve (self-review by Claude, the lead, per the 2026-10-17 agreement)

Reviewed `git diff main...agent/claude/T-105` in full. Without whitespace (Prettier re-indented `Dashboard.tsx` around the new context provider), it is about 250 lines, mostly new code and tests.

## What changed

- **Inline Markdown outside the editor.**
  - New `src/lib/inlineMarkdown.ts` tokenizes one line into text, `code`, bold, italic, ~~strike~~, `[[wikilinks]]` (alias, or note › heading) and `[label](url)`. There's no nesting and no HTML, so callers build React nodes and note text can't inject markup. snake_case, `2 * 3`, unclosed marks and Markdown inside code stay literal.
  - New `src/features/tasks/InlineText.tsx` renders it. Wikilinks open through `followLink` (Ctrl+click opens a new tab; daily-note links create the day's note, as in the editor). Web links show their label with the address on hover; there is no in-app opener for web URLs yet.
  - Used in the Tasks view, and in the dashboard's task and schedule rows.
  - Checkbox labels use `plainInline`, so screen readers hear "Complete: Read Welcome now" rather than raw Markdown.
- **Performance.**
  - `indexTree` (`dashboardModel.ts`) builds the path map plus each folder's file count and latest change in one walk. The dashboard computes it once per tree change and shares it through a context.
  - Cards no longer rebuild `entriesByPath` per widget or recurse a folder's subtree on every render (the old `latestChange`/`fileCount` per card).
  - `listTasks` stays gated on planning widgets being present.
- **Real-app test.**
  - `e2e/specs/dashboard.e2e.ts` and a `dashboard` seed in `wdio.conf.ts`. The spec covers:
    - Ctrl+Shift+H opens Home;
    - task text shows a link and bold, with no `[[`;
    - quick add creates `Daily/<today>.md` on disk;
    - the link opens Welcome;
    - Customize: wide Calendar, Pinned moved earlier, Biology pinned, all saved to `.axisnotes/config.json`;
    - Add dashboard on School from the tree context menu;
    - after a front-end reload, Home comes back with the wide calendar and the pinned card.
- **Fixed from the real-app screenshots:** on a wide calendar the due-count badge sat at the cell's right edge, far from its day number (`calendar.css`). It is now anchored just right of the centred number (checked at 1500 px wide).
- **Fixed, pre-existing (since T-093):**
  - `ai.e2e.ts` and `phase5.e2e.ts` clicked the first `[aria-label="Close"]`. Since T-093 that is the window's own title-bar Close, which closed the app mid-spec ("target window already closed").
  - The selectors are now scoped to `.modal`. Only those three lines in the specs changed.

## Findings (most severe first)

1. **Fixed:** the e2e Close-button collision above. It made ai and phase5 fail on `main`, not just this branch, and was not caused by this task.
2. **Minor, accepted:** `[label](url)` is shown but not clickable, because there's no in-app opener for web URLs. That's worth a follow-up when one exists.
3. **Minor, accepted:** a native mouse drag still isn't exercised end to end. WebDriver's pointer drag doesn't start HTML5 DnD in WebView2, so the spec reorders with the Move buttons. T-104's component tests and real `DragEvent`s in Chromium cover dragging.
