## What it changes

Settings → Appearance → Theme & layout gets **Bold, italic and strikethrough colours**, under
Heading colours. Appearance already had heading colours, app colours and Typography
(T-248/T-253) but nothing for emphasis, so this is a new field rather than a change to an
existing one.

- One row per kind: a checkbox (off by default), a **Light** and a **Dark** colour chip, each
  showing a sample in that mode, and a reset (back to the theme's colours). Off, the text
  keeps the theme's colour.
- Saved as `appearance.textColors.{bold,italic,strike} = {on, light, dark}` in the vault's
  `.axisnotes/config.json`; older configs get the defaults (`mergeConfig`).
- `applyTextColors` sets `--text-bold`/`--text-italic`/`--text-strike` on the root as
  `light-dark(<light>, <dark>)`. A mode without a picked colour uses the theme token
  `--text-*-theme` (new in `themes.css`: bold = the theme's accent, italic = a teal in
  `light-dark()`, strikethrough = muted text; E-ink overrides italic to black). Only hex
  colours reach CSS.
- Applied to the editor's live preview (`.cm-lp-strong/.cm-lp-em/.cm-lp-strike`, which also
  covers embeds and inactive lines — the app's reading view) and rendered AI answers
  (`.answer-text strong/em/s`). The Markdown never changes.
