# T-171 review: the Agent, animated AI status in its own always-on-top window

**Verdict: approve** (Claude self-review, 2026-11-05). Merged together with T-172, which is built on it.

## What changed

- `src/ipc/aiActivity.ts`: `withAiActivity` wraps `backend.aiRun` in place.
  - It announces start, first text and end (`ok`, `error`, `blocked` or `cancelled`) with the note path. It never includes content.
  - Every AI feature (Ask AI, AI blocks, Fix writing, diagrams, handwriting) is covered without changes to any of them.
- `src/features/agent/agentModel.ts`: a pure `agentStateAt`.
  - Thinking until the first text arrives, then Working.
  - Done for 8 s (`DONE_MS`). Needs you for 20 s after a blocked or failed run, showing the reason.
  - Sleeping after the chosen idle minutes, or when "Sleep now" is chosen.
  - `until` gives the next time the state changes by itself, so nothing polls.
- `src/features/agent/agentSettings.ts`: mode (always / only while busy / never), sleep minutes, size and window position. Stored on this device in `localStorage`.
- `src/features/agent/AgentBridge.tsx`: mounted in `App`. While the Agent is on, it:
  - tracks AI activity and the user's key and pointer use
  - opens, closes and resizes the Agent's window through `backend.agentHost` and sends it the view
  - handles its messages: Open (focus the main window and open the note a finished run was in), Sleep now, and Hide (mode off, with a notice)
  - in a browser, draws the Agent floating in the page instead, draggable and with an HTML menu
  - when off (or under WebDriver), unmounts, which stops every listener, timer and window
- `src/features/agent/AgentApp.tsx` and `src/main.tsx`: the Agent's window loads `index.html?agent` and renders only `AgentApp`.
  - A press-and-move hands the drag to the OS (`startDragging`), a click posts Open, and right-click shows a native menu.
  - The position is saved after moves.
  - `main.tsx` now loads `App` or `AgentApp` with a dynamic import.
- `src/ipc/tauriBackend.ts` and `types.ts`: `agentHost` and `agentSide`.
  - The window is `WebviewWindow("agent")`: transparent, borderless, no shadow, always on top, off the taskbar, not focused on open, on all workspaces.
- `src-tauri/capabilities/agent.json`: the Agent's window gets `core:event:default`, `core:window:default`, `allow-start-dragging` and `core:menu:default` only.
- `src-tauri/capabilities/default.json`: the main window can now create the Agent's webview, and focus, show and unminimize itself.
- `src-tauri/src/lib.rs`: destroying the main window exits the app, so the Agent can't outlive it.
- `src/features/agent/AgentFigure.tsx` and `agent.css`: the built-in Agent drawn in CSS, with a small animation for each state, a speech bubble and the reduced-motion setting respected.
- Settings → Agent (new section).
- Command palette: "Show or hide the Agent".

## Findings

No blocking findings. Notes:

1. Tauri app commands are not window-scoped, so the Agent's window could technically invoke them. It only ever loads this app's own bundle (no remote content), and `AgentApp` never calls them. If remote content is ever added, gate commands by window label.
2. Dragging and the remembered position weren't checked. The drag needs a physical mouse, and an outside `SetWindowPos` was refused. The user should drag the Agent once in the published build.
3. Hiding from the taskbar uses the taskbar API, not a window style, so it couldn't be read from the window flags. It needs a look at the taskbar.
