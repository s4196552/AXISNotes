# T-264 review: editor hit areas ("hitbox" fixes)

**Verdict:** approve (Claude, self-verified under the 2026-11-10 rule)

## What the human reported

"Fix hitbox issues": clicks landing on the wrong thing around the line + / grip controls,
Mermaid resize handles, the sidebar/file tree, and code copy / callouts.

## What was found (browser preview, elementFromPoint probes and real pointer input)

- **Line + / grip:** the controls and their hover bridge were only one row (18px–1lh) tall,
  aligned to the first row. On a callout body, wrapped paragraph or any line taller than one
  row, moving left from the text left the hover area, so the controls vanished and a click
  just above or below + hit the editor (caret moved, Markdown revealed) or, moving
  diagonally, the neighbouring line's controls. Reproduced: pointer beside a callout body's
  second row → no controls, hit `.cm-content`.
- **Mermaid / image resize handles:** 10×10 corner and 8×22 side squares; a press 1–2px off
  hit the diagram background, which deselects it.
- **Code copy, task checkbox, callout chevron:** a near miss put the caret on the hidden fence
  / task / callout title and revealed its Markdown, shifting the layout under the pointer.
- **Sidebar / file tree:** rows tile with no gaps and nothing covers them; the panel
  resizers overlap rows by 1px only. No change made.

## What changed

- `blockTools.ts`, `editor.css`: the line controls strip spans the whole line height and
  reaches the text (no gaps between + and grip); each button fills the strip while the
  visible control stays where it was (first row, same x/y, measured before and after). The
  strip swallows mousedown so a stray press never moves the caret. The hover bridge in the
  margin spans the whole line.
- `editor.css`: invisible larger hit areas for resize handles (18px corners; kept within a
  diagram's 8px padding so it doesn't scroll), the task checkbox (+4px), the code copy
  button (+4px) and the callout chevron (its 4px leading gap is now padding).

## Findings

None open. The grip/+ hit area now covers the whole line height in the margin, so a click
in that 35px strip beside the active or hovered line no longer places the caret at the line
start (by design).
