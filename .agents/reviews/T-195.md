**Verdict: approve**

Reviewer: Claude (self-review). I read the full diff of `agent/claude/T-195` against `main`.

## Findings (most severe first)

1. **Resolved: fail-open on broken YAML.** A mark inside frontmatter that doesn't parse would have been ignored. `privacy::note_mark` (`src-tauri/src/ai/privacy.rs`) and `noteMark` (`src/lib/aiAccess.ts`) now treat a mark line in a broken block as `never`. `markText` edits only that one line, so it never rewrites broken frontmatter (`withFrontmatter` would have replaced it).
2. **Resolved:** the connector's index-based marks could lag behind an edit. Reads and writes (`shared_note` and `writable` → `marked()` in `src-tauri/src/mcp/tools.rs`) check the file itself. An unreadable file counts as marked.
3. **Accepted:** in the index, a broken-YAML mark isn't visible, so lists and folder scope won't hide that note. Requests that read it are still refused at send time, because `service.rule()` reads the file. This is documented in the handoff.
4. **Accepted:** `ModelPicker` doesn't grey out models a folder's allowlist excludes. The Rust layer refuses such a request with a message naming the folder.
5. **Note:** `service.rule()` now reads each source file, so attached notes are read twice per request (rule, then `expand`). This was judged acceptable at the 100-note folder cap.
