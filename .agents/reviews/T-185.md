# T-185 review: AI blocks survive switching tabs

**Verdict: approve** (Claude self-review, 2026-11-07)

## Why

The user: "I don't want AI tasks to disappear when I'm on a different tab."

A note's editor is destroyed whenever another tab or note is shown. `aiBlock.ts`'s `cleanup` plugin cancelled every running request and deleted every block's state on destroy, so leaving the tab threw away the prompt, the running answer and any finished result.

## What changed

`src/features/ai/aiBlock.ts`:
- The `keep` plugin follows the editor's blocks and, when the editor closes, parks them by note path. It no longer cancels or deletes them.
- Requests keep running. They already wrote only to the block store (`useAiBlocks`), never to the editor, so streaming and the final result carry on while the note isn't shown.
- `aiBlocks(path)` starts the block field from that note's parked blocks (`unpark`). The same block ids come back, so the views find their prompt, answer, skill, format and phase in the store.
  - Positions are clamped to the document.
  - Blocks closed meanwhile are dropped.
  - Each parked block comes back in one editor only.
- Closing a block (×, Escape, Insert) still cancels and forgets it, as before.
- `discardParkedBlocks(path?)` cancels and forgets parked blocks. It's called when the vault changes, so blocks don't follow you into another vault.

## Findings

None blocking.
1. Parked blocks of a note that's renamed while away stay under the old path, and won't show on the renamed note. They're forgotten when the vault changes.
2. Two editors on the same note at once (split panes) don't share blocks. That's unchanged, since each block belongs to the editor it was opened in.

  - A new editor for the note has the same block, with the answer, and Insert writes it into the note.
- "only come back to their own note, and go when the vault changes".
