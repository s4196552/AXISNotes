# T-170 review: Ask AI about a folder (or a note) from the file tree

**Verdict: approve** (Claude self-review, 2026-11-05)

## What changed

- `src/features/filetree/FileTree.tsx`: the right-click menu has **Ask AI about this folder** on folders and **Ask AI about this note** on Markdown notes, just above the AI access items.
- `src/features/ai/folderScope.ts`: chooses which notes a folder request sends.
  - It sends the folder's own notes, or the subfolders too when that is ticked, sorted by path.
  - Notes under an "AI: never" rule are left out and listed. They don't block the whole request.
  - At most 100 notes (`MAX_FOLDER_NOTES`) are sent. The rest are counted as left out.
  - `ruleForPath` mirrors the Rust lookup (own rule, then the nearest folder rule, then `any`).
- `src/features/ai/AskAi.tsx`: takes `folder`.
  - Shows "Include N notes in “Folder”", a Subfolders toggle, a "left out" line (the names are in its tooltip) and an empty-folder message.
  - The notes go by path in `attach`, so Rust reads them, intersects their rules and fails closed if a never note slipped through.
  - The plan line shows the "Local-only notes" badge when the folder includes local-only notes.
  - The system prompt names the folder.
  - A folder answer can be copied or saved as "AI answer.md" in that folder, which opens in a tab.
- `src/features/commands/{ui.ts,Modals.tsx}`: the `ask` modal carries `folder`.
- `.agents/reviews/T-163.md`: corrected the follow-up task numbers.

## Findings

No blocking findings. Notes:

1. The webview decides which paths to attach, but Rust still checks every attached note's rule. A stale config in the webview can only make a request fail, never leak a never note.
2. The 100-note cap and the existing token cap and confirmation threshold limit the size of a request. There is no retrieval yet: the whole notes are sent. "Ask my vault" with search-ranked passages is a separate idea in the report.
