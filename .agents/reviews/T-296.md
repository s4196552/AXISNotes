# T-296 review: the WebdriverIO e2e suite passes again on Windows

**Verdict: approve** (Claude, self-verification under the 2026-11-10 rule)

## Background

The e2e suite could not start while the installed msedgedriver (155) didn't match WebView2 (158). With the matching driver in `~/.axis-e2e/msedgedriver-158.0.4370.45/`, `main` at a80d640 passed 20 of 36 spec files. Most failures were specs written or last run before later UI tasks changed the UI. Several later specs (T-259, T-263) were type-checked but never run.

## App changes (two regressions found by the run)

1. **A note whose first line below its hidden title is an embed opened with the embed's source showing** (`src/features/editor/titleHeading.ts`, `embeds.ts`, `Editor.tsx`).
   - Since T-107, a freshly opened note starts its cursor on the first line below the hidden `# Title` (and the blank line after it). An embed line shows its source while the cursor is on it.
   - So a clipped screenshot (`# Shot` followed by `![[Shot ….png]]`) opened showing `![[…]]` rather than the image. This was phase6's failure.
   - Now `startBelowTitle` takes a `drawnAsBlock` check (`isEmbedLine`, the same test the embed decorations use). The cursor skips embed lines and starts on the next line. When only embeds follow the title, it starts where it did before.
   - Notes opened at a saved position, or with text below the title, are unchanged.
   - Unit tests in `noteTitle.test.tsx`: the pure function, `isEmbedLine`, and an Editor mount. The mount test fails without the fix and passes with it.
2. **The table cell's Ctrl+/ menu found nothing for "priority high"** (`src/features/editor/tableCellMenu.ts`).
   - Its matching kept punctuation, so the label "Priority: high" didn't match. The note's own command menu (CodeMirror's fuzzy match) does match it.
   - The cell menu now compares words, ignoring punctuation.
   - Unit test in `tableCellMenu.test.ts`. T-263's e2e case had never run.
