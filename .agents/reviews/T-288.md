Human request (2026-11-26): rework the note's right-click menu to their layout. They sent it twice ("right clicking on the note" and "on the note contents … some should change the highlighted note contents"); read as one editor menu whose Format / Paragraph / Insert items act on the selection, or at the caret / on the caret's line with nothing selected.

## What the menu is now

- **On a misspelled word, first:** its suggestions, Add “word” to dictionary, Ignore (the quick fixes the spelling popup used to show on right-click; Ctrl+. still opens that popup).
- **Format ▸** Bold / Italic / Strikethrough / Highlight / **Color ▸** Green, Yellow, Orange, Red, Violet, Blue.
- **Paragraph ▸** Bulleted List / Numbered List / Task List — Heading 1 … Heading 6 — Quote.
- **Insert ▸** Footnote / Table / Callout / Divider — Code Block / Math Block.
- Cut / Copy / Paste / Paste as plain text / Select All.
- **Kept, last:** Ask AI about this selection/note, Send selection/note to AI chat (the menu's existing items).

The menu is T-287's `filetree/ContextMenu.tsx` (groups, submenus by hover/click and → Enter Space ← Escape ↑ ↓ Home End), imported unchanged; the table-cell and image menus are untouched (the editor ignores a right-click they already handled).

## Choices made

1. **Right-click outside the selection moves the caret there** (as in other editors), so caret/line actions apply where the pointer is. Inside the selection it is kept. The menu key / Shift+F10 opens the menu at the caret.
2. **Format** reuses `toggleMark` (Ctrl+B's): wraps or unwraps the selection; at a caret it leaves an empty pair to type into. Highlight is `==…==`.
3. **Color** uses the app's only text colours, the coloured-code tags (`` `green`text`` ``, codeColors.ts): it colours each selected line; inside coloured text the current colour is ticked, another colour replaces it and the ticked one removes it. At a caret it inserts the tag ready to type into. Note these show as code (monospace), as they already did.
4. **Paragraph** items toggle and show a ✓ on the current type: Heading 2 on a heading 2 line makes it plain; on a heading 3 it becomes heading 2. Lists number 1, 2, 3 and keep indents; blank lines are skipped. **Quote** makes the same block the / Quote command makes (`> [!NOTE] TITLE`, TITLE selected to type over); on a quote it takes the whole quote out again (an untouched TITLE line goes, a real title stays as a line).
5. **Insert** with a selection turns the selected lines into the block (table rows split at tabs or `|`, first row the header; callout; `$$` math; the existing code-fence wrapper for code). Without one the block goes below the caret's line (or on it, when empty) with blank lines where it meets text, using the / commands' Markdown. Divider goes after the selection. Footnote adds `[^n]` (next free number) after the selection/caret and `[^n]: ` at the end of the note, with the caret there.
6. **Cut / Copy** with nothing selected take the caret's line (Cut removes the line), since the layout always lists them.
7. **Paste vs Paste as plain text:** Paste inserts the clipboard text as it is (Markdown stays Markdown), plus media files when the page may read them without a prompt; Paste as plain text removes HTML tags and Markdown formatting (bold/italic/strike/highlight/code marks, links → their text, heading and quote markers) and keeps words, line breaks and list markers.
8. **Clipboard reading in the app:** Tauri's windows don't have WebView2's clipboard-read permission (`enable_clipboard_access` is off), so `navigator.clipboard.readText()` waited on a permission prompt in the installed 0.3.114 (checked over its DevTools port: state "prompt", readText never resolved; the old menu's Paste had the same problem). New Rust command `read_clipboard_text` (src-tauri/src/clipboard.rs) reads CF_UNICODETEXT through the existing `windows` crate (three more Win32 features, no new dependency) and refuses callers that aren't the app's own pages; other systems fall back to the browser API. In the app, media paste stays on Ctrl+V.

## Findings

1. Note: `src/features/editor/NoteContextMenu.tsx` imports `../filetree/ContextMenu` and `filetree.css` (read-only reuse; the brief kept filetree files off-limits). Moving the menu component to a shared folder would be a small follow-up.
2. Note: the menu re-fits to the window when the spelling suggestions arrive (they load after it opens); a menu taller than the window starts at the top and scrolls.
3. Known gap: Color on a selection that starts with punctuation, or holds a double backtick, is left uncoloured (the tag syntax can't hold it).
