# T-191 review: copy and paste from skills' web pages

**Verdict: approve** (Claude self-review, 2026-11-07)

## What changed

- `src/features/skills/copyable.ts` (new):
  - `makeCopyable` adds a `<style>` and `<script>` guard first in a page's `<head>`, adding a `<head>` if the page has none, and does nothing if the guard is already there.
  - `COPYABLE_RULE` is the line added to page-making runs.
  - `pageText` and `copyPageText` power "Copy text".
- `src/features/skills/skills.ts`:
  - `extractHtml` returns guarded pages.
  - `parseSkillFiles` guards a Teach session's `.html` files and leaves `.md` files as they are.
  - `skillSystem` adds `COPYABLE_RULE` for html and files runs.
- `src/features/skills/SkillResult.tsx`: "Copy text" beside Open in browser, Save next to the note and Open as draft.
- `src/features/drafts/WebFileView.tsx`: "Copy text" for any vault web page, and a line saying the text can be selected and copied in the browser.
- Tests: `copyable.test.tsx` (new, 10 tests). In `skills.test.tsx`, three expectations of the exact saved HTML now include the guard.
- `docs/DECISIONS.md`: entry for T-191.

## Findings

1. Note, by design: the guard stops the page's own handlers for copy, cut, paste, selectstart, contextmenu and Ctrl/⌘+A/C/V/X. A skill page that wanted its own right-click menu or Ctrl+C shortcut loses it. That is the point of the change, and none of the built-in skills need one.
2. Note: the "click that ends a selection" check uses the selection when the click fires. A plain click on already-selected text clears the selection first in Chromium, so the card still flips as expected. Checked in the preview.
3. Note: the guard is an inline script. A page that sets a strict Content-Security-Policy without `'unsafe-inline'` would block it, but such a page would also block its own inline script, so the format rules (one inline script) already rule this out.
4. Known gap: pages saved before this update aren't changed (saved files are never rewritten). Running the skill again gives a copyable page, and "Copy text" works on old pages.

- Preview (Chromium, Vite on port 1891), the same hostile flash-card page with and without the guard. The page had `user-select:none`, `oncopy`/`oncontextmenu="return false"`, preventDefault on copy, paste and selectstart, and a click that flips the card.
  - Without the guard: copy, paste and select were all cancelled, and dragging across the card selected nothing and flipped it.
  - With the guard: `user-select: text`; nothing was cancelled; dragging highlighted "What is the powerhouse of the cell?" without flipping; a plain click still flipped.
