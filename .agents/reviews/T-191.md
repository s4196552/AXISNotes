## Findings

1. Note, by design: the guard stops the page's own handlers for copy, cut, paste, selectstart, contextmenu and Ctrl/⌘+A/C/V/X. A skill page that wanted its own right-click menu or Ctrl+C shortcut loses it. That is the point of the change, and none of the built-in skills need one.
2. Note: the "click that ends a selection" check uses the selection when the click fires. A plain click on already-selected text clears the selection first in Chromium, so the card still flips as expected. Checked in the preview.
3. Note: the guard is an inline script. A page that sets a strict Content-Security-Policy without `'unsafe-inline'` would block it, but such a page would also block its own inline script, so the format rules (one inline script) already rule this out.
4. Known gap: pages saved before this update aren't changed (saved files are never rewritten). Running the skill again gives a copyable page, and "Copy text" works on old pages.
