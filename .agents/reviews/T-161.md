# Review: T-161 Fold arrows for list items, toggle fold keys, remembered folds

**Verdict: approve**

The human asked for nested fold arrows on headings, bulleted lists, numbered lists, tasks/checklists and toggles.

## What already existed

- Headings: a hanging arrow (T-133/T-156), view-only folding (`flipHeading`).
- Toggles (`> [!toggle|hN]± Title`) and foldable Obsidian callouts (`> [!note]- Title`): an arrow that flips the `+`/`-` in the note, so the state is saved in the file and other apps fold them too (T-157/T-158). This is the app's toggle syntax, and it is kept as it is.
- List items: a `foldService` (`outlineFolding`) and CodeMirror's fold keymap (Ctrl+Shift+[ / ], Ctrl+Alt+[ / ]), but no arrow unless the optional Outline view's fold gutter was on.

## What changed

- `src/features/editor/outliner.ts`: `listItemSpans` finds every list item (bullets, numbers, tasks) and its last line in one pass, cached per document. It skips fenced code, HTML comments and frontmatter, which `listItemAt` did not. A test checks it against `listItemAt`. `outlineFolding` now uses it (`listFoldRange`), so the arrows and the keys fold the same range.
- `src/features/editor/toggles.ts`:
  - An arrow on every list item that has children, in the visible lines. It shows when the line is hovered, and stays (in the accent colour, with a ring round the bullet) while the item is folded. Clicking or Enter/Space folds or unfolds it.
  - Folding is view-only, through `flipViewFold`, which headings now share. Unfolding removes whatever fold starts on that line. Before, a fold whose item had grown since it was folded (a child typed after it) could not be unfolded from the arrow.
  - Ctrl+Shift+[ / ] (Cmd+Alt on a Mac) on a toggle's or foldable callout's title closes or opens it the way its arrow does. Elsewhere the keys keep folding headings and list items.
  - `viewFolds` and `restoreFolds` save and restore the view folds. On restore, a fold is skipped unless the note still folds exactly that range.
- `src/features/editor/Editor.tsx`: a note's folds are kept with its cursor and scroll position (`viewStates`, this session only), so they come back after a tab switch.
- `src/features/editor/editor.css`: the list arrow sits at the start of the line and hangs left of the marker, offset by `--li-depth` steps of `--list-indent`. Top-level arrows line up with the heading arrows.

Nesting uses CodeMirror's fold set. Folding a parent keeps the folds inside it, so unfolding the parent brings its children back as they were. Folding never changes the note's text (tested).

## Findings

No blocking findings.

1. Note: with Outline view on, its fold gutter still draws a second marker for headings and list items. This already happened for headings and is unchanged.
2. Note: list items inside quotes or callouts (`> - item`) get no arrow, as before (the outliner does not treat them as list items).
3. Note: fold memory lasts for the session only, like the cursor and scroll memory. Folds are not saved across app restarts.
