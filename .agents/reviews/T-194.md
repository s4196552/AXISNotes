# Review: T-194, copy, cut and paste in the file tree

**Verdict: approve** (Claude, self-review under the 2026-10-17 agreement)

Branch `agent/claude/T-194`, from `c57486b` (Release 0.3.72).

## Findings (most severe first)

1. **Low, accepted:** `copy_entry` marks only the copy's top path as a self-write (`src-tauri/src/commands.rs`, `copy_entry`). For a copied folder the watcher still reports the files inside as created, which refreshes the tree and reindexes them a second time. Harmless (idempotent), and the command already reindexes the whole copy.
2. **Low, accepted:** a large folder copy runs in one async command with no progress; the UI stays responsive (async command) but the copy only appears when it's done.
3. **Note:** React Compiler bailed out of `FileTree` (`react-hooks/preserve-manual-memoization` on the `actions` memo) when the component read the clipboard store while rendering. Fixed by letting the Paste menu item and each row subscribe themselves (`PasteItem`, `useIsCut` in `FileTree.tsx`), which also means a copy/cut redraws only the affected rows.
4. **Note:** paste into itself is refused in the UI before the backend is asked; the Rust and memory backends refuse it too (`InvalidName`).
