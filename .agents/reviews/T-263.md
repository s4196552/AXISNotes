# T-263 review: commands and text styles in table cells; images in list items

**Verdict:** approve (Claude, self-verified under the 2026-11-10 rule)

## What the human reported

1. In a table cell, the `:` emoji/icon picker and the Ctrl+/ command menu did nothing.
2. Bold, italic and strikethrough couldn't be applied in table cells.
3. Image embeds only rendered on lines of their own, not in task, bullet or numbered items.

## Cause

- A cell being edited is a plain `<textarea>` inside the table widget (T-259), so
  CodeMirror's autocompletion never sees its typing. The global Ctrl+/ command was set to
  ignore textareas. Ctrl+B / Ctrl+I / Ctrl+Shift+S / Ctrl+E were worse than doing nothing:
  the window's capture-phase hotkeys ran `toggleMark` on the **note's** selection, outside
  the table.
- `embeds.ts` only replaced whole lines that were an embed (`EMBED_LINE_RE` /
  `parseMarkdownEmbed` anchored at line start and end).

## What changed

- `tableCellMenu.ts` (new): the cell's menu, drawn inside the editor with the command menu's
  own classes, so it looks like the note's menu (section headers, icons, descriptions,
  Markdown hints). Ctrl+/ (and the optional typed trigger from Settings) offers the
  commands that fit one table line: text styles, inline code, link/embed/web embed, date,
  time, due date, priorities and the user's custom commands (respecting disabled ones).
  The emoji trigger offers emoji plus built-in and pack icons. Typing filters; ↑↓, Enter,
  Tab, Escape, mouse. Inserts never contain line breaks (`<br>`), and `|` is escaped on
  write by `tableCellSource`.
- `tables.ts`: cells get the menu and a `format(mark)` method; `tableCellCommand` lets the
  global hotkeys act on the focused cell; right-click while typing offers Bold / Italic /
  Strikethrough for the selection. Rendered cells use `cm-lp-strong` / `cm-lp-em` /
  `cm-lp-strike`, so T-260's optional colours apply, and inline icons (`![x](<lucide:…>)`)
  render as icons.
- `inlineMarks.ts`: `toggleMark`'s change is factored into `toggledMark(state)`, and
  `toggleMarkInText` reuses it for plain text, so cells wrap/unwrap exactly like notes.
- `registry.ts`: Bold/Italic/Strikethrough/inline code and the command menu route to the
  cell when the key is pressed in one (code block does nothing there).
- `embeds.ts` + `editor.css`: `ListMediaWidget` renders `![[img.png|w]]` and `![alt|w](…)`
  images, video, audio and web players inline in list/task items (syntax tree `ListItem`,
  not in code/frontmatter/HTML), at their width, after the bullet/number/checkbox. A click
  puts the cursor after the name and width (source shows, ready to change the size);
  players have "Edit link". Lines that are only an embed keep the existing block widget.
- `inlineIcons.ts`: `inlineIconElement` shared with table cells.

## Findings (none blocking)

1. `src/features/editor/embeds.ts` (ListMediaWidget): list-item images have no drag-resize,
   move or crop handles (those `imageTools` are line-based). Size is changed by editing
   `|width`, which a click puts the cursor next to.
2. `src/features/editor/tableCellMenu.ts`: block commands, skills/AI, "Image, video or
   audio…" (file picker) and "Add icon…" are left out of the cell menu on purpose; they
   need lines of their own or the note editor. The menu sits under the cell, not the caret.
3. Edits from the menu/shortcuts set the textarea value directly, so the textarea's own
   Ctrl+Z won't step through them; the note's history (CodeMirror) still records them.
