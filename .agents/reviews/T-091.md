## Findings
1. Fixed before commit — `src/features/packs/PackParts.tsx`: line-icon packs (black or
   `currentColor` strokes) were nearly invisible on dark themes with no colour picked.
   Import now marks one-colour icon packs (`.pack.json`, `src-tauri/src/packs.rs`
   `svg_is_monochrome`), and their icons default to the text colour (saved as
   `color: currentColor`, shown as the default swatch). Multi-colour packs keep their colours.
2. Fixed before commit — `src-tauri/src/commands.rs` `remove_pack`: moving a folder to the
   Windows Recycle Bin took ~1.5 s, and as a sync command it held up the window. It's async
   now, and Settings shows "Removing…" meanwhile (found by the E2E, which first expected the
   list to update at once).
3. Fixed before commit — `e2e/specs/packs.e2e.ts`: the first test called the backend before
   the window had loaded (WebDriver retried); it now waits for the file tree.
4. Low, accepted — covers using a pack image don't show in Obsidian, which ignores
   dot-folders (the user chose hidden storage knowing this).
5. Low, accepted — `list_packs` reads every pack folder each time a picker or Settings
   opens; fine for thousands of files, and changes made outside the app show then.
6. Note — SVGs are only ever shown through `<img>` and CSS masks, never inlined, so scripts
   in a pack can't run. Zip entries use their base name only; sizes are checked while reading.
