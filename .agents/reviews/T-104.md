# Review: T-104 — Easier dashboard customizing

**Verdict:** approve (self-review by Claude, the lead, per the 2026-10-17 agreement)

Reviewed `git diff main...agent/claude/T-104` in full (5 files in `src/features/dashboard/**`).

## What changed

- **Drag and drop** (Customize mode only), using native HTML5 DnD like the tab bar and file tree, with no new dependency:
  - **Widgets** drag by a grip handle; the whole card is the drag image.
  - **Pinned cards** drag as a whole.
  - A drop lands before or after the target by pointer half: left/right normally, above/below on an item much wider than tall, with an accent bar on that side.
- **Keyboard and screen-reader access:** the up/down buttons stay on widgets, and pinned cards gain "Move … earlier/later" buttons.
- **Model:** `placeWidget`, `placeLink` and `moveLink` (shared `shift`/`place` helpers); `moveWidget` now uses the same `shift`.
- **Widget size:** `size?: "normal" | "wide"` with a toggle in the widget tools. Unset keeps the old rule (Pinned/Recent wide). `isWide()` is used by the frame.
- **Rename any widget:** the title field in Customize mode is on every widget, not only Pinned.
- **Recent count:** `options.count` (4/8/16/24, default 8) via a "Show [n] files" select shown while customizing. Saved counts outside the list still show; out-of-range or non-integer values are dropped on load.

## Findings (most severe first)

1. **Minor, accepted:** the preview pane's automated mouse drag doesn't start a native HTML5 drag (it selected text instead). Real `DragEvent`s with a `DataTransfer` dispatched in the same Chromium page did reorder widgets, so the handlers work in a real engine. A physical mouse drag in the installed app wasn't exercised; the WDIO spec (Task D) is the place to cover it if WebDriver's drag works with WebView2.
2. **Minor, accepted:** a pinned card is draggable as a whole while customizing, so a drag that starts on its button also drags. Clicking still opens it, which matches how the tab bar behaves.
3. **Minor, accepted:** a widget made wide in a single-column (narrow) layout looks the same as a normal one, since every widget already spans the column.
