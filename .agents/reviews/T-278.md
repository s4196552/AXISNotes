# T-278 review: never overwrite a broken settings file

**Verdict: approve** (Claude, the builder's own verification under the 2026-11-10 rule)

## Findings

1. Fixed during verification: `src/app/config.ts` `load()` first flushed a waiting save, which could write the old settings over the file it was about to read. A full-run failure in `themes.test.tsx` ("keeps a 0.3.1 vault's blur choice") showed this. `load()` now drops a waiting change, and vault switches save it first in `store.openVault` / `createVault`.
2. Note: the write delay is chosen at module load from `import.meta.env.MODE`. Importing `config.ts` from `src/test/setup.ts` would load the real backend before each test file's `vi.mock`, so it isn't imported there.
3. Known gap, not changed: external edits to `config.json` while the app is open are overwritten by the next change.
