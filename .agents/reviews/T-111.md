# Review: T-111 — The file tree shows the open file

**Verdict:** approve (self-review by Claude, the lead, per the 2026-10-17 agreement)

Finding N5 of the 2026-10-20 UX review (batch 2, picked by the human). Reviewed `git diff main...agent/claude/T-111` in full.

## What changed

- When the open file changes (switcher, link, calendar, tab), the file tree opens the folders it is in, selects it and scrolls it into view. Selecting also moves the tree's keyboard cursor, so the old row no longer keeps a focus outline next to the new selection.
- The setting **Settings → Files & links → Show the open file in the file tree** is on by default, stored as `fileTree.revealActiveFile` in the vault config (merged over defaults, so older configs get it).
- A **Reveal open file in the file tree** command (palette, with a FolderTree icon) shows the Files panel, opens the left sidebar if hidden, and reveals the file even with the setting off.
- `reveal.ts` holds `ancestorsOf`, the request store and the command; FileTree listens through store subscriptions (not effect-time state updates).

## Findings (most severe first)

1. **Minor, accepted:** a file opened before the tree has loaded (startup tab restore) isn't revealed until it's opened again or the command is used.
2. **Minor, accepted:** revealing expands folders and keeps them expanded (saved like any other expansion).
