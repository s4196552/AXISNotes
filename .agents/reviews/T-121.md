# Review: T-121 (move, reorder and edit items in the file tree)

**Verdict:** approve

Human request (2026-10-21): "Allow the user to change, edit and move the content in the sidebar."

## Finding that drove it

In the installed Windows app, dragging in the file tree did nothing. Reproduced with a real OS mouse drag
(SendInput) on the 0.3.20 release build: a click at the same coordinates selected and opened the row, but dragging
`Note.md` onto `Alpha` left the files unchanged. Tauri's native file-drop handling (`dragDropEnabled`, on by
default, used here for importing dropped files) swallows HTML drag and drop inside the webview on Windows.

## Change

- `src/features/filetree/FileTree.tsx`: rows drag with pointer events instead of HTML drag and drop. After 5 px a
  drag starts: a label follows the pointer, the dragged row dims, and the target shows a line (before/after) or a
  highlight (into a folder; middle half of a folder row). Empty space = top level. Hovering a closed folder opens
  it after 600 ms; the list scrolls near its edges; Escape cancels; the click that ends a drag is swallowed.
  Dropping between rows sets a custom order (moving the item into that folder first when needed; a name clash is
  reported, nothing overwritten). Context menu: Move to…, Move up, Move down, and Sort A–Z on a folder or the empty
  area when it has a custom order. Alt + ↑/↓ moves the selected item.
- `src/features/filetree/treeModel.ts`: `orderedChildren`, `dropSide`, `placeName`, `remapOrder`; `visibleRows`
  takes the order.
- `src/app/config.ts`: `fileOrder` (folder path → names) in the vault's `.axisnotes/config.json`; unlisted items
  follow A–Z (folders first), so new files appear after the ordered ones.
- `src/features/files/renameEntry.ts`: renames, moves and deletes carry the order along (`remapOrder`).
- `src/features/commands/Modals.tsx`: Move to… never offers a folder itself or its subfolders.
- `src/features/filetree/filetree.css`: drop line, dragged row, drag label, grabbing cursor.

## Findings

None blocking.

- Dragging a tree item into the editor or canvas (HTML drag with the path) is gone with `draggable`; it never
  worked in the Windows app for the same reason. Tabs and dashboard tiles still use HTML drag and are likely
  broken the same way in the installed app — worth the same pointer treatment as a follow-up.
