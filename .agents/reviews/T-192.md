# Review: T-192, links in web pages shown in the app

**Verdict: approve** (Claude, self-review under the 2026-10-17 agreement)

Branch `agent/claude/T-192`, from `4389158` (Release 0.3.71).

## What changed

- **`src-tauri/src/pages.rs`:**
  - Every served `.html` gets `LINK_SCRIPT` appended; the file on disk is unchanged. A left click, with no modifier keys, on an `http(s)`/`axispage` link that the page didn't `preventDefault` is cancelled and posted to the parent as `{ axisnotesLink }`. `#section` links within the page are left alone.
  - The new `open_web_link` command opens `http(s)` URLs only. It refuses whitespace, control characters and anything over 4096 bytes, and reuses `browser_command` from T-182, now `pub(crate)` in `ai/subscription.rs`.
- **`WebFileView`** takes a link message only when:
  - it comes from its own frame;
  - the frame has focus;
  - at least one second has passed since the last one.

  Web links go to `backend.openWebLink`. Vault links open in a tab when the file is in the tree; otherwise a notice says the file isn't in the vault. `pageLink()` lives in `src/features/drafts/pageLinks.ts`.
- **`Backend.openWebLink`**: the Tauri version invokes `open_web_link`; the memory version uses `window.open` for http(s) only.
- **New test for T-190's missing case**: Open page opens the draft in a tab, and Open in browser opens it in the browser without changing the tab.

## Findings (most severe first)

1. **Low, accepted:** after the user clicks into a page, the frame keeps focus, so the page's own script could post web links every second until the user clicks elsewhere (`src/features/drafts/WebFileView.tsx`, the message handler). Each one opens a browser tab.
   - The rate limit bounds this.
   - Only `http(s)` URLs are accepted (`src-tauri/src/pages.rs`, `open_web_link`), so nothing local can be launched.
   - Pages are the user's own vault files.
2. **Note:** links are handled only for left clicks without modifier keys. A link the page's script handles itself (`preventDefault`) is left to the page. If the page stops propagation, the handler doesn't see the click, and the frame navigates as before.

## Checked in the real app (release build, 2026-11-08)

The release build from this branch ran on the scratch QA vault, driven over the WebView2 DevTools port with `Input.dispatchMouseEvent` (no OS mouse input). The test page was `Bio/Links.html`.

| Action | Result |
| --- | --- |
| Before T-192 (0.3.71 build): click a web link | The frame shows WebView2's blocked-page icon until Reload |
| Click the web link | The frame stays on the page; the app gets `{ axisnotesLink: "https://example.com/" }` from its own frame, with the frame focused |
| Click `#bottom` | The page scrolls (`location.hash` is `#bottom`); no tab change |
| Click a link to `Cells quiz.html` | That page opens in its own tab |
| Click a link to `Secret.md` | The note opens in the editor ("secret note") |
| The page posts a link from script while the frame isn't focused | Ignored; the tab is unchanged |

My attempt to stub the browser opener in the page failed: `__TAURI_INTERNALS__.invoke` can't be reassigned. So the two web-link clicks really called `open_web_link`, and example.com most likely opened in the default browser. The vault links show the same handler path end to end.
