# Review: T-156 Headings, lists, tasks and fold arrows laid out like Obsidian

**Verdict: approve**

## What changed

The values come from Obsidian 1.14.5's own stylesheet (`app.css` in `obsidian-1.14.5.asar`). They were then checked by measuring both editors with the same script: every line's top, height, padding and text start, plus the positions of bullets, numbers, checkboxes and fold arrows. Both used the same sample note at 16px.

- `src/styles/theme.css`: new layout tokens that themes can override. They cover the note line height (1.5), the gap above headings (one note-font-size), the H1–H6 sizes (1.618/1.462/1.318/1.188/1.076/1 em), line heights and weights (700→600), list indent (2.25em per level), item spacing (0.075em), marker widths, bullet size, marker and indent-guide colours, checkbox size and fold-arrow size.
- `src/features/editor/theme.ts`: line height comes from `--note-line-height` (was 1.65). Lines no longer get CodeMirror's 6px left padding, so body text lines up under the note title, as in Obsidian.
- `src/features/editor/livePreview.ts`: new `listLayout` function for each list item line (not inside quotes or callouts):
  - Each nesting level is a fixed-width `cm-lp-indent` step with an indent guide. A level runs from the parent item's marker to the child's, so tab and space indents both work.
  - The marker has a fixed width: a CSS-drawn bullet, a checkbox, or the number in a box sized to its digits.
  - Wrapped lines hang under the text, using `--li-depth`/`--li-marker` on the line.
  - While a bullet is edited, its raw `- ` stays in the same box, so the text doesn't jump.
- `src/features/editor/editor.css`:
  - Headings use the tokens, with no muted H6 (Obsidian keeps H6 the text colour).
  - New list and indent-guide styles.
  - Checkboxes are drawn like Obsidian's: a 1em rounded box that fills with the accent and shows a check mark.
  - Fold arrows for headings and toggle headings hang 5px left of the text. They are 10px, centred on the text line, and use the accent colour while closed. A Markdown heading's arrow shows only on hover, when closed, or when focused.
  - The fold placeholder `…` is plain and muted, 8px after the text.
- `src/features/editor/toggles.ts`: a toggle heading's arrow hangs (`cm-toggle-hang`) and its section is not indented (`cm-toggle-section`), like a heading's. A toggle list keeps its arrow inline and its inside indented under the arrow (`cm-toggle-inside`).
- `e2e/specs/heading-folding.e2e.ts`: an open heading's arrow is transparent until hovered, so the spec waits for it to exist, not to be displayed.

## Findings

No blocking findings.

1. Minor, `src/features/editor/livePreview.ts` (`listLayout`): the hanging indent of a numbered item is estimated in `ch` units for its digits, so with a font whose `.` is unusually wide, a wrapped line can be off by a pixel or two. Obsidian measures this in JavaScript. A CSS estimate keeps decoration building pure and fast.
2. Note: a list item's continuation paragraphs (indented text under an item without a marker) are not indented. Obsidian's `HyperMD-list-line-nobullet` lines are. This was the same before the change; it could be a follow-up.
3. Note: a task line being edited shows its raw `- [ ] ` from the line's start rather than in the checkbox's box. Obsidian also shows the raw marker there.
