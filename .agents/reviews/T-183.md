# T-183 review: copy the ChatGPT sign-in link

**Verdict: approve** (Claude self-review, 2026-11-07)

## Why

The user asked to be able to copy and paste the ChatGPT sign-in link as well as have it open in the browser, for example when the wrong browser or none opens.

## What changed

- `src-tauri/src/ai/subscription.rs`:
  - While a sign-in waits, its link is kept in the session state (`links`), next to the pending flag. It's removed when the sign-in ends, whether it succeeded, failed or was cancelled.
  - `pending_link(id)` returns it only while that sign-in is still pending.
  - The copyable link leaves out `id_token_hint`, which only re-sign-ins add. It's just a hint, and the identity token shouldn't reach the clipboard or the webview. Everything else that matters is the same as the opened link: `state`, `nonce`, `code_challenge` and `redirect_uri`. Either link completes the same sign-in.
  - If the browser can't be opened at all, the sign-in no longer fails straight away. It keeps waiting (up to the existing 180 seconds) so the link can be copied.
- `ai/service.rs` and `ai_commands.rs`: `subscription_sign_in_link` and the `ai_subscription_sign_in_link` command, registered in `lib.rs`.
- IPC: `aiSubscriptionSignInLink(providerId): Promise<string | null>` in `types.ts`, `tauriBackend.ts` and `memoryAi.ts`. The memory backend returns `null`, since the preview can't sign in.
- `SubscriptionConnection.tsx`:
  - While "Waiting for ChatGPT…" shows, the card asks for the link every 300 ms until it arrives, then shows it.
  - It shows: "Browser didn't open, or opened the wrong one? Copy this link into the browser where you use ChatGPT…", a read-only field that selects all when focused, and a **Copy link** button that changes to "Copied".
  - All of it disappears when the sign-in finishes or is cancelled.

## Findings

None blocking. The OAuth secret (the PKCE verifier) never leaves Rust. The link has only the public challenge, `state` and `nonce`, which is what a browser gets anyway.
