## Root cause (reproduced on the installed 0.3.95)

The installed main window already had the chosen logo (Risograph) as both ICON_BIG and
ICON_SMALL (read back with `e2e/window-icon.ps1`), yet the taskbar drew the original AXIS
triangle. A copy of the same exe run from another folder showed the logo; adding a
temporary Start-menu shortcut to that copy made it show the original again. Windows 11
groups the window under the installer's shortcut (AppUserModelID `app.axis.axisnotes`)
and draws that shortcut's icon, ignoring window icons. Setting an explicit window
AppUserModelID made the taskbar show the logo.

## Fix

- `src-tauri/src/taskbar_icon.rs`: a custom logo gives the main window its own
  AppUserModelID (`app.axis.axisnotes.logo`) with relaunch command, name and icon (a
  saved 256×256 .ico), so the button — and a pin made from it — shows the logo. The
  original logo clears them and the window rejoins the installed shortcut.
  - Windows draws the relaunch .ico and caches it by path, and ignores an instant
    identity swap: each logo is saved as `logo-<FNV hash>.ico` (`current.txt` names the
    one in use; 6 newest kept for pins), the identity is cleared and given back after
    400 ms, and an unchanged logo touches nothing.
  - At startup (`restore`, before the page loads) the current icon and identity are
    applied, so a fresh launch shows the logo at once.
  - Icons live in app-local data (`taskbar/`), or under `AXIS_CONFIG_DIR` in tests.
- `src/App.tsx`: the window logo waits for the vault's config, so startup no longer
  applies the default (original) logo first and undoes the saved one.
- `src/app/windowLogo.ts`, `src/ipc/*`: `setWindowIcon(rgba, branded)`; a missing image
  falls back to the original, unbranded.
- `windows` crate: two more features of the existing dependency
  (`Win32_System_Variant`, `Win32_UI_Shell_PropertiesSystem`); no new dependency.

## Findings

Fixed during review:

- `taskbar_icon.rs`: an unchanged re-apply bumped the generation counter and could
  cancel the delayed identity of the previous change; it no longer does.
- `taskbar_icon.rs`: clippy `unnecessary_sort_by`.

Known limits (by Windows design):

- A pin keeps the icon it was pinned with. A pin made from the Start-menu shortcut (or
  while the original logo was on) stays the original icon, and a custom-logo window then
  shows as its own button beside it; pinning that window pins the custom logo.
- Pinning itself was not exercised (Windows doesn't let programs pin); the relaunch
  properties a pin copies were read back from the window.
