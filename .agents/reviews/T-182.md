# T-182 review: ChatGPT sign-in opens the browser, not the Documents folder

**Verdict: approve** (Claude self-review, 2026-11-07)

## Why

The user clicked "Continue with ChatGPT" in Settings → AI, and their Documents folder opened instead of the sign-in page.

`ai/subscription.rs` opened links with `explorer <url>`. Explorer mangles long links with a query string (the OpenAI authorize link has about ten parameters). When it can't make sense of one, it opens the default folder, Documents. The same function opens "Manage usage" (`chatgpt.com/#settings/Usage`).

## What changed

- `src-tauri/src/ai/subscription.rs`: new `browser_command(url)`.
  - On Windows it returns `rundll32.exe url.dll,FileProtocolHandler <url>`, the standard way to open a link in the default browser. No shell or Explorer parses it, so `&`, `=` and `%xx` stay intact.
  - macOS still uses `open` and Linux `xdg-open`.
  - Only `http://` and `https://` links are accepted. Anything else is refused, so it can't launch files or programs.
- `open_browser` uses it. The process is still started without a console window.

## Findings

None. Other `explorer` uses (Show in folder, the clipper extension folder, opening vault `.html` files) open folders or files, not links, and work as they are.

  - I ran `rundll32.exe url.dll,FileProtocolHandler` on a local test page with the same kind of query string (`client_id`, `response_type`, `scope=openid+profile+email`, `state=a%2Cb`, `code_challenge_method`).
  - The default browser opened it, and the page's server received the whole path and query unchanged.
