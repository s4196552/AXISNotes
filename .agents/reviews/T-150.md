- `src/features/editor/inlineCodeLanguage.ts` (new): the `` `Java`String greeting = "Hello, World!";` `` syntax.
  - A one-backtick span holding a language name, then code that starts right after it, then a closing backtick.
  - Languages are looked up in `@codemirror/language-data` by name, alias or file extension (`findLanguage`), not fuzzily, so prose words don't match.
  - `scan()` reads a line's backtick runs left to right. A tagged span runs to the next backtick; any other run pairs with the next run of the same length, as in Markdown.
    - This is needed because the Markdown tree pairs the stray closing backtick with the next one on the line. A tree-based check missed two tagged spans on one line, and a tagged span followed by ordinary inline code; both are now tested.
  - The tree is used only to rule out code blocks, frontmatter, raw HTML, comments and `$$` math.
  - Code can't start with a space or prose punctuation, so `` `python`, `java` `` and `` `npm`'s `` stay ordinary inline code.
  - The view plugin marks the code `cm-lp-code` and colours tokens with the same `HighlightStyle` as code blocks.
    - `theme.ts` now exports it as `axisHighlight`. Only the name changed.
    - Off the cursor's line, the `` `Java` `` span and the closing backtick are hidden. On it, the raw text shows as code.
    - A language not loaded yet is loaded on first use, then the view rebuilds through a `StateEffect`. A destroyed view is guarded against, and a failed load leaves the code uncoloured.
  - The input handler runs before the other typing rules. Inside a tagged span still being typed, characters go in as typed. Without this, inline marks paired the closing backtick after `;` and symbols turned `!=` into `≠`.
- `livePreview.ts:175`: skips nodes inside a tagged span, and an `InlineCode` its closing backtick opens. It only skips nodes that start and end inside the span, so a paragraph starting with a tagged span keeps its other styling (an earlier draft got this wrong; caught in review).
- `links.ts:90`: `#tags`, `[[links]]` and block IDs inside tagged code are not rendered. The new assertion fails without this change.
- `symbolAutoformat.ts:61`: the odd-backtick heuristic is replaced by `openCode()`. Its behaviour is the same for ordinary code spans, and text after a closed tagged span is prose again (`` `Java`x;` a != b `` gives `≠` after the span).
- Known limits:
  - Other Markdown apps show `` `Java` `` as inline code, then plain text and a stray backtick.
  - The code can't contain a backtick.
  - Spellcheck may still underline words in tagged code.
