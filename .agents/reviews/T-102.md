# Review: T-102 Home as the start page

**Verdict: approve** (Claude self-review, per the 2026-10-17 working agreement)

Reviewed `git diff main...agent/claude/T-102` in full (9 files, about 220 lines added, half of them tests). `src/features/dashboard/**` is untouched (another session owns it).

## What it does

- `config.home = { openOnStartup, onLastTabClose }`, both off by default, so existing vaults see no change. Normalized by `mergeConfig` like the other sections (wrong types fall back to the defaults).
- **Open Home when a vault opens**: once the vault's settings load, `openStartupPages` (new `src/app/startup.ts`, called from `App.tsx` in place of the inline daily-note code) calls the store's new `openHomeOnStartup()`. That focuses an open Home tab, else shows Home in the active tab if it's empty, else adds a Home tab in front of the restored tabs. Restored tabs are never replaced.
- With **Open today's daily note on startup** also on, the daily note opens first (as before, only when no note is showing; if a dashboard or other view is showing it gets a new tab instead of replacing it) and Home opens last, so it's the tab showing.
- **Show Home when the last tab closes**: `closeTab`, `closeTabGroup`, `onEntryRemoved` and the restored-tab pruning in `refreshTree` call `homeIfLastClosed`. When a close left a freshly made empty tab as the active one (the last visible tab went), it becomes Home via `openDashboard("")`. Close Others / Close to the Right always keep a tab, so they don't need it.
- Settings: the "Daily notes" section is now **Home & daily notes**, with the two new checkboxes under the daily-note one (whose label is now "Open today's daily note on startup" so the three don't read alike).
- Tab bar: a **Home** button (Lucide `House`, aria-label "Go to Home" to stay distinct from the sidebar's "Home" button) left of "+", running `openDashboard("")` in the active tab (Back returns to what was there).

## Findings

No blocking findings.

1. Low, `src/app/store.ts:150`: pruning restored tabs runs in `refreshTree` from `openVault`, possibly before the new vault's config has loaded, so `onLastTabClose` may be read from the previous vault's settings. The effect is limited to a vault whose every restored tab points at a deleted file: it gets an empty tab or Home, and with `openOnStartup` on, Home follows anyway. Not worth extra coupling.
2. Note, `src/features/tabs/TabBar.tsx:201`: the button's title says Ctrl+Shift+H even if the user remapped it. This matches the existing "New tab (Ctrl+T)" title.
3. Note: `src/App.tsx` was touched (startup wiring, 3 lines) although the brief listed only store/config/Settings/TabBar. Moving the daily-note + Home sequence into `src/app/startup.ts` made it testable without rendering `App`.
