## Findings

I found no blocking defects. The resource-identity helper and the AI evaluator are correct and fail closed for everything T-042 claims. The Tauri capability change is formatting-only. The three items below are all low severity and can go into T-043 or later rebriefs, or be fixed on this branch before merge.

1. **Low: the Connect interface is missing an endpoint the protocol documents.** `docs/SUITE_PROTOCOL.md:49` lists `POST /apps/heartbeat`, but `SuiteConnectV1` in `src/suite/contracts.ts:279-287` has no heartbeat method. `RegisteredApp.status` ("available" or "unavailable") depends on liveness, so either add `heartbeat(...)` to the interface or remove the endpoint from the doc, so that ports to Rust or Python don't disagree.

2. **Low: the doc and the type disagree on who supplies a new project's ID.** `docs/SUITE_PROTOCOL.md:52-53` says project create supplies "an operation ID and name/colour/icon", and that later writes supply the project ID. But `ProjectMutation` `create` in `src/suite/contracts.ts:245` takes a caller-supplied `projectId`. `docs/SUITE.md:72` implies Connect issues the stable ID. Pick one model and state it in both places:
   - Connect issues the ID and create returns it; or
   - the caller issues it with create-only semantics, like `calendar.upsert-study-block` with `expectedRevision: null`.

3. **Low: one of the promised acceptance vectors is only partly tested.** `docs/SUITE_PROTOCOL.md:121` says "An empty list allows nothing", and `:144` lists "empty allowlists" as a vector that Rust and Python must share. `src/suite/contracts.test.ts:77-79` only tests `models: []`.
   - `operations: []` and `executions: []` pass `isAiPolicy` (`src/suite/policy.ts:26-31`). `authorizeAi` then denies them correctly (`:69`, `:78`), but no test pins that down.
   - Add both cases, plus one ordering case, so the port vectors are complete. For example, check that `[legacyAiPolicy("any"), invalidPolicy]` and `[legacyAiPolicy("any"), legacyAiPolicy("never")]` both deny, whichever order the policies come in.

## Checks with no defects found

- **Identity (`src/suite/references.ts`):**
  - The key is a JSON tuple of `appId`, `collectionId` and `resourceId`. It avoids separator collisions and is tested.
  - Extra fields such as `title` or `rowId` are ignored, so the identity survives renames and index rebuilds.
  - An unknown `appId`, an empty ID or a whitespace-only ID is rejected.
  - `resourceKey` throws on invalid input, so `sameResource` can't silently match malformed refs.
  - The doc states clearly that this key doesn't replace the existing Notes `axis:` links.
- **AI evaluator (`src/suite/policy.ts`):** every path fails closed.
  - An empty policy list, an unknown operation, a malformed candidate, an unverified execution, an `unknown` location, a non-v1 policy version or a sparse list (checked through `Array.from`) all deny.
  - The evaluator stops at the first failing policy, so it enforces the intersection of all policies.
  - Model matching compares provider, endpoint and model exactly.
  - Every operation, including suggest and apply, requires `read`, and `apply` must be listed explicitly.
  - `private-server` is kept separate from `on-device`.
- **Legacy mapping:** `legacyAiPolicy("local")` maps to `["on-device"]` only. Today's Rust `AiRule::Local` (`src-tauri/src/ai/privacy.rs:22-23`) accepts any localhost endpoint, so the new mapping is stricter, which matches the "preserve stricter restrictions" rule in `docs/SUITE.md:149-152`.
- **Existing Rust behaviour:** `rules()` in `privacy.rs:30-47` silently drops invalid config and falls back to `Any`, which is fail-open. That behaviour predates T-042, which leaves it unchanged. The handoff and SUITE.md correctly assign the fix to T-045, so I have not counted it against T-042.
- **Compatibility:**
  - There are no runtime imports of `src/suite/**`.
  - No identifiers, formats, dependencies or IPC changed.
  - `app.axis.axisnotes`, `.axisnotes`, `.axgrid`, `.axcanvas`, block IDs and `axis:` links are explicitly kept.
- **Provenance and privacy boundaries:**
  - `SourceProvenance` records the source revision and policy revision.
  - `MediaAnalysisLink` treats the fingerprint as a version, not as identity.
  - `ResourceChange` includes `policy-changed`.
  - The protocol states that Connect exposes no content transfer and that native backends hold credentials.
- **`src-tauri/capabilities/default.json`:** in the diff (lines 1027-1045) the same `windows` and `permissions` entries are collapsed onto single lines. This is formatting only and the permissions are unchanged.
