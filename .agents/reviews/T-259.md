## What it changes

The human asked for tables "more like Obsidian UI/UX". The old table had text buttons above
it ("Edit cells", "Format table", "Edit Markdown") and a separate edit mode with textareas
and "Remove row" buttons. Now (`src/features/editor/tables.ts`, `tableOps.ts`, `editor.css`):

- **Look:** sized to its content, quiet borders, a bold header, no zebra stripes, and lined
  up with the note's text. A table wider than the note still scrolls inside it (T-126).
- **Typing:** click a cell and type.
  - Tab and Shift+Tab move to the next or previous cell; Tab in the last cell adds a row.
  - Enter goes to the cell below, adding a row after the last one.
  - Shift+Enter is a line break.
  - The arrow keys leave a cell at its edges.
  - Escape stops editing.
  - Before editing, the arrow keys move between cells, and Enter or F2 starts editing.
- **Grips:** six-dot grips beside a row and above a column, shown while the pointer is over
  it.
  - Click: the row menu (insert above/below, move up/down, duplicate, delete) or the column
    menu (insert left/right, move left/right, duplicate, align left/centre/right, sort A→Z /
    Z→A, delete).
  - Drag: moves the row or column, using pointer events because the desktop webview
    swallows HTML drag and drop.
  - The header row stays first.
- **+ bars:** along the right and bottom edges, they add a column or a row and start
  editing it.
- **Right-click on a cell, or the menu key:** that cell's row and column edits, plus
  **Edit as Markdown** (the source view, as before) and **Tidy up the Markdown** (the old
  "Format table").
- **Read-only notes:** no grips, bars or editing.
- Every edit is written straight back as Markdown and can be undone. Structural edits
  rewrite the table tidily, as Obsidian's do.
