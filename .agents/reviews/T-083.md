## Findings
1. Fixed before commit — `src/features/editor/Editor.tsx` (`changeProps`): inserting the
   first frontmatter key with the cursor at the top of the note put the cursor inside the
   new YAML block, so it unfolded (seen in the preview). A cursor below the frontmatter
   is now mapped past the inserted text. This also fixes adding a first property from the
   properties chip. Covered by a test.
2. Fixed before commit — `src/features/editor/Editor.tsx`: the page header only mounted
   once the note loaded, so the title jumped ~20 px; it now renders while loading too.
3. Fixed before commit — `src/features/editor/PageHeader.tsx`: cover focus values
   drifted (`60.00000000000001%`); positions are rounded to two decimals as they change.
4. Fixed before commit — `src/features/editor/PageHeader.tsx`: compact mode only applies
   when there is a cover, so scrolling a plain note doesn't shift its title.
5. Medium, accepted with a note — `src-tauri/src/commands.rs` (`import_image`): the
   command copies any *image* file whose path the webview passes (normally from the
   native dialog). It can't write outside the vault, overwrite, or copy non-images or
   files over 25 MB; the AXISNotes webview is local and trusted. Revisit if remote
   content ever gets IPC access.
6. Low, accepted — renaming an image breaks covers/image icons that point to it (they
   say "not found" / fall back). See handoff.
7. Low, accepted — SVG covers and icons load through `<img>`, which doesn't run scripts.
8. Fixed after the native E2E run — `src/features/editor/PageHeader.tsx` (`onPointerDown`):
   while repositioning, pressing **Save position** or **Cancel** started a drag and captured
   the pointer, so a real mouse click never reached the button (jsdom tests clicked
   directly and missed it). Presses on buttons no longer start a drag; the unit test now
   checks the press isn't captured and fails without the fix.
9. Fixed after the native E2E run — `src/features/editor/PageHeader.tsx`: the cover's
   `object-position` is written as a whole percentage, avoiding values like
   `34.00000000000001%`.
10. Process note — while trying to automate the native Open dialog, the E2E briefly sent
    OS-level keystrokes (a temp file path, then Enter) to the window Windows matched as
    "Open". A screen capture showed the user's browser in front, so the keys may have
    landed there on two runs. The approach was removed, the capture deleted, and the user
    warned. Native E2E must never use desktop keystrokes.
