Seen in the preview while checking the new "Not verified" text. The banner's position is unchanged here. It's a follow-up for whoever owns the Agent or the banner.
2. **Fixed during verification:**
   - Rustfmt and Prettier reformatted long lines in `updates.rs`, `UpdateBanner.tsx` and `updates.test.tsx`.
   - The decision entry first named the wrong license for `ring`. It now says `Apache-2.0 AND ISC`, from the crate's `Cargo.toml`.
3. **Design note:**
   - The signature covers the manifest's raw bytes. No JSON canonicalisation is needed, and a BOM or whitespace change counts as tampering; there is a test for this.
   - `check` reads the bytes once and parses the bytes it verified. `prepare` re-reads and re-verifies, so a manifest swapped between the check and the click is caught.
4. **Design note:**
   - The UI's `allowUnverified` is not a security boundary against the webview. It only stops the automatic path, and a verified-then-swapped manifest, from installing unverified code.
   - The threat here is whoever can write to the folder, and the gate against them is in Rust (`prepare`).
5. **Residual risk (in the handoff):**
   - Installed 0.3.111 and earlier don't check signatures, so protection starts once 0.3.112 is installed.
   - There is no Authenticode certificate yet.
   - A folder writer can still offer an unverified update and rely on the user clicking "Install anyway".
