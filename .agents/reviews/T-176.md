# T-176 review: remove High contrast, Retro, Glass and Minimal

**Verdict: approve** (Claude self-review, 2026-11-06)

## What changed

- `src/app/appearance.ts`: `BUILTIN_THEMES` and `THEME_INFO` now hold System, Light, Dark, Darker and Translucent. The Settings tiles and the command palette's "Choose theme" both read these lists, so both lose the four themes. `keptTheme()` maps a removed id to its counterpart, and `applyAppearance` and `effectiveMode` use it.
- `src/app/config.ts`: `REMOVED_THEMES` (a `Map`) and `migrateRemovedThemes`, run on load after the existing trigger and window-effect migrations. Minimal and Retro become `light`, High contrast becomes `dark`, and Glass becomes `system`.
- CSS: removed the four token/structure blocks in `src/styles/themes.css`, High contrast's syntax colours in `src/styles/theme.css`, and the per-theme miniature styles in `src/features/settings/themePicker.css` (Glass, Retro, High contrast). The `--glass-*` variables were used only by Glass. The Translucent / Liquid glass styles (`data-glass="liquid"`) are separate and unchanged.
- Tests: `themes.test.tsx`, `palette.test.tsx` and the `panes.e2e.ts` theme list now cover the kept themes. The Glass-only `backdrop-filter` assertion is gone; the "no `isolation:` on panes" check is kept.

## Findings

1. Fixed during review, `src/app/config.ts` (`REMOVED_THEMES`): the first version was a plain object, so `REMOVED_THEMES["constructor"]` would have returned `Object.prototype.constructor` for a user theme with that file name. It is now a `Map`, and a test loads a user theme named `constructor`.
2. Note, no change needed: migration happens in memory on load. `config.json` keeps the old id until the user's next settings change writes the file. Every read path (`applyAppearance`, `effectiveMode`, the Settings picker after load) shows the counterpart, so nothing renders unstyled meanwhile.
3. Note, no change needed: user themes are untouched. The removed ids all carry the `axis:` prefix, which can't appear in a Windows file name, so a user's own `retro.css` (saved as `retro`) still loads. A test covers this.
