# Review: T-124 (side panel zoom scales the content, not the panel)

**Verdict:** approve

Human request (2026-10-22): when zooming, change the zoom of the sidebar's content, not the sidebar itself.

## Reproduced

Real release build (events sent into the page over the DevTools port): Ctrl + wheel over the left panel at 175%
kept its 260 px width, but its header (vault name truncated), panel switcher and toolbar icons were enlarged with
the file list, so the panel itself looked bigger.

## Change

- `src/app/zoom.ts`: `useAreaZoomProps(area, { content: true })` sets only `--area-zoom` on the part (no CSS zoom on
  it); `src/App.tsx` uses it for both side panels. The main view and tab bar are unchanged.
- `src/styles/app.css`: zoom applies to the panels' content — the file list (`.filetree-body`), search results and
  help (not the search box), the tags list, and the right panel's calendar, outline, links and hint — while the
  header, switcher, toolbars and section titles keep their size. The width compensation is gone (nothing on the
  panel is zoomed). The canvas/graph "undo zoom" rule is limited to the main view; the local graph's canvas sits
  outside the zoomed content, so it needs none.
- Test: a side panel gets `--area-zoom` without `zoom`; the main view gets both.

## Checks

- `pnpm lint`, `pnpm typecheck`: pass. `pnpm vitest run --maxWorkers=4`: 81 files, 678 tests pass.
- Release build, left panel at 175% and right panel at 150% (Ctrl + wheel events in the page):
  - Panel widths 260 / 280 px before and after; sidebar header 38 px, file toolbar 33 px and section titles 34 px
    unchanged; file rows 26 → 46 px; calendar 205 → 308 px; local graph 278×200 at zoom 1, unchanged.
  - Dragging `Third.md` onto `Beta` in the zoomed file list moved it to `Beta/Third.md` (drop maths holds under
    zoom).
- No Rust changes.
