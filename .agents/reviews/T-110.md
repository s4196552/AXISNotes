# Review: T-110 — Vault menu on the vault name, and "Open another vault…"

**Verdict:** approve (self-review by Claude, the lead, per the 2026-10-17 agreement)

Finding N4 of the 2026-10-20 UX review (batch 2, picked by the human). Before this, once a vault was open nothing led back to another vault. Reviewed `git diff main...agent/claude/T-110` in full.

## What changed

- The vault name at the top of the sidebar is now a button (`VaultMenu.tsx`) that opens a menu:
  - **Switch to:** the other recent vaults (name and folder);
  - **Open folder as vault…** and **Create new vault…** (asks for the name, then the parent folder);
  - **Show vault in File Explorer** (`revealEntry("")` from T-109) and **Vault settings**.
- The menu focuses its first item, moves with ↑/↓, and closes on Escape (back to the button), an outside click or the window losing focus.
- Palette commands **Open another vault…** (a picker with the same choices) and **Show vault in File Explorer**, registered from `vaultSwitch.ts`.
- **Safe switching** (`vaultSwitch.ts`): every open document is saved first (`saveAll`). If one can't be saved, the vault isn't switched and the status bar says which note.

## Findings (most severe first)

1. **Minor, accepted:** a vault created from the menu starts empty. The welcome screen's "add example notes" choice isn't offered here.
2. **Minor:** Show vault in File Explorer only works in the desktop app (the browser preview says so).
3. **Minor, accepted:** there is still no "Close vault" back to the welcome screen. Switching covers the need, and closing would need a backend call to release the index.
