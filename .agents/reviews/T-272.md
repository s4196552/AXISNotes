# T-272 review: settings colors, math color, theme click, American spelling

**Verdict:** approve (Claude, self-verified under the 2026-11-10 rule)

## What the human asked

- "For settings add custom color for bold, italize, math, and strikethrough in Appearance
  -> Typography"
- "Have settings Colours be in theme & layout and have those effects change the settings
  page"
- "Clicking on theme colors should automatically change to it regardless of the App
  colours selected."
- "Change App Colours to colors and use normal americanized english"

## Changes

1. **Typography.** The bold, italic and strikethrough color rows moved from Theme & layout
   to Typography, with a new **Math** row.
   - `TextColorKind` gains `math`, and the config default is off; older configs merge to
     off, which a test covers.
   - Math uses `--text-math`, with a theme suggestion `--text-math-theme`
     (`light-dark(#9333ea, #d8b4fe)`, black on E-ink).
   - `.cm-math` (KaTeX in notes) uses `color: var(--text-math, inherit)`.
2. **Colors in Theme & layout.** The separate "Colours" tab is gone. A "Colors" field sits
   under the theme list.
   - `appColorsCss` also targets `.modal.settings` (main colors) and `.settings-nav`
     (sidebar colors), so the Settings window takes the chosen colors.
3. **Picking a theme clears custom colors.** Choosing a theme tile saves `theme` and
   `appColors: NO_APP_COLORS` together. A click on the tile that's already chosen does the
   same, through `onClick`.
4. **American spelling.** "Colour" becomes "Color" in all user-facing strings: labels,
   hints, tooltips, aria-labels, notices and the built-in skill prompts.
   - Code identifiers (`isLightColour`), code comments and the bundled third-party skill
     pack are unchanged.
   - Tests that look up those labels are updated.
5. The text-color rows got a fixed label column, so "Strikethrough" no longer crowds its
   Light chip.

## Findings

1. (Fixed) The bulk spelling script wrote CRLF line endings. They were stripped back to LF
   before committing, and `git diff` shows only real changes.
2. (Note) Inline `$…$` math is not rendered in the editor today, as before this change, so
   the math color shows on `$$` math blocks. This is unchanged.
