# Review: T-107 — Editable note title, grouped header tools, no duplicate title, save state in the status bar

**Verdict:** approve (self-review by Claude, the lead, per the 2026-10-17 agreement)

The human picked batch 1 of the 2026-10-20 UX review (findings E1, E2, E3, E5) with mockup M1 option A ("tools beside the title"). Graph fitting (L4) is T-108. Reviewed `git diff main...agent/claude/T-107` in full.

## What changed

- **E1, editable title.** The note header's static `<h1>` is now a text field (`NoteTitle.tsx`, aria-label "Note title"). Enter, ArrowDown or leaving the field renames the file through the same path as a file-tree rename (`renameEntry` in `src/features/files/renameEntry.ts`, moved out of `FileTree.tsx` with `remapIcons`/`remapKeys` so icons, colours, dashboards and tabs follow). Unsaved edits are flushed first, and the rename is skipped if they can't be written. Names with `\ / : * ? " < > |`, a leading dot or an existing note's name (case-insensitive) are refused with a status-bar error, and the old name comes back. Escape restores the name and moves to the text.
- **New-note focus.** Ctrl+N (`newNote` with the default "Untitled") asks the editor to focus the title with the name selected (`focusRequest.ts`); a named note (from the quick switcher) opens with the cursor in the text. After a rename by Enter the remounted editor puts the cursor in the text.
- **E2, grouped tools.** The bug was `margin-left: auto` on every `.editor-tool`. The four tools now sit in one `.editor-tools` group at the right, dimmed to 60% until the header is hovered or focused, or a tool is active (outline on, timer running). The header rule `.editor-title + * { margin-left: auto }` keeps the grid, canvas and image headers' own layout (one push, not one per button).
- **E3, no duplicate title.** `titleHeading.ts` hides the first non-blank line after the frontmatter when it is `# <title>` (case and spacing ignored), plus one blank line after it, using a block-replace decoration from a StateField. It shows again while the selection touches it; the file is never changed. A note opened fresh starts its cursor below the hidden heading.
- **Daily notes** show "Tuesday, October 20, 2026" as the title (not editable, since a renamed daily note stops being one; the file name is the tooltip), with Previous day / Next day buttons that open or create the neighbouring daily note. The daily template's own `# dddd, MMMM D, YYYY` heading matches that title, so it is hidden without changing the template (the dashboard quick-add and existing files rely on its layout).
- **E5, status bar.** The word count (and "N of M words" for a selection, counted 200 ms after typing stops, frontmatter excluded) and the save state now show at the right of the status bar. The editor portals them into a slot the status bar registers (`statusSlot.ts`); with no status bar (the editor alone, as in the component tests) they stay in the header, so existing `role="status"` tests are unchanged.

## Findings (most severe first)

1. **Minor, not done:** the review proposed an "AI working" indicator and a click-to-reveal path in the status bar. AI requests only run inside the Ask AI / Fix writing dialogs, which already show progress, so the indicator was left out; reveal-in-tree belongs with N5 (not picked).
2. **Minor, accepted:** grids and canvases still show "Saved" in their own headers; only notes moved to the status bar.
3. **Minor, accepted:** the word count includes a hidden title heading's words (it is still in the file).
4. **Minor, accepted:** clicking elsewhere after typing a new name renames the note, as in Obsidian; only Escape discards the change.
