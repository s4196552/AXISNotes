# T-099 review: updates install automatically by default

**Verdict:** approve

## What changed

- `src-tauri/src/updates.rs`: `UpdateSettings.auto_install`, default `true`. The struct is `#[serde(default)]`, so an `updates.json` saved before this option existed loads with it on (tested), and existing installs switch to automatic install.
- `src-tauri/src/updates_commands.rs`: the settings view adds `autoInstall` and `canInstall` (a release build on Windows, the same condition `updates_install` already enforces); `updates_save_settings` takes `auto_install`.
- `src/ipc/{types,tauriBackend,memoryBackend}.ts`: the new fields and the `updatesSaveSettings(checkOnLaunch, autoInstall, folder)` signature. The browser preview reports `canInstall: false`.
- `src/features/updates/updates.ts`: `checkOnLaunch` installs what it finds when `autoInstall && canInstall`. `install()` is unchanged, so it still saves every open document first and refuses over unsaved/conflicting edits (T-073), showing why in the banner.
- `src/features/updates/UpdatesSettings.tsx`: "Install updates automatically" checkbox, disabled while "Check for updates when AXISNotes starts" is off; `save()` now keeps both choices when the folder changes.
- `src/features/updates/UpdateBanner.tsx`: doc comment only.

## Findings

None blocking.

- Automatic install runs only at launch. An update published while AXISNotes is open is found at the next start; there's no periodic check, so nothing polls in the background.
- `canInstall` keeps development builds and the E2E build (a debug build) from attempting, and failing, an install at every start. `updates.e2e.ts` behaviour is therefore unchanged.
- If an automatic install fails (e.g. a checksum mismatch), the banner shows the error and the Install button, the same as a manual attempt; it is tried again at the next start.

- Preview (vite on 1699): Settings → Updates shows both boxes checked; unchecking the launch check disables "Install updates automatically" and keeps its value.
