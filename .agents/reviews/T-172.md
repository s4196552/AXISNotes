# T-172 review: your own images for each Agent state, and sprite strips

**Verdict: approve** (Claude self-review, 2026-11-05)

## What changed

- `src/features/agent/agentImages.ts`: images are stored on this device in IndexedDB (`axis-agent` / `images`, keyed by state), which both windows can read.
  - The main window sends only `imagesVersion`. The version is bumped on every change and shared through `localStorage`. Each window loads the version it's given and replaces its previous object URLs.
  - Accepted: PNG, JPG, GIF, WebP, APNG and SVG (shown through `<img>`), up to 8 MB. Frames 1–64, speed 1–30 fps.
- `AgentView.images` became `imagesVersion`. `AgentApp` and the in-page Agent load the images for that version.
- `AgentFigure`: a single image, or a sprite strip stepped through with `steps(n, jump-none)` over `n × 100%` background size. Reduced motion shows the first frame.
- Settings → Agent → Images has one slot per state with a preview, Choose/Change, Remove, Frames and Speed. It explains the fallback (a state without its own image uses Idle's, then the built-in Agent) and has "Use the built-in Agent for every state".
- `AgentBridge`: the Agent stays off under WebDriver, so end-to-end runs see one window.
- `agentModel`: Needs you shows the real error, shortened, for example "No AI provider is set up…".

## Findings

No blocking findings. Notes:

1. Exporting and importing a whole Agent set (`.axagent`) is not built. That needs a save dialog path or a zip writer and is left as a follow-up.
2. jsdom has no IndexedDB, so the tests replace storage with a map. The real IndexedDB path ran only in the built app, which loaded no images (none were set).
