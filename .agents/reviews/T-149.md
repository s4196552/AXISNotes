Findings: none blocking.

- `src/features/editor/symbolAutoformat.ts`: a new input rule. Typing the second character of `->`, `<-`, `>=`, `<=`, `!=` or `~=` replaces the pair with `→ ← ≥ ≤ ≠ ≈`. A `>` straight after an auto `←` gives `↔`. Backspace straight after a replacement puts back the typed ASCII, the same way list autoformat's Backspace works.
  - Escape routes for other syntax: `-` after an auto `←` gives `<--`, so `<-->` stays ASCII. `=` after an auto comparison sign gives `!==`, `>==` and so on. `-->` and `\->` are never converted.
  - Places it never converts: anything `verbatim()` covers (code, frontmatter, raw HTML, comments, `$$` math), an inline code span still being typed (odd backtick count), an unclosed `[[` on the line, and a URL up to the cursor. It also does nothing with more than one cursor or during IME composition.
- `src/features/editor/listAutoformat.ts:37`: exports `pendingBullet()`, a read-only view of its auto state. A `>` typed right after the auto `- ` bullet then becomes `→`, so `->` works at the start of a line. `symbolAutoformat` is registered before `listAutoformat` in `Editor.tsx`, so its handler runs first.
- Minor: Ctrl+Z after an arrow undoes it together with the preceding typing, because the replacement shares the `input.type` history group. Backspace is the one-step undo, the same as list autoformat. There is no setting to turn the rule off; the user did not ask for one.
