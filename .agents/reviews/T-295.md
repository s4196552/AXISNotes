# T-295 review: the AI chat draws on the open canvas

**Verdict: approve** (Claude, self-verification under the 2026-11-10 rule)

## What changed

- **Draw mode in the sidebar chat** (`src/features/ai/SidebarChat.tsx`, `canvasChat.ts`):
  - When the focused tab is a canvas, the chat shows a canvas chip (with ×), and the action menu offers **Ask** and **Draw**. Draw is the default; Suggest edit stays for notes.
  - Draw sends a compact summary of the canvas, in the same shape as the connector's `read_canvas`: ids, types, rounded boxes, labels, non-default colors, and arrow ends. It never sends the raw Excalidraw JSON or image data. The summary is read again when the message is sent.
  - The model answers with `{"ops": [...], "reply": "..."}`. The operations use the same fields as the connector's `add_to_canvas` and `change_canvas`: `add` (rectangle, ellipse, diamond, text, noteCard), `arrow` (from/to by id), `change` (move, resize, relabel, recolor, font size) and `delete` (with its label and arrows).
  - The answer is checked against the canvas, and an invalid answer is retried once with the problems (`askValidated`).
  - Ask mode on a canvas sends the same summary, so questions about the canvas work too. The history keeps only the question, because the canvas is sent fresh each time.
- **Privacy:**
  - The request goes through the provider layer with `sources: [canvas]`, so the Rust layer applies the canvas folder's rule and model allowlist.
  - A canvas in an "AI: never" folder is refused before anything is sent.
  - Drawing notes held to a stricter rule (for example, local-only notes attached to the chat) onto a looser canvas is refused. The drawing would otherwise carry their content to a less private place, and canvases have no `ai-access` mark to raise.
  - Note cards list their note path only when the note's folder rule is no stricter than the canvas's. Note cards may only show notes that exist and that the request may read.
- **Operations engine** (`src/features/canvas/canvasOps.ts`):
  - A TypeScript twin of `src-tauri/src/mcp/canvas.rs` add/change: complete elements, bound labels, arrows routed border to border, auto-placement in a grid, versions raised on every change, and `axisRemeasure` on estimated text.
  - It also handles partial parsing of a streaming answer (`partialDraw`, built on `arrayAfter` from `lib/diagram.ts`), plus `touchedIds`/`overlay` for drafts.
- **Live drawing and undo** (`src/features/canvas/activeCanvas.ts`, `Canvas.tsx`):
  - Each mounted canvas registers a handle by path. `begin()` snapshots the scene.
  - `preview(ops)` recomputes from the snapshot and puts the touched elements over the current scene with `CaptureUpdateAction.EVENTUALLY`. Edits the user makes meanwhile are kept, and the drawing scrolls into view if none of it shows.
  - `commit` applies the checked answer with `IMMEDIATELY`, so Ctrl+Z takes back the whole drawing in one step. `discard` restores the snapshot's elements for anything the draft touched.
  - Text is measured with the real font (`restoreElements` and `remeasure`), as for outside changes.

## Findings

Found and fixed during verification in the real app:

1. **Undo didn't take back the drawing** (`src/features/canvas/Canvas.tsx`, commit). Excalidraw 0.18's store leaves elements it hasn't committed out of an `IMMEDIATELY` update (`filterUncomittedElements`) because it treats them as local edits in progress, and the live preview is exactly such elements. The undo button stayed disabled, and the one step that did record removed only the labels.
   - Fix: commit first takes the draft back (`EVENTUALLY`), then applies the finished drawing with `IMMEDIATELY`.
   - Unnamed labels and shapes keep the same ids across redraws (`stableIds`).
   - The Canvas test fake now models the store's commit filter and undo. With the fix removed, the test fails.
2. **The drawing went past the view and under Excalidraw's tool bar.** The canvas now scrolls a drawing into view while it grows. It centers the drawing, and fits it only when it's larger than the view, keeping it clear of the tool bar.

Not changed: T-293's diagram maker uses the same draft pattern, but it gives the finished diagram new ids, so its undo step is recorded.

Known limits:

1. If the user edits an element that the AI is changing while it draws, the AI's version wins for that element.
2. Live previews are autosaved like any other edit. If the app closes mid-stream, the partial drawing stays.
3. The chat draws on the focused pane's canvas only; a canvas open in another pane isn't a target.
4. Note-card paths are hidden by folder rule. A note in an "any" folder whose own `ai-access` mark is stricter still shows its path (only the path, never its text).
