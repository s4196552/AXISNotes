# Review: T-190, web pages shown in the app

**Verdict: approve** (Claude, self-review under the 2026-10-17 agreement)

Branch `agent/claude/T-190`, from `4bd168e` (Release 0.3.69).

## What changed

- `src-tauri/src/pages.rs` (new) serves vault files through the `axispage` protocol: `http://axispage.localhost/<path>` on Windows, `axispage://localhost/<path>` elsewhere. It registers in `src-tauri/src/lib.rs`.
  - Only GET, and only `.html`/`.htm`, CSS, JS, images and fonts. Paths outside the vault get a 403; files over 25 MB aren't served.
  - Every response carries a CSP with `sandbox allow-scripts allow-forms allow-modals`, `default-src 'none'` and no `connect-src`. It also sends `nosniff`, `no-referrer` and `no-store`.
- `tauri.conf.json`: the app CSP's `frame-src` gains the protocol's two origins.
- `WebFileView` shows the page in `<iframe sandbox="allow-scripts allow-forms allow-modals" referrerpolicy="no-referrer">`.
  - Toolbar: Reload, Open in browser, Show in folder.
  - The page reloads when the file changes outside the app.
  - The memory backend (browser preview) keeps the old "Open in browser" card.
- `Backend.pageUrl(path)`: Tauri builds it with `convertFileSrc("", "axispage")` and encodes each path segment separately, so relative links resolve within the page's folder. The memory backend returns null.
- AI skill pages: Open page (a draft in a tab), Save next to the note (then opens in a tab) and Try the practice page all open in the app. Open in browser is a secondary button.

## Findings (most severe first)

1. **Residual risk, accepted: Tauri's IPC bridge is injected into the page frame on Windows.** In the real app, `__TAURI_INTERNALS__`, `window.ipc` and `chrome.webview` all exist inside the frame (`src-tauri/src/pages.rs:1`). Tauri marks its invoke scripts "main frame only", but WebView2 still runs them in subframes. Every command attempt failed, through three separate layers:
   - **Null origin.** Tauri's IPC protocol parses the `Origin` header as a URL and rejects `null`.
   - **CSP.** It blocks `fetch` to `ipc.localhost` from the page.
   - **`postMessage` from the subframe.** Messages via `window.ipc` or `chrome.webview` are not processed. No command ran.

   The third layer depends on wry/WebView2 behaviour. After any Tauri or wry upgrade, re-run `.agents/qa/T-190/probe.html` together with the `create_dir` side-effect check below. Never add `allow-same-origin` to the frame: that would give the page the `axispage` origin, which Tauri's `is_local_url` treats as the app itself.
2. **Low: no test clicks "Open page" in the skills block.** It is `createDraft({ … open: true })`, the same path the drafts tests cover, and "Save next to the note" is covered.
3. **Note: pages with dark styling** paint over the frame's white backdrop (`src/features/drafts/drafts.css`). A page that only changes its text colour for OS dark mode would show light text on white. AI pages set their own backgrounds.
