# Review: T-112 — Readable search results: clean snippets, the heading of each match, operator help

**Verdict:** approve (self-review by Claude, the lead, per the 2026-10-17 agreement)

Finding N7 of the 2026-10-20 UX review (batch 2, picked by the human). Reviewed `git diff main...agent/claude/T-112` in full.

## What changed

- **Clean snippets:** `cleanSnippet` (`src/lib/searchText.ts`) removes Markdown syntax: heading markers, quotes, list bullets and task boxes, emphasis, strike, highlight and code ticks, block ids. Wikilinks and links show as their text, `[[Note|alias]]` as the alias. The match markers are kept, so highlighting still works. Tags and `snake_case` stay.
- **Heading of the match:** search hits carry `heading`, the last heading at or before the first match (code blocks skipped):
  - Rust: `heading_at` and `first_match_offset` in `index/search.rs`; the query now also returns `fts.body`;
  - in-memory backend: `headingAt`.
  The panel shows "Biology › Cells", and clicking the result opens the note at that heading.
- **Operator help:** with an empty box the panel explains what is searched and lists `tag:`, `path:`, `prop:k=v`, `"exact phrase"` and `-word` with a one-line meaning each. Clicking one puts it in the box.

## Findings (most severe first)

1. **Minor, not done:** the review proposed grouping several matches per file. The index returns one row and one snippet per note, so each file appears once; per-match listing would need a different query.
2. **Minor, accepted:** the heading is found from the snippet's first highlighted word, matched case-insensitively in the note text, so a word that also appears earlier can point at an earlier heading.
3. **Minor, accepted:** heading text is still part of the snippet (its `#` markers are gone).
