## What the menus are now

- **File:** Open in new tab / Open in split screen / Open in new window — New Note / New Grid / New Canvas / New Folder (in the file's folder) — Make a copy / Move file / Favorite — AI ▸ — Change Icon / Change Colors — Delete / Copy / Cut / (Paste, while something waits) / Rename.
- **Folder:** New Note / New Grid / New Canvas / New Folder — Make a copy / Move folder / Search in folder / Favorite — AI ▸ — Change Icon / Change Colors — then, kept from before: dashboard (Add / Open / Remove) and Sort A–Z when the folder has its own order — Delete / Copy / Cut / (Paste) / Rename.
- **AI ▸** (notes and folders): Send to AI Chat, Ask AI about this note/folder, Add to comprehension heatmap…, AI Skills ▸ (every skill), AI Access ▸ (Inherit / Never / Local models only, current one checked, then Allowed models…). Other files (images, PDFs) get AI Access only.
- **Empty space:** New Note / New Grid / New Canvas / New Folder — Paste and Sort A–Z when they apply.
- **Several picked items:** AI ▸ (send, heatmap, skills) and Add N to favorites — Delete / Copy / Cut N items.

## Choices made

1. The two "Copy" items: the one beside Move/Favorite is **Make a copy** (duplicates beside the item as "Name copy", one undo step, using the existing `copyEntry` + `copiesMade` undo); the last group's **Copy** is the existing clipboard copy (Ctrl+C).
2. "Favorite" toggles: it reads **Unfavorite** once the item is a favorite. The Favorites panel's empty hint now says "choose Favorite".
3. Kept, not in the human's list: Ask AI about this note/folder and the heatmap (inside AI ▸), dashboards and Sort A–Z (folder), Paste. **Removed from the menu:** Move up / Move down; Alt+↑/↓ and dragging still reorder.
4. **Search in folder** opens Search with `path:<folder>/ ` (quoted when the path has spaces). The `path:` filter is a substring match, so a folder named like the tail of another path also matches; pre-existing search behaviour.
5. **Open in new window** had no existing action. It opens a second app window (`note-…` label, same framed look) on `index.html?note=<path>`, which opens just that note and keeps its tabs to itself (the main window's saved tabs/panes are untouched). The capability gives `note-*` windows the main window's permissions. Because the backend doesn't report the app's own saves, each window now tells the others over a `BroadcastChannel` (`src/app/windows.ts`) what it wrote, created, renamed, copied, trashed or restored; the other windows treat that like an outside change (editor reloads or shows its conflict banner, tree re-lists), and re-read settings when `.axisnotes/config.json` was saved. Opening another vault in one window: the main window follows; a note window closes. The note window skips the update check, the Agent, the daily note/Home startup pages, the timer restore and Getting started. In a browser (no `appWindows`) the item isn't shown; the dev preview opens a popup on its own demo vault.

## Findings

1. Note: `ContextMenu.tsx` is new shared menu code (groups, submenus, keyboard). Keyboard: the menu key or Shift+F10 opens the selected row's menu; ↑ ↓ Home End move; → / Enter / Space open a submenu and focus its first item; ← / Escape close a submenu back to its item; Escape closes the menu and returns focus to the tree; Tab leaves. Submenus open on hover, flip left near the right edge, move up near the bottom and scroll when taller than the window (the skills list is).
2. Note: while two windows are open, each autosave in one makes the other re-list the tree (as an edit made outside the app does). Only with a second window open.
3. Known gap: settings changed in both windows within the same ~300 ms save delay: the later save wins. A vault opened from a note window's own vault switcher moves the main window to it too.
