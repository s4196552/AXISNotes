# Review: T-118 (welcome screen at start)

**Verdict:** approve

Human request (2026-10-21): stay on the home screen at start so the person opens a vault themselves.

## Change

- `src/app/recentVaults.ts`: reopening the last vault at start is now opt-in. `reopenLast()` is true only when the
  welcome-screen box was ticked. The storage key moved to `axis:reopen-last-vault-v2`, so the old default (on, never
  stored) doesn't carry over; someone who ticks the box again gets the old behaviour back.
- `src/App.tsx`: comment only. A vault the backend already has open (webview reload) is still restored.
- Tests: `src/app/startup.test.tsx` renders the whole app on a cold start (welcome screen stays; reopens when chosen);
  `onboarding.test.tsx` checks the box starts unticked and turns reopening on.

## Findings

None blocking.

- Note: users who had explicitly unticked the box before are unaffected (still off). Users who had it on by default
  now see the welcome screen first, as requested.

## Checks

- `pnpm lint`, `pnpm typecheck`: pass.
- `pnpm test`: 80 files, 665 tests pass. (An earlier full run had two timing failures in `media.test.tsx` and
  `installGuard.test.tsx`, unrelated; both pass on rerun and in the final full run.)
- The new startup test fails against the old `recentVaults.ts` and passes with the change.
- No Rust changes, so no `cargo test`.
- Preview: the browser preview's demo backend always starts with a vault open (the reload path), so it can't show a
  cold start; the App-level test covers it instead.
