# T-294 review: AI chat context as removable chips

**Verdict: approve** (Claude, self-verification under the 2026-11-10 rule)

## What changed

- `src/features/ai/SidebarChat.tsx`: the composer's context row shows chips like the editor's tabs (icon, name, ×): the open note, a selection ("Selected text · Note"; clicking it opens the passage above the box with Use whole note), or one chip per attached note. × takes it out of the chat. The open note or selection stays out until the user picks another note or selection, starts a new chat, or opens the chat from a menu again. Removed: "Open note · …", "Attached notes · N" and the Follow editor selection button. The skill chip uses the same look.
- `src/features/ai/sidebarChatState.ts`: attached notes keep each note's text and AI rule (`files`), so one can be removed and the text and the strictest rule are rebuilt from the rest (`attachedContext`, `withoutAttached`).
- `src/features/ai/sidebarChat.css`: chip, × and preview styles.
- Tests: 2 new chat tests (remove one attached note, rule drops from local to any and its text is no longer sent; remove a selection then the open note); the attachment test and the e2e spec look for the chips.

## Findings

None open. During review, the hide key moved from a fresh editor read to the same `live` state the chip is drawn from, so they can't disagree.

Privacy: removing a chip only changes what the next message sends. Notes already sent stay in the conversation's `sources` and rule, as before, so the Rust layer still checks them on follow-ups.
