**Verdict: approve** (Claude self-review, per the 2026-10-17 working agreement)

Reviewed `git diff main...agent/claude/T-100` in full (20 files, ~1,970 lines added, most of them the new `src/features/dashboard/**` module and its tests).

## What it does

- Every vault has a **Home** dashboard (sidebar House button, `Ctrl+Shift+H`, "Go to Home" on a new tab, command palette). Any folder can get its own dashboard: right-click → **Add dashboard** / **Open dashboard** / **Remove dashboard**. A folder with a dashboard shows a small dashboard button in the file tree.
- Default widgets: **Calendar** (the daily-note month view, reused), **Today's tasks** (overdue, due today, today's daily note; tick off in place), **Day schedule** (timed lines in today's daily note plus timed tasks due today) and **Pinned** links (file/folder cards in a notebook-style grid, picked with the fuzzy picker). A **Recent** widget can also be added.
- **Customize** mode: add any widget, move widgets earlier/later, remove them, rename a Pinned widget, reset to the default layout, and remove a folder's dashboard.
- Layouts live in `.axisnotes/config.json` → `dashboards`, keyed by folder path (`""` = Home). There is no new file format. Removing a dashboard or trashing its folder keeps the layout (`enabled: false`). Renames re-key dashboards and update pinned links. Missing links show as "Missing" cards that can be relinked or removed.
- Dashboards open in tabs (`view: "dashboard"`, path = folder) and are restored with the vault's tabs.

## Findings (most severe first)

1. **Fixed during review:** `src/features/dashboard/dashboardModel.ts` `defaultDashboard`. An unsaved Home dashboard generated new widget IDs on every read, so the first edit to a default widget (for example pinning a link) found no matching widget and was silently dropped. The default widgets now have fixed IDs (`default-<type>`). Covered by a model test and the "pins a file" component test, which caught it.
2. **Fixed during review:** `src/app/store.ts` restored-tab pruning. It kept only file paths, so a restored dashboard tab (a folder path) would have been reset to an empty tab on every vault open. It now keeps folders and `""` too.
3. **Fixed during review:** `withTabs` mirrored a dashboard's folder path into `activePath`, which panels treat as the open note. It is now null while a dashboard shows.
4. **Minor, accepted:** `src/features/filetree/FileTree.tsx` dashboard badge. It is a clickable `<span>` inside the tree row, like the existing chevron, so it isn't a separate keyboard stop. The context menu ("Open dashboard") gives keyboard and screen-reader access, and the row's name includes ", has a dashboard".
5. **Minor, accepted:** "today" is worked out on each render. A dashboard left open across midnight updates on its next render (any index change, tab switch or interaction), not exactly at midnight.

No new dependencies. The dashboard view is a lazy chunk (12.6 kB JS, 5.2 kB CSS) and loads only when a dashboard opens. Task and daily-note reads run only while a tasks or schedule widget is on the dashboard. Ticking a task reuses the Tasks view's revision-checked edit, now shared as `src/features/tasks/toggleTask.ts`.
