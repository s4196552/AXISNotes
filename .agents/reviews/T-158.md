# Review: T-158 Review fixes for T-155–T-157

**Verdict: approve**

Fixes the findings of the `/code-review high` run over `origin/main...HEAD` (T-155 back/forward buttons, T-156 Obsidian list and heading layout, T-157 Obsidian callouts).

## What changed

- `src/features/editor/headingSections.ts`: the shared, cached outline now also lists every callout and toggle (`calloutBlocks`). Each one runs from its title through the quoted lines after it, up to the next callout's title or an unquoted line, outside fenced code. `CALLOUT_HEAD` moved here from obsidianSyntax.ts.
- `src/features/editor/toggles.ts`:
  - `findToggles` reads that outline. A plain toggle list's inside now ends at the next callout's title, as obsidianSyntax.ts already drew it. Before, a callout straight after a toggle list was treated as the list's inside: it took the toggle's indent and vanished when the list was closed.
  - Only a toggle's own quoted lines get `cm-toggle-body`/`cm-toggle-section` (new `quoteTo`). Callouts and plain quotes further down a toggle heading's section draw as they would anywhere else. Before, the section's `padding-left: 0 !important` and text colour beat the callout box, which lost its 24px padding and coloured title.
  - A foldable callout's chevron also shows when the editor is unfocused.
- `src/features/editor/obsidianSyntax.ts`: callouts come from the shared outline, so there are no separate scans and the outline is cached per document. Only the visible lines of a long callout are decorated. The raw `[!type]` shows only while the editor has focus, like the rest of the live preview; before, a blurred editor with the cursor on a callout title showed half-raw Markdown.
- `src/features/editor/editor.css`: Lined, Cornell, Math Grid and Dotted pages set `--list-spacing: 0`, so list items stay on the 26px paper lines. Headings were already off that grid before T-156 and are unchanged.
- `src/styles/theme.css`: `--list-marker` and `--indent-guide` moved to the block shared with `[data-theme-preview]`, so a Settings theme tile computes them from its own colours.
- `e2e/specs/heading-folding.e2e.ts`: an open heading's arrow is transparent until its line is hovered, so the spec moves the pointer onto the arrow and waits for it to show before clicking.
- `src/features/tabs/NavButtons.tsx`: `allCommands()` once per render rather than once per button.

## Findings

No blocking findings.

1. Not changed: the review suggested `.cm-lp-li > *` instead of `.cm-lp-li *` for the text-indent reset. That would let an inline-block nested inside a mark span (for example a widget inside a link) inherit the list's negative indent, so the descendant selector stays.
2. Note: the e2e spec change was not run locally (WDIO needs the Tauri build). It uses standard WebdriverIO `moveTo` and `getCSSProperty`.
3. Note: with the machine under heavy load, one default `pnpm test` run (6+ minutes) timed out in four unrelated files: `mermaid.test.ts` (invalid-code graphic), `code.test.ts` (python highlighting), `media.test.tsx` (video and audio) and `noteTitle.test.tsx` (hidden heading). All four files passed alone (45 tests), and the whole suite passed with four workers.
