# T-266 review: writing sits on the paper; graph paper and Cornell layout

**Verdict:** approve (Claude, self-verified under the 2026-11-10 rule)

## What the human asked

"Fix the layouts so that the lines are written appropriately on where they should be
regarding the layout. Also add graph paper, and Cornell unless already made."

Graph paper (`axis-style: math-grid`) and Cornell already existed. The problem was that
text drifted off the paper: rules were drawn every 26px from an offset of 8px, while
headings (heading gap, own line heights), callouts (12px and font-size paddings), code
blocks (6px paddings, a 32px header row, a 19.5px hidden fence), the properties chip and
tables or math (margins and arbitrary heights) were not whole rows. Measured before the
fix: offsets of 2–23px after the first few blocks. Cornell text also ran straight
through the red cue margin.

## What changed

- `editor.css`: a shared `.page-paper` class (`--paper-row` 26px). Every text line is
  `line-height: var(--paper-row)` with no vertical padding or min-height (no heading gap,
  flat callout and code paddings). CodeMirror's widget buffers are top-aligned so a
  heading's large font doesn't stretch its line to 28px. The hidden closing code fence takes
  no row. Block widgets lose their vertical margins and the properties chip becomes a 26px
  block. The paper is drawn from the content box (`background-origin: content-box`), so
  row 1 starts at the text.
  - Lined: a rule under each row.
  - Graph paper: one square per row, plus a stronger line every five squares. Text starts
    on a vertical line.
  - Dotted: dots at the grid crossings, between rows rather than behind letters.
  - Cornell: lined, with a red cue margin at 10× the note font size (150px at 15px) that
    stops at the Summary heading, and a red rule across the page there.
- `paperLayout.ts` (new):
  - `cornellZones`: a state field reads `axis-style` from the frontmatter. On Cornell pages
    it decorates each line as cue / notes / summary. The Cues section and other headings
    among the notes go in the cue column (as side cues); notes go right of the margin;
    Summary and below span the page. Headings inside fenced code are text. Without
    sections, all writing is in the notes column.
  - `paperRhythm`: a measure-phase view plugin that pads block widgets (tables, block math,
    embeds) with `padding-bottom`, and tall inline widgets in a line (an image in a list
    item) with `margin-bottom`, up to the next row boundary. Padding is used for blocks
    because CodeMirror leaves margins out of its height map, which made widgets drift once
    they scrolled out of view (seen as a uniform 3.6px offset before switching).
    Widget DOM is ignored by CodeMirror's mutation observer, so these writes don't fight
    re-rendering. Lines are never mutated. It is capped at 4 changing passes per
    doc/viewport change, and it clears its padding when the page goes back to Plain. It
    also sets `--cornell-end` on the scroller from the Summary heading's height-map top,
    so this works when the heading is off screen.
- `headingIndicator.ts`: measures the text column from the content box instead of the
  first `.cm-line`, which a Cornell page narrows. Without this the rail jumped to mid-page.
- `Editor.tsx`: adds `page-paper` for non-plain styles and registers `paperLayout`.
- "Math grid" is now called "Graph paper" in the command menu and the template list. The
  stored value is still `math-grid`, so existing notes are unchanged.

## Findings

None blocking. Known limits:

- Cornell in linear Markdown: a Cues *section* sits above the notes, in the left column,
  not beside them. Side-by-side cues come from headings among the notes, which sit in the
  cue column at the start of their notes.
- Widgets whose height changes after they render (KaTeX, images loading) are off by up to a
  row until the next measure, usually the next frame.
- A widget in the notes column is moved right only when the line just before it is a notes
  line (CSS sibling rule).
