## What it adds

- **Ribbon:** a column of buttons along the left panel's edge (`src/features/ribbon/`): Home,
  New note, Today's daily note, Search, Graph view, Tasks, Time report, Quick switcher and
  Command palette, then plugins' buttons. With it on, the four view buttons above the panel
  move into it; turning it off (Settings → Appearance → **Ribbon**) puts them back.
- **Reordering:** drag a button (pointer events, like the app's tabs and dashboard, because
  the desktop webview swallows HTML drag and drop), or Alt+↑/↓ on a focused button (↑/↓ move
  focus; the ribbon is one tab stop). The Ribbon tab lists the buttons to drag, move with
  arrow buttons or hide, with Reset.
- **Plugins:** `registerRibbonItem({ id, label, Icon, source, run, available })` in
  `ribbon/registry.ts`. AXIS Hub adds “AXIS Hub” this way (`src/features/hub/ribbon.ts`),
  shown only while the Hub plugin is on (Settings → Plugins), like its sidebar tab; Settings
  marks it “added by AXIS Hub”. Order and hidden buttons are saved per vault by id
  (`ribbon: { enabled, order, hidden }`), so a plugin's button keeps its place while the
  plugin is off; new buttons appear after AXISNotes' own.

## Findings

Fixed during review:

- Drag and drop was first written with HTML5 drag events, which never fire in the desktop
  app (the webview takes every drag; `usePointerDrag` explains why). Rewritten on
  `usePointerDrag`; verified with a real pointer drag in the preview.
- A plugin registered before the built-ins came first; unsaved buttons now list AXISNotes'
  own first.
- `registry.ts` was named `ribbon.ts`, which clashed with `Ribbon.tsx` on Windows' case-
  insensitive file system.
- With the ribbon off, the new `.sidebar-main` wrapper had no flex layout, so the panel body
  would not have filled the height; it now always has it.
