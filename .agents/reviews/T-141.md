### Security checklist

- **Credentials never reach the webview.** IPC exposes only `hasKey` (connected) and `account` (email). The new commands return `()` or static error strings. No token is logged; token/HTTP errors are fixed messages and do not echo response bodies. Tested by `plan_settings_expose_no_tokens_and_model_failure_has_no_api_catalog`.
- **Storage.** The OS keychain via the existing `KeyStore`, in base64 chunks of ≤800 characters under a per-save random generation, with the manifest written last and old chunks removed afterwards (`subscription.rs:183-217`). Provider IDs starting with `chatgpt-session:` are rejected case-insensitively (`service.rs:190-196`), so an API-key provider cannot be pointed at the plan's credential entries and send them to a custom endpoint. `set_key`/`delete_key` refuse plan providers.
- **OAuth flow.** Fresh 256-bit `state`, `nonce` and PKCE verifier per attempt (S256). The listener is bound to `127.0.0.1:0`, accepts GET only, rejects requests with an `Origin` header, duplicate parameters, a wrong path or a wrong state, and expires after 180 s. Errors are checked after the state check. The issued client ID is required on first registration, never saved as `dynamic_agent_client`, and must match on reauthorisation.
- **ID token.** RS256 only, `kid` lookup in OpenAI's JWKS, 2048–8192-bit RSA, `iss`, `aud`/`azp` (multi-audience), `exp`, `iat`, `nbf`, non-empty `sub` and the nonce (sign-in) are checked. The account subject is bound: a different account on re-sign-in or refresh is rejected. Tampered-payload and wrong-audience/nonce/time cases are tested.
- **Scope.** `resource.invoke` and `chatgpt.tokens.use.direct` are required before a record counts as connected (`permitted`); a refresh without `scope` keeps the previously granted scopes, as RFC 6749 allows.
- **Refresh can't race.** An async mutex serialises refreshes in one process, and an OS file lock (`fs2`) covers separate AXISNotes processes. The record is re-read under both locks, so a token rotated by another process is used rather than replayed. The epoch fence (`commit`) discards late results after cancel, disconnect, disable or removal.
- **Fails closed.** Unreadable or partial keychain records, a missing expiry, the wrong token type, unknown signing keys and an incomplete stream are all errors. Disconnect clears tokens locally before attempting revocation, and the revocation endpoint must be same-origin as the issuer.
- **No paid fallback.** When the selected or first provider is a plan provider, the candidate chain is reduced to plan providers only (`service.rs:390-404`). Tested for 429/quota, disconnected and disabled cases with an API-key provider in the fallback list (no second request is made). The browser preview backend refuses rather than fabricating a connection.
- **Privacy rules.** Plan providers are never `is_local`, so "AI: local models only" and "AI: never" folders are refused before any request (tested). The input-token cap still applies (`service.rs:551`).
- **Endpoint pinned.** A plan provider cannot save a `baseUrl`, and the adapter ignores it anyway (`adapter.rs:34`). Changing an existing provider's kind is refused.

## Findings (none blocking; most severe first)

1. **Low — spurious "another window" error under concurrent use.** `subscription.rs:420`: `access_token` takes the non-blocking cross-process file lock on every request, not only when a refresh is needed. With two AXISNotes processes open (the app is not single-instance), a request made while the other process holds the lock (during its own request, refresh or sign-in commit) fails at once with "Another AXISNotes window is updating…" instead of waiting. This is safe (it fails closed) but can annoy. Suggested follow-up: return a fresh token without the file lock and lock only to refresh, or retry the lock for a few seconds.
2. **Low — orphaned client registration after a failed first sign-in.** `subscription.rs:375-415`: on first registration the issued `oaiapp_…` client ID is only saved after the code exchange and ID-token checks succeed. If those fail (network, clock skew), the next attempt registers again with `dynamic_agent_client`, leaving an unused registration in the user's ChatGPT settings. Harmless; the user can remove it there.
3. **Low — vision capability for plan models uses name heuristics.** `service.rs:427-441` decides image support with `registry.enrich`, which has no ChatGPT entries and falls back to the model-name hint. The account catalogue's `supports_image_input` (parsed in `codec/chatgpt.rs`) is not consulted, so handwriting may be offered or skipped wrongly for some plan models.
4. **Info — `fs2` is unmaintained (last release 2018).** std's `File::try_lock` (stable since Rust 1.89) could replace it later.
5. **Info — the "ChatGPT plan" option is listed first in Provider type,** but the default selection is still OpenAI, so nothing changes silently.
