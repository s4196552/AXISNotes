# T-154 review: images in notes are selected, opened, dragged and resized on the image

**Verdict: approve** (Claude self-review under the 2026-10-17 agreement)

## What changed

- `src/features/editor/imageEditor.ts`: the always-visible image toolbar ("Edit image" / "Edit link") is gone. On the image itself:
  - **One click** selects it: a solid accent outline, the text cursor hides, the cursor stays where it was and the embed's text is not revealed. The selection lives in a CodeMirror state field (`imageSelection`). Edits move it with the image, and moving the cursor, clicking text or pressing any other key clears it. While an image is selected, Delete/Backspace removes it, Enter shows its embed text, Ctrl+C / Ctrl+X copy or cut the embed line (which pastes back as the image), and Escape lets go.
  - **Double-click** opens it: `openFile(path)` (the app's image view, the same path as the file tree; Ctrl+double-click opens a new tab). A web image opens like table links (`target=_blank`).
  - **Press and drag** puts the embed on another line, using pointer events rather than HTML drag and drop (the WebView2 issue the file tree also works around). A small floating copy of the image follows the pointer, an accent line shows where it will land, and the note scrolls near its top or bottom edge. The default is **move**; holding **Ctrl or Alt** (Cmd on macOS) when releasing **copies** it instead. Dropping where it already is changes nothing; Escape cancels. A moved image takes one of the blank lines around it along, and gets a blank line next to any text it lands beside, so it stays its own paragraph and no gaps build up. Moving is a single undoable change (`relocateEmbed`).
  - **Hover** (my reading of the unfinished "When hovering over the image adds"): a faint accent outline appears and the six resize handles show.
  - **Resize**: handles on the four corners and the left and right sides. Dragging one previews live with a "W × H" badge, and on release writes Obsidian's `|width`. An embed that already had `|WxH` keeps its proportions, so both numbers are scaled. Width is clamped to 24 px and to the width of the text column. Escape cancels. The image stays selected after resizing.
  - **Right-click menu** (`filetree-menu` styling, Lucide icons) keeps every action the toolbar offered: Open image, Edit link, Copy embed, **Crop and exact size…** (the existing size/crop form, unchanged and now opened from here), Reset size and crop (shown when the image has a size or crop), and Delete image. In read-only mode it has only Open / Edit link / Copy embed, and there are no handles and no dragging.
- `src/features/editor/embeds.ts`: passes `open` and `editLink` to `imageTools`, updates the tooltip, and adds `imageSelecting` to `embeds()`.
- `src/features/editor/editor.css`: styles for hover/selection outlines, handles, size badge, drop line, drag ghost and the cursors used while dragging.

## Findings (most severe first)

1. Minor gap: keyboard-only access to the crop/size form. The old toolbar buttons could be reached with Tab. The form now opens from the right-click menu, and the menu key fires on the editor rather than on the image. Keyboard users can still edit `|width` in the embed text (Enter on a selected image, or put the cursor on its line). Not blocking: the user asked for the mini GUI to be removed.
2. Minor: on touch screens, a swipe that starts on an image starts an image drag instead of scrolling. AXISNotes targets desktop first; worth revisiting with the mobile clients.
3. Note: Ctrl/Alt copy is read when the pointer is released and while modifier keys change during the drag. Releasing one of two held modifiers turns copy off until the next key or pointer move. This is cosmetic.
