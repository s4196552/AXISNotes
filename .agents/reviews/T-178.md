# T-178 review: App colours (sidebar and note-area colours, 12 presets)

**Verdict: approve** (Claude self-review, 2026-11-06)

## What changed

- `src/app/appColors.ts` (new):
  - the 12 presets;
  - hex parsing, WCAG contrast, automatic text and muted text with a 3.5:1 floor;
  - `appColorsCss`, which builds the stylesheet, and `applyAppColors`, which puts it in a `<style id="axis-app-colors">` last in `<head>`.
- `src/app/config.ts`: the `AppColors` type, `NO_APP_COLORS`, and `appearance.appColors` in the defaults. `mergeConfig` already drops values of the wrong type.
- `src/App.tsx`: applies the colours when the theme, the colours or the heading-colour preset change.
- `src/features/settings/AppColorPicker.tsx` (new), `Settings.tsx` and `settings.css`: the App colours area under Theme. It has:
  - split-swatch presets;
  - Sidebar background, Sidebar text, Main background and Main text pickers, each with "Theme" or "Auto" when unset and a Reset button;
  - a contrast warning;
  - a "Use theme colours" button.
- `docs/DECISIONS.md`: entry for T-178.

## Findings

1. Fixed during review, `src/app/appColors.ts` (surface `color` and `background`): `.content` has no background of its own (the body backdrop shows through), and `color` is inherited already resolved. The first version changed the tokens but not what was painted. Each surface rule now sets `background: var(--bg)` (main) and `color: var(--fg)`.
2. Fixed during review, `src/app/appColors.ts` (`OWN_HEADINGS`): the note's H1 kept the theme's heading colour and was nearly invisible on Cream. theme.css declares `--heading-N: var(--heading)` on `:root`, so the value is fixed there. Surfaces now re-point `--heading-1`…`6` at their own `--heading`. They skip this while a heading-colour preset is chosen, so that preset still wins. A test covers both cases.
3. Fixed during review, `src/app/appColors.ts` (`mutedText`): muted text at a flat 35% fade gave about 2.7:1 on Cream. It now fades no further than 3.5:1, and a test checks every preset surface.
4. Preset 3 (Cream): the suggested sidebar text `#586e75` is 4.39:1 on `#eee8d5`. It is now `#52676e` (4.86:1). The other 23 text colours were already at least 4.5:1, and a test checks all 24.
5. Note: menus and dialogs portalled to `<body>`, such as Settings and the command palette, keep the theme's colours. Only the sidebars, the note area (with its tabs and editor tooltips) and the status bar change. This is intended: those are the surfaces the user asked about.
6. Note: Translucent ignores App colours, and the Settings hint says so.
