# T-200 review: Ctrl+Z / Ctrl+Y in the file tree

**Verdict: approve**

Reviewer: Claude (self-review). I read the full diff of `agent/claude/T-200` against `main`.

## Findings (most severe first)

1. **Resolved: undo must never lose writing.**
   - Undoing a new note or pasted copy moves it to the trash only if its text matches what it was created with (`created()` in `src/features/filetree/undo.ts`).
   - A new folder goes only while it's empty.
   - Otherwise the step is refused with a message, and nothing changes.
2. **Resolved: a partial restore.** `Vault::restore_from_trash` (`src-tauri/src/vault/mod.rs`) checks that every path is in the trash and its place is free before restoring any. It returns NotFound or AlreadyExists and changes nothing.
3. **Resolved:** a regex in the step labels lost its backslash during an edit. The labels now strip only a real `.md` (`undo.ts`, `base`).
4. **Accepted: limits.**
   - On macOS the `trash` crate can't restore, so undoing a delete there shows a message.
   - Command-palette renames aren't recorded.
   - The history is in memory only.
   - All of these are in the handoff.
5. **Note:** the window-level Ctrl+Z skips text boxes, the editor, iframes and any open dialog. It never runs when the tree's own handler already took the key (`defaultPrevented`).
