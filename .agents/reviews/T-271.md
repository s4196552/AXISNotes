# T-271 review: emphasis colours everywhere note text is shown

**Verdict:** approve (Claude, self-verified under the 2026-11-10 rule)

## What the human asked

"Add optional and customizable bold, italic, and strikethrough color". The colours
already existed (T-260, Settings → Appearance → Theme & layout) but applied only in notes,
note embeds, AI answers and table cells. The human picked "Colour them everywhere".

## Change

- `src/features/tasks/InlineText.tsx`: the shared renderer for note text outside the
  editor now gives its `<strong>`, `<em>` and `<s>` the classes `inline-bold`,
  `inline-italic` and `inline-strike`. It draws the task view, the dashboard's task and
  list widgets, and the study cards (flash cards, quiz, mind map).
- `src/styles/app.css`: those classes use `var(--text-bold|italic|strike, inherit)`, the
  same variables `applyTextColors` sets for notes. When a colour is off, the text
  inherits.
- App labels that use `<strong>` (settings text, dialogs) are untouched: only `InlineText`
  output gets the classes.

## Findings

None open. Canvas note cards and note embeds already use the editor's `cm-lp-*` classes, so
they were already coloured.

## Tests

- New test in `textColors.test.tsx`: the CSS rules, the three views using `InlineText`, and
  the rendered classes. The colour tests, tasks, dashboard, study blocks and openClick give
  6 files and 72 tests, all passing.
- The full `pnpm lint`, `pnpm typecheck` and `pnpm test` results are under "Full checks"
  below.

## Checked in the preview

Checked in `pnpm exec vite` (dark theme), with the colours turned on:
- A task's bold, italic and struck words showed in `rgb(255, 77, 109)`,
  `rgb(45, 212, 191)` and `rgb(250, 204, 21)`.
- A flash card's bold matched the note's bold.

With the colours turned off, `--text-bold` was cleared and the task text went back to the
row's own colour.
