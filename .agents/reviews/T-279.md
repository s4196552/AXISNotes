## Findings

1. **By design: some content goes stale until the next structural change** (`src/features/panels/SearchPanel.tsx:50`, `src/features/panels/BacklinksPanel.tsx:31`).
   - Search results and unlinked mentions re-query on `structureVersion` or a query change, not on every save.
   - A word typed into a note shows up in an existing search only after the next structural change or query edit.
   - The done-when for this task requires exactly this: no `search` or mention calls while typing plain text. The handoff records it.
2. **By design: tasks are compared with their lines** (`src-tauri/src/index/mod.rs`, `structure_sig`). The tasks view edits by line number, so Enter above a task counts as a structure change. A word typed within a line does not.
3. **Migration** (`src-tauri/src/index/mod.rs`, `Index::init`).
   - `notes.sig` is added with `ALTER TABLE`, not a schema bump, so existing vaults are not re-indexed.
   - A NULL `sig` counts as changed once per note. Covered by `notes_indexed_before_signatures_count_as_changed_once`.
4. **Ordering** (`src-tauri/src/commands.rs`). Making the file commands async allows concurrent IPC calls. `rename_entry` was already async. Every caller awaits its write, the index sits behind its mutex, and self-write marks are per path. No ordering the UI relied on was found.
5. **Fixed during verification:**
   - Python edits on Windows had written CRLF line endings; they were normalised to LF.
   - A heredoc turned `\t` in a regex into a literal tab; corrected.
   - Rustfmt and Prettier reformatted long lines.
   - The first version of the typing test set `activePath` together with `vault`, and restoring the vault's tabs cleared it. The test now sets `activePath` after `refreshTree`.
