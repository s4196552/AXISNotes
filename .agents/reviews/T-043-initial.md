## Findings

- P1 — docs/S2_FOUNDATION.md:107: An unpaired app cannot send the required signed status request, and bootstrap credentials are accepted only for pairing. When Connect is already running (especially after restore/revocation), the proposed fallback starts a process that exits 3, then waits for a new instance that never arrives. Specify first pairing/re-pairing against the existing manifest and distinguish authentication failure from dead service; include first-install and restore acceptance cases.
- P1 — docs/S2_FOUNDATION.md:437: The confirmed native widening flow can be bypassed by existing generic write_file/config writers: the protected-path list at line 319 excludes config.json, while legacy ai.folders still contributes authoritative permissions. Specify native validation/interception of AI-related config deltas and migrate the existing folder-rule writers without breaking unrelated settings. Add rejection tests for generic removal/widening of legacy never/local rules.
- P1 — docs/S2_FOUNDATION.md:486: Checking a destination's current policy only at apply does not retain derivative restrictions. An AI-generated medical summary can be applied to another local-only note, then that destination widened and sent to cloud without re-resolving the medical source. Retain conservative per-resource provenance in the authoritative sidecar and recheck current ancestor policies, or defer derivative apply until it can be enforced. Span-level Markdown provenance can remain deferred. Add the destination-widening/source-policy-change regression.
- P2 — docs/S2_FOUNDATION.md:144: The claim that secrets never cross the wire contradicts the plaintext clientSecret returned in the signed HTTP pairing response at line 176 (also SUITE_PROTOCOL.md:224). HMAC gives authenticity, not confidentiality. Make the pairing transport/derivation and claimed protection consistent; do not describe signing alone as hiding response credentials.
- P2 — docs/S2_FOUNDATION.md:346: Guaranteeing a fresh identity for every new file at an old path is unsupported by the specified path/fingerprint map. Delete-and-recreate while Notes is closed is indistinguishable from an ordinary edit without further identity evidence. Define the evidence and ambiguity rule for offline replacement and test it; do not silently reuse an old ID where continuity is uncertain.
