## Findings (most severe first)

1. Resolved during the build: rule bypass by spelling. On Windows a request for `medical/scan.md` or `MEDICA~1/scan.md` opens the file under `Medical/`, but the AI rules are keyed by the exact path. `src-tauri/src/mcp/access.rs:155` (`real_path`) now respells every segment from the folder listing. It refuses a segment the listing doesn't contain when the file system still opens it (8.3 names). It also rejects `..`, `:` streams and trailing dots or spaces. Rules are matched exactly and also ignoring case, and the stricter rule wins (`access.rs:128`). Tests: `folders_kept_from_cloud_ai_are_never_shown`, `short_8_3_names_cannot_reach_a_hidden_folder`.
2. Resolved: fail-open config. `ai::privacy::rules` treats an unreadable config as "no rules". The connector uses its own strict loader instead (`access.rs:42`). Invalid JSON or a non-object rules map refuses all access, and an unknown rule value counts as "never". Test: `nothing_is_shared_until_access_is_on`.
3. Accepted (documented in the handoff and DECISIONS): an AXISNotes update closes running connectors, so Claude must be restarted afterwards.
4. Accepted: a daily note created by the connector doesn't get the daily template, which is expanded in the UI. The tool description tells Claude so.
5. Nit, accepted: notes inside symlinked folders follow the app's own link behaviour.
