# T-281 review: unbypassable "local only" AI check

**Verdict: approve.** Claude verified its own work under the 2026-11-10 rule.

## Findings

1. Note (`src-tauri/src/ai/transport.rs`, `remote_redirects`): the remote redirect
   policy has no automated test. reqwest's `Attempt` can't be built outside reqwest, and
   a real test needs a trusted local https server. The closure follows only to an https
   URL with the same host and port as the original, never to a local host, with at most
   5 hops. Everything else stops, and the transport turns the 3xx into a clear error.
   That error path is tested on the local client (`local_endpoints_never_follow_redirects`).
2. Note (`src-tauri/src/ai/settings.rs:69`, `endpoint_problem`): behaviour change. A LAN
   server over plain `http://` can no longer be saved, and one saved by an older version
   is kept visible but refused at send time (`transport.rs`, `check_endpoint`). This is
   what the brief asked for. It is recorded in the handoff and DECISIONS for the lead.
3. Note (`transport.rs`, `check_endpoint`/`redirect_refused`): both errors are
   `AiError::Unavailable`, so the request falls back to the next provider. Fallback
   candidates are filtered by the folder rule first, so a "local only" note still only
   reaches local providers.
4. Nit (`src/lib/aiEndpoint.ts`): the TS mirror is not enforcement. It only drives the
   in-memory backend and the inline message. Rust stays the source of truth.

Checked by hand in the diff: every former bypass now parses to the attacker's host;
`is_local` requires an http(s) scheme and no user info; and `clear_bad_endpoints` still
uses only the address check, so an endpoint is never silently swapped for the default.
The local client cannot reach a non-loopback address. IP hosts must be loopback to be
classed local. Names go through `LoopbackResolver`, and no proxy is used.
