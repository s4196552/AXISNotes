# T-218 — Custom in-app logo and default pack

Implemented in `.worktrees/T-218`, branch `agent/codex/T-218`, based on `1fff0be`. Approved after assigned-agent verification. No merge, release, installation or remote push.

## Behaviour

- Settings → Appearance and Icon & image packs offer **App logo**: AXIS Original, AXIS Risograph, AXIS Neon, Upload custom logo and Restore original logo. The two supplied PNG files are bundled without image transformations; the original SVG remains available.
- The choice is stored per vault in `appearance.logo`. Existing vaults retain the original via the default empty setting. `Logo` applies it to existing logo surfaces (settings About, Welcome and Getting started) and the settings preview. Missing images or invalid/network paths fall back to the original.
- Upload uses the existing native picker/importer and copies into `Attachments/Branding`, preserving originals. Async completion is ignored after settings unmount or a vault change. Import/cancel/save failures are handled by the control; source files are not rewritten.
- The icon picker's Packs tab offers a **Default pack** with all three logo designs, usable for notes/folders via existing `image:` icon values. Known bundled references resolve from a fixed asset table rather than the vault filesystem; reopening the picker returns to Packs. Existing Lucide/emoji/image options and imported packs remain intact. Default assets are not installed into or removed from the user's vault.
- No dependencies, native permissions/commands, models or background tasks were added. Bundled references use stable IDs; custom images remain vault-relative. Disabling or changing a logo does not delete its file.

The optional Windows taskbar question received no reply during implementation. Work follows the stated in-app default: Windows taskbar/window/installed shortcut icons remain outside this feature. No release version has been bumped.
