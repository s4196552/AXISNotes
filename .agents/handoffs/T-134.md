# T-134 — Direct table editing without reformatting

## Built

Click a rendered Markdown table cell, or focus it and press Enter/F2, to edit that cell in place. The other cells remain rendered. The input overlays its existing cell so activation retains the table's columns and footprint. Tab/Shift+Tab moves between cells; Enter/Escape finishes; Shift+Enter inserts a line break. Link clicks retain their navigation behavior. Read-only editors do not expose direct editing.

Cell edits update Markdown immediately through the existing document/save path. They preserve unedited cell contents, padding, separator rows, alignments and optional borders rather than formatting the entire table. Existing bulk editing uses the same source-preserving update. Explicit Format table and structural row/column controls retain their existing behavior. Escaped pipes, code spans and wiki aliases remain intact; new structural pipes and line breaks are escaped. Padded missing cells are materialized when edited. Empty borderless edge cells receive the minimum border needed to remain present, and editing a padded header extends the separator accordingly.

Controller updates retain the active input/caret across typing and undo. Finishing/removing an input is explicit and idempotent: relying on blur alone left an orphan input when focus had already moved, found during the full-suite run and fixed here.

Real per-keystroke desktop typing exposed the existing editor's edge-whitespace normalization removing each space before the next word. The update now compares normalized cell content while retaining the typing draft, and source writes trim only the new content's Markdown edge padding. This preserves word spaces without accumulating padding in the source. A new character-by-character regression covers this for the same controller used by direct and bulk editing.
