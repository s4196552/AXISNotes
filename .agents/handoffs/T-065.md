# T-065 handoff: Command symbols (Ctrl+/, @@, ((, ::, :, $$, {{)

**Built by:** Claude. **Branch:** `agent/claude/T-065` (from `main` at 9a9baaa). **Requested by:** the human. After comparing other apps' symbols, they chose: command menu `Ctrl+/`, mentions/dates/notes `@@`, block search `((`, inline properties `::`, emoji `:`, math `$$`, template variables `{{}}`.

## What was built
- **Command menu, `Ctrl+/`.**
  - `openCommandMenu` sets a `commandMenuAnchor` and starts completion. `slashCompletions` filters on what's typed after the anchor.
  - The anchor clears when the menu closes, the cursor leaves the line, or a command runs.
  - The registry command `command-menu` (default `Ctrl+/`, remappable) opens it in a note, or the palette elsewhere. `Mod-/` is removed from CodeMirror's default keymap.
  - The typed trigger is optional and off by default. `migrateTriggers` moves vaults that saved `/` to "" once.
- **`src/features/editor/triggers.ts`:**
  - `@@`: `mentionCompletions`.
  - `((`: `blockCompletions` and `linkBlock`.
  - `::`: `propertyCompletions`.
  - `{{`: `templateCompletions`.
  - `blockPreview` gives menu text without Markdown marks.
- **`src/features/editor/math.ts`:** `$$…$$` KaTeX rendering (display or inline), and auto-closing `$$`.
- **Rust:**
  - `inline_property` in `index/parse.rs`: inline `key::` lines become note props (frontmatter wins).
  - `Index::property_keys` and the `list_property_keys` command.
  - `SCHEMA_VERSION` 3, so existing indexes rebuild once.
- **IPC:** `Backend.listPropertyKeys` in both backends. The TS `inlineProperties` mirrors the Rust parser for the memory backend.
- **Config:** `quickCommands.{mentionTrigger, blockTrigger, propertyTrigger, templateTrigger, triggerVersion}`. The `slashTrigger` default is now "".
- **Settings → Commands:** fields for every trigger, plus a note on `Ctrl+/` and `$$`.
- **Getting started, the Start here note and examples:** updated from `/` to the new symbols.
- **Theme:** autocomplete menus styled with the theme variables. They were unreadable in dark mode before; this was a pre-existing bug, fixed here because every new feature uses them.
- **Dependency:** `katex` ^0.16.47 (MIT), the same version Mermaid already pulls in, so there's one lazy chunk.

## Known gaps
- `::` suggests keys only, not values.
- `@@` understands fixed phrases ("next friday") and `YYYY-MM-DD`, not free-form dates ("march 3").
- Block search reads up to 12 matching notes per keystroke (fine for the 100 ms search budget; very large vaults show the first 40 blocks).
- Math in embeds and exports renders where the editor renders; there is no separate reading view.

## Codex review round 1: all six findings fixed
1. **Async block link could overwrite newer typing.** For a block in another note, the link (with a pre-made id) is now inserted synchronously. The id is then added to the block on disk, and if that block got a different id meanwhile, the link is updated. If writing fails, the typed `((query` is put back and an error is shown. Test: "keeps what's typed while the id is being added in the other note".
2. **CRLF corrupted existing block ids.** `lib/blocks.ts` `lines()` now drops the `\r`, so ids are found on CRLF lines and new ones go before the `\r\n`. This also fixes `copyBlockLink`, `[[Note#^` completion and embeds on CRLF notes. Test: "handles CRLF line endings…".
3. **A stale position was reused after a fresh read.** `relocateBlock` finds the block again by its text (nearest its old place) in the fresh file, for both the same-note and other-note paths. Test: "finds the block again if the note changed after it was listed".
4. **Folder was lost when names clash.** `linkTargetFor` writes the path (`[[Archive/Biology]]`) when two notes share a name, for both `((` and `@@` notes. The `((` menu detail shows the note's path. Test: "writes the path when two notes share a name".
5. **Date links ignored the daily folder.**
   - `@@` dates now write `[[Daily/2026-10-08|2026-10-08]]`; with no daily folder they write `[[2026-10-08]]`.
   - Following a link to a daily note that doesn't exist (`followLink` / `dailyDateOf` in `commands/actions.ts`, used by the editor) creates it in the daily folder from the daily template, like the calendar does.
   - Test: "opens a missing daily note from a link in the daily folder…".
6. **Ownership.** The task-board row now lists every file area this task touches, beyond the original three editor modules: Editor and registry wiring, config migration, IPC, `lib/blocks.ts` (the CRLF fix), onboarding copy and E2E. Each is needed for the feature or for a review fix.

Also found by the new tests: the insert helper treated `|` as a cursor marker and dropped the `|` from link aliases. It now takes an explicit cursor offset.
