# T-242 handoff — AI privacy rules fail closed

## What was built

- `privacy::read_config` reads the vault config: none yet is `Ok(None)`; an I/O
  error or invalid JSON is an error.
- `privacy::rules_from` / `rules`: an unknown or non-text folder value counts as
  never (values are read ignoring case, so `"Never"` is never), and `ai.folders`
  of the wrong shape is an error. Keys that differ only by slashes keep the
  stricter rule.
- `privacy::FolderRules`: rules matched as written and ignoring case, stricter
  wins. Used by the AI service, `vault_passages` and the Claude connector (which
  had its own copy of this logic).
- `privacy::allowlists_from` (fails closed like the rules) and `allowlists_for`
  (nearest list as written plus nearest ignoring case; a model must be on each).
- `AiService::policy` replaces `rule` + `allowlists`. A config problem, or a note
  that exists but can't be read to check its mark, returns `Blocked`; `run` logs
  it as a blocked request before contacting any provider.

## Known gaps

- The frontend's own `ruleForPath` (used to choose which notes to offer) is
  still exact-case; Rust enforcement is what changed. A skill run on picked
  files still ignores notes' own marks when choosing notes (separate finding).
- The Claude connector now reads `"Any"`/`"LOCAL"` ignoring case (previously any
  non-lowercase value was never). This is the user's stated intent, so it's kept.
