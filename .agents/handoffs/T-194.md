# Handoff: T-194, copy, cut and paste in the file tree

## What was built

- **Copy / Cut / Paste for files and folders in the sidebar file tree.**
  - Ctrl+C, Ctrl+X and Ctrl+V (Cmd on macOS) while the tree has focus. They act on the picked rows (Shift+click / Shift+arrows) or the selected row. Paste goes into the selected folder, or the selected file's folder, or the top level when nothing is selected.
  - Context menu: Copy and Cut on every row; "Copy N items" and "Cut N items" on a multi-selection; "Paste here" (or "Paste N items here") on any folder, file or the empty area while something waits to be pasted.
  - A copy keeps its name when that's free in the target folder, otherwise it becomes `Name copy`, `Name copy 2`, … (before the extension; a folder name is never split at a dot). Nothing is ever overwritten.
  - Cut rows are dimmed until pasted. Pasting a cut moves the items (through the existing rename/move path, so wikilinks to them are rewritten and open tabs follow). A cut item that can't move (name clash, into itself) stays cut, to paste somewhere else. A copy can be pasted many times.
  - A folder can't be pasted into itself or below itself. Items deleted since they were copied are skipped; if none are left, an error says so.
  - The tree's clipboard belongs to one vault: switching vaults hides it, and it is not the system clipboard.
- **Rust `copy_entry(from, dir)`** (`Vault::copy_entry` + Tauri command): copies a file or a whole folder, picks the free name, refuses a folder into itself, skips folder links inside a copied folder (so a link loop can't make the copy endless), removes only its own half-made copy on failure, and reindexes the copy.

## How to test

- `pnpm vitest run src/features/filetree` (6 new tests), `cargo test --lib vault::` (`copies_files_and_folders_under_free_names`).
- In the app: right-click a note → Copy, select a folder, Ctrl+V; paste again to get "… copy"; Shift-select two notes, Ctrl+X, right-click a folder → Paste 2 items here.

## Known gaps

- Copies don't take the original's custom icon or colours (Explorer behaviour); copied notes keep their block IDs, so a block ID can exist in two notes, as after any manual duplicate.
- Files copied in Windows Explorer can't be pasted into the tree (the webview can't read the OS file clipboard); dropping files in still works.
- No undo for a paste (as for other file operations); a copy can be deleted to the trash.
