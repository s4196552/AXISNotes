# T-131 — Native Ctrl+/ command-menu crash

## Evidence and reproduction

The human clarified Ctrl+/ as the trigger. Windows Application Error reports showed native axisnotes.exe fail-fast exits (0xc0000409) in 0.3.24, 0.3.25 and 0.3.26. Read-only analysis of the latest user dump using the matching local release PDB and PE disassembly resolved the original panic to apply_to_index's poisoned index.lock().unwrap() branch (0.3.26 return offset 0x1c86d8). This is a native autosave/index failure, not a JavaScript palette-render error.

Two new Rust Unicode tests failed before the fix: extension/name checks sliced inside UTF-8 characters. Two poisoned-index tests also failed on unwrap. The old real Windows app opened Ctrl+/ on an ordinary dirty ASCII note, but creating the Unicode fixture 😀é.md aborted the process at index/mod.rs:138 with a char-boundary panic followed by a non-unwinding COM callback panic. The remaining native test then failed because the window had closed. This proves a deterministic index-panic cause; the user's secondary poisoned-lock abort is prevented regardless of which earlier cache operation was interrupted. User note contents were not read or modified for reproduction.

## Fix

- UTF-8-safe suffix checks replace unchecked slicing in strip_md and has_ext. Existing extension/case semantics remain; emoji/non-ASCII note/link names and non-indexed files no longer panic during classification, parsing or updates.
- All shared-index access paths use a fallible lock helper. Read/query and rename operations return an existing Io error with a reopen instruction when the cache is poisoned. Post-write cache updates log and skip that interrupted cache, preserving the successful source-file save instead of panicking across native IPC.
- Reopening replaces the index connection before clearing poison, then uses the existing background sync. A connection interrupted by a panic is not silently reused.
- Five Rust regressions cover Unicode names, mixed-file indexing/updates, saves with an unavailable cache, recoverable query errors, and index replacement/recovery.
- New native command-menu coverage opens Ctrl+/ while dirty, applies heading/task commands, creates/opens/saves a Unicode note with a Unicode link, handles a Unicode attachment watcher event, repeats the menu, and verifies subsequent saves and Ctrl+P. The test runner accepts AXIS_E2E_APP so the exact optimized release executable can be verified before publication.
- Version manifests advance to 0.3.27. No command shortcut behavior, source file formats, dependencies, AI policy, theme styles, namespaces or user settings changed.
