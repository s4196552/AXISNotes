# T-282 handoff: signed updates and publish guards

## What was built

- **Signed manifest.** `publish-update.ps1` now writes `latest.json.sig` next to `latest.json`. It holds the base64 Ed25519 signature of the manifest's exact bytes, so the version, file name and SHA-256 are covered together.
  - The app embeds the public key as `UPDATE_PUBLIC_KEY` in `src-tauri/src/updates.rs`. `updates::check` reads the manifest bytes once, verifies them and parses the same bytes. `prepare` does this again before it copies and hashes the installer.
  - `Available` gains `verified` and `unverifiedReason`.
- **Unverified updates** (no signature, garbled signature, wrong key, any edit after signing) are still offered. The banner and Settings → Updates show "Not verified: <reason> Install it only if you trust whoever can change the updates folder." and the button reads "Install anyway" or "Install X anyway".
  - The launch check never installs them, even with automatic install on.
  - `updates_install` takes `allowUnverified`, which defaults to false. Rust refuses an unverified manifest without it.
  - The UI sends `true` only for an update it showed as unverified. If a verified offer has turned unverified by the time of the click, Rust refuses it.
- **Defaults:** check on launch and automatic install stay on. Automatic install now applies to verified updates only.
- **`scripts/update-signing.mjs`:** `keygen`, `pubkey`, `sign` and `verify`, using Node's built-in `crypto`. There are no new dependencies; Rust verifies with `ring`, which was already a dependency.
- **`scripts/publish-update.ps1`:**
  - `-NewKey` creates the key pair and restricts the key's ACL.
  - `-DryRun` runs the guards and prints the plan.
  - It refuses on a dirty tree (untracked files are ignored), a branch other than `main`, an existing tag `vX.Y.Z`, a version that isn't newer than `package.json`, a missing key, or a key that doesn't match the embedded public key. All problems are listed together.
  - It runs `pnpm lint`, `pnpm typecheck` and `pnpm test`. `-SkipChecks` skips them; the skip is recorded in the tag and in `publish-log.txt`.
  - It builds the installer. If the build fails, it undoes the version change.
  - `-CertThumbprint` signs the installer with signtool, timestamped (`-TimestampUrl`), before hashing. Without it the script warns.
  - It writes and signs the manifest, verifies the signature, then swaps the signature and the manifest in.
  - It commits `Release X.Y.Z: version bump`, adding `-CommitTrailer` if given, and creates the annotated tag `vX.Y.Z`. Nothing is pushed.
  - `-Keep N` (default 10) deletes older `AXISNotes_*_x64-setup.exe` files.
  - It appends a line to `publish-log.txt` in the updates folder.

## How to test

- `cargo test updates` runs 19 updater tests, including valid, tampered version, tampered hash, missing signature, garbled signature, wrong or empty key, a signature made by the Node script, and refusing an unverified install unless asked.
- `npx vitest run src/features/updates`.
- Run `powershell -File scripts/publish-update.ps1 -Version 0.3.112 -DryRun` in the primary checkout on `main`. With a clean tree and the key in place it prints the plan; otherwise it lists what blocks the publish.

## Known gaps

- **The protection starts with the first signed release.** Installed 0.3.111 and earlier don't check signatures and still auto-install whatever the folder offers. Until the human has 0.3.112, the old risk remains.
- **No Authenticode signature yet:** there is no certificate, so the installer is unsigned and SmartScreen may warn.
- Someone who can write to the folder can still offer an unverified update that the user might click "Install anyway" on, delete updates, or hold back new ones. Downgrades aren't offered, because only newer versions are shown.
- **Not exercised:** the script's full build path (version bump, `pnpm tauri build`, release commit) and its in-script checks, because the brief forbids a real publish. The guards, `-DryRun`, `-NewKey`, and the `-SkipBuild` path (signing, tag, pruning, log) were run in a throwaway clone with a throwaway key and a scratch folder. See the review.
- `e2e/specs/updates.e2e.ts` was updated for the unverified labels (its manifests are unsigned) and typechecks, but was not run, because that needs the tauri-driver build.
