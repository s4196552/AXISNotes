# T-093 handoff: no system title bar; the tab row is the title bar (like Obsidian)

## What was built
- The main window is created without the system frame (`decorations: false`). The "AXISNotes" title bar with its own minimize/maximize/close is gone.
- `WindowControls` (`src/features/window/`): minimize, maximize/restore (icon follows the window's state through `onResized`) and close, fixed to the window's top-right corner, 38 px tall to match the tab row. Close is a *request* (`window.close()`), so the unsaved-work guard (T-074) runs first.
- Drag regions (`data-tauri-drag-region`, self mode): the tab row's empty part, the left panel's header and vault name, a strip at the top of the right panel, and a top strip on the welcome screen. Double-click on them maximizes/restores (Tauri's built-in behaviour). The tab list's own double-click-for-new-tab is unchanged.
- Layout: with the right panel hidden, the tab row and the right panel button move left by the buttons' width (`--frame-controls`, only set on `:root.framed`). With it shown, its new top strip sits under the buttons, level with the tab row. The left panel header is now 38 px, level with the tab row.
- `Backend.windowFrame` (optional): present in the Tauri backend, absent in the browser preview, which keeps its browser frame and shows no buttons.
- Capabilities: `core:window:allow-minimize`, `allow-toggle-maximize`, `allow-close`, `allow-start-dragging`.

## How to test
`pnpm tauri dev`: no system title bar; buttons at the top right; drag the window by the empty tab row or the vault name; double-click there to maximize; Close with unsaved work still asks first.

## Known gaps
- macOS and Linux get the same Windows-style buttons (no traffic lights). A macOS `titleBarStyle: "Overlay"` pass is future work if macOS builds matter.
- No WDIO spec drives the buttons (the native window's frame can't be clicked through WebDriver reliably); covered by unit tests and a manual run.
