# T-066 handoff: updates from a folder

## What was built

AXISNotes can now update itself from a folder. The user chose "check on launch, ask first" and "local folder for now".

- **On launch** (unless turned off), the app reads `latest.json` in the updates folder. If it lists a newer version, a banner offers **Install and restart** or **Later**.
- **Install** copies the installer to `%TEMP%\AXISNotes-update` and checks its SHA-256 against the manifest. It then runs the installer as `/P /UPDATE /R`, so the installer shows only progress, keeps the user's shortcuts and reopens the app. The app quits so the installer can replace it.
- **Settings → Updates** has:
  - the current version;
  - "Check for updates when AXISNotes starts";
  - the updates folder (type a path, pick a folder, or go back to the default);
  - "Check for updates" and "Install X and restart".
- **Command palette:** a "Check for updates" command.
- **Publishing:** `scripts/publish-update.ps1 -Version X.Y.Z [-Notes "…"] [-Folder …] [-SkipBuild]` sets the version in three files, builds the NSIS installer, copies it to the folder and writes `latest.json`. The manifest is written last, so the app never sees one that points at a missing file.
- **Version:** this release is 0.2.0.

## How to test

- `pnpm lint && pnpm typecheck && pnpm test`, and in `src-tauri`, `cargo test` and `cargo clippy -- -D warnings`.
- `pnpm e2e:build && pnpm e2e --spec e2e/specs/updates.e2e.ts`. This publishes a fake 0.99.0 into the test's own config folder, then checks:
  - Check for updates finds it;
  - after a reload, the launch check shows the banner;
  - the development build refuses to install;
  - "Later" hides the banner;
  - with checking turned off, no banner appears.
- Real install: build with the script into a scratch folder, publish a higher version, and click Install and restart in the installed app.

## Known gaps

- Windows only. macOS and Linux would show the banner but refuse to install.
- A checksum, not a signature. Anyone who can write to the updates folder can publish an update. Signed updates come with hosted releases (`tauri-plugin-updater` and GitHub Releases), which the user deferred.
- Old installers stay in the folder; the script doesn't prune them.
- 0.1.0 has no updater, so 0.2.0 must be installed once by hand.
