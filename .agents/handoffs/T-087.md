# T-087 handoff: tab groups, like Chrome's

## What was built
- **Model** (`src/app/tabs.ts`): tabs have a `group`; the state has `groups` (id, name,
  colour, collapsed) and `selected` (tabs selected along with the active one). New pure
  functions: `selectTab` (toggle / range), `clearSelection`, `groupTabs`, `addToGroup`,
  `removeFromGroup`, `ungroup`, `closeGroup`, `updateGroup`, `toggleGroup`,
  `newTabInGroup`, `moveGroup`, and `moveTab(…, group)`. One `tidy` step keeps the rules
  after every change: empty groups go, each group's tabs sit together, the selection only
  holds live tabs. Collapsing the active tab's group moves to the nearest visible tab (or a
  new one); activating a hidden tab expands its group; Ctrl+Tab / Ctrl+1–8 skip hidden
  tabs; closing skips hidden tabs; new tabs from a grouped tab join its group. Groups are
  saved and restored with the tabs.
- **Store** (`src/app/store.ts`): actions for all of the above.
- **Tab bar** (`src/features/tabs/`):
  - Ctrl/Cmd+click toggles a tab in the selection, Shift+click selects the range from the
    active tab, Escape clears it; selected tabs are tinted.
  - Tab menu acts on the whole selection when opened on a selected tab: Add N tabs to new
    group, Add to “group”, Remove from group, Close N tabs (plus the existing items for a
    single tab).
  - Group chip before the group's tabs: a coloured circle until named, then a coloured pill
    with the name; a count when collapsed. Click collapses/expands; right-click opens the
    editor (name, 9 colours, New tab in group, Ungroup, Close group). The editor also opens
    when a group is created.
  - Grouped tabs carry the colour on their bottom edge (top edge when active).
  - Drag the chip to move the whole group; drop a tab next to a grouped tab to join it,
    onto a chip or the empty strip to leave groups.
- **Commands** (no default shortcuts): Add selected tabs to a new group, Remove selected
  tabs from their group.

## How to test
- `pnpm lint && pnpm typecheck && pnpm test`: see the review. New: 11 model tests and 4 UI
  tests (select + group from the menu + editor, collapse/expand, add/remove/ungroup/close,
  dragging a group and tabs).
- Preview: grouped 3 selected tabs, named the group and picked blue, collapsed and expanded
  it, made a second (unnamed) group, dragged groups and tabs with real drag events,
  checked what was saved. Screenshot in `.agents/qa/T-087/`.
- Native E2E (`pnpm e2e --spec e2e/specs/tabs.e2e.ts`): Ctrl+click selects, the menu
  groups, the editor names it, the chip collapses it, and it comes back collapsed after a
  reload.

## Known gaps
- Dragging moves one tab at a time, not the whole selection.
- No keyboard shortcut to collapse a group or move between chips with the arrow keys (the
  chip is reachable with Tab).
- Group colours are fixed mid-tones that work on light and dark themes; they don't follow
  custom themes.
- jsdom drag events carry no position, so UI tests only cover drops on a tab's left half;
  the right half was checked in the preview with real drag events.

## Decisions for the lead
- Selecting doesn't open a tab (Chrome activates the Ctrl+clicked tab). This keeps the
  editor from switching notes while you pick tabs.
