# T-071 handoff: Lists start as you type `-` or `1`

**Built by:** Claude. **Branch:** `agent/claude/T-071` (from `release/0.3.1` at 292ba18). **Requested by:** the human ("Make '-' at the start of every line immediately make a bulleted list, same with '1' or '1.' start a numbered list").

## What was built
- **`src/features/editor/listAutoformat.ts`** (new): an input handler, plus a highest-precedence Backspace key that undoes the last auto-format.
  - **Rules:**
    - `-` at the start of a line inserts `- `. With only indentation before it, this also works for nested items, and before existing text it turns that line into a bullet.
    - `1` on an empty line inserts `1. `.
    - `.` after `^\s*\d+` with nothing after it inserts `. `.
  - **The keystroke right after a formatting:**
    - A space, or the `.` after an auto `1`, is absorbed.
    - `-` after an auto `- ` gives `--`.
    - A digit or one of `,:/)-` after an auto `1. ` gives plain `1x`. A digit after an auto `1.` or `3. ` gives a decimal.
    - Backspace leaves only the typed character.
  - The "just formatted" state lives in a `StateField` and is cleared by any other edit or cursor move.
  - **Skipped:** code (inline, fenced, indented), frontmatter, `$$` math, several cursors, and IME composition. A `-` right before an existing `-`, `*`, `+` or space is also left alone.
- **`livePreview.ts`:**
  - A bullet's `•` now shows on the cursor's line too. The raw `-` appears only while a selection touches the marker itself.
  - A bullet just started (`- ` with nothing after it), which follows a paragraph and so is still paragraph text to the parser, gets a `•` on the cursor's lines.
- **`math.ts`:** exports `inCode` and `insideMath`, which the auto-format reuses.
- **`Editor.tsx`:** adds the extension.
- Enter continuing the list, and ending it on an empty item, is CodeMirror's Markdown keymap, which was already active.

## Review round 1 (Codex: changes-requested)
- **Finding 1:** a blank line in indented code (`    code` then `    |`) isn't code in the syntax tree until it holds text, so typing `1` or `-x` there was auto-formatted.
- **Fix:** before formatting, the line is parsed as it would be with the inserted text (`becomesCode`), and nothing happens if that text would be code. This also covers four spaces of indent after a blank line, which start a code block. A nested item indented four spaces under a list item is still formatted.
- **Regression tests:** `-x`, `1x` and `3.` are each typed in code, frontmatter, math, inline code and both indented-code cases. They fail without the fix.

## How to test
- **Unit tests:** `pnpm exec vitest run src/features/editor` passes 111 tests, 11 of them new in `listAutoformat.test.ts`. They cover:
  - bullets, including nested ones and conversion of an existing line;
  - absorbed spaces, numbered lists from `1`, `1.` and `3.`;
  - ordinary text left alone: `10 apples`, `1:30 pm`, `1/2 cup`, `2026 plans`, `3.5 stars`, `1.5 h`, `1,000`, `---`, `--`, mid-line `-1`, and `-` before `- item`;
  - Backspace undo, forgetting the state after a cursor move, and no formatting in code, frontmatter or math;
  - Enter continuing the list, and bullet decorations on the cursor's line.
- **Browser preview:** typing through the browser's own input path (`execCommand("insertText")`) in a real note gave `- milk` and `1. eggs`.
- **E2E:** `vault.e2e.ts` gets "starts bulleted and numbered lists as you type, and continues them on Enter". It uses real WebDriver key presses: `-milk`, Enter, `eggs`, Enter, Enter, `1first`, Enter, `second`, Enter, Enter, `10 apples`. The file must then contain `- milk\n- eggs\n1. first\n2. second\n10 apples`. Enter on an empty item turns that same line back into plain text, so no blank line is added.
  - **Native Windows WebView2 run:** the typed text came out exactly as above, so the auto-format works with real key presses. A first run failed only on my expected string, which wrongly included blank lines; it has been corrected and rerun.
  - **Full native suite (Windows WebView2):** all 9 spec files pass (59 tests). The other specs' typing, including `- ` lists, `---` and numbers, is unaffected.
- **Other checks:** `pnpm test` passes 353 tests. `pnpm lint` and `pnpm typecheck` are clean, and Prettier is clean on the changed files.

## Known gaps
- Only `-` starts a bullet; `*` and `+` behave as before, and the `- ` form still works if typed in full.
- A bullet started inside a blockquote (`> -`) isn't auto-formatted.
