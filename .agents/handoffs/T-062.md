## Built

- AGENTS.md rules for bundled modules, dependable product cores, on-demand loading,
  feature dependencies, bounded expensive jobs, safe teardown, data preservation and honest
  performance measurements. The primary copy receives the same section without replacing
  concurrent suite handoff changes.
- docs/SUITE_MODULES.md defines the core/module split across Notes, Hub, Deck, Calendar,
  Athena, ULAP and Connect. SUITE.md and SUITE_ROADMAP.md link that design and its acceptance.
- Notes Settings → Features controls graph, time tracking, AI assistance, handwriting,
  diagrams and existing offline spellcheck. Old configs get enabled defaults; invalid flag
  types are ignored, unknown config keys and source policies are preserved. Dependencies
  affect availability without overwriting preferences. Failed saves roll back the switch.
- Graph starts collapsed and mounts only on request. Timer UI/runtime and occasional
  canvas dialogs/AI settings load lazily. Disabled commands/shortcuts and toolbar entry points
  stay inactive. Tasks, daily notes and compatible grid/canvas opening stay available.
- Timer writes cannot be disabled mid-save; a running timer must be explicitly stopped.
  Restore and config loads reject late results from a superseded vault/lifetime. Failed timer
  stops retain recoverable running state. Disabling does not modify existing time logs.
- Spellcheck is shared across live consumers, starts on first use, terminates on disable or
  last close, and rejects pending calls so consumers settle safely. No duplicate scanner is added.
- Shared AI dispatch rejects disabled assistance, requests cancellation and drops late output;
  closing AI/recognition dialogs cancels their runs. Deterministic diagrams remain usable when
  AI assistance is disabled. Optional chunk failures offer recovery without deleting source data.
- scripts/measure-module-bundle.mjs measures initial JS/static dependencies and verifies
  optional feature entries are absent from the initial chunk graph.
- The human's uncommitted primary DESIGN.md gained a suite-context sentence and an optional
  features/loading section. Existing design/ assets were untouched. This existing user artifact
  was not copied wholesale into the task commit.

## Performance evidence and limits

includes every static dependency exactly once. Baseline: 1,123,000 bytes / 372,270 gzip bytes.
Final task build: 1,120,516 bytes / 371,956 gzip bytes.
This is only a small bundle-size difference; do not claim measured startup, CPU or RAM savings.
GraphView, TimeRuntime, TimerControls, mermaidBlocks, AiSettings, HandwritingDialog and
DiagramMaker have separate non-initial entries. Native tests and lifecycle unit tests verify
loading/switches/teardown, not a performance benchmark. Idle CPU/RAM, typing latency, cold/warm
first-use timing and all future suite job/model budgets still need reproducible measurements.

## How to test

Use a normal dependency installation and run pnpm lint, pnpm typecheck, pnpm test and pnpm
test:rust. Build the frontend with --manifest and run the measurement script with dist and an
optional baseline dist path. Run the five native specs above against a real desktop build.
Open a note: its local graph is collapsed. Settings → Features can disable tools; reopening
the webview retains preferences and note contents. Stop a timer before disabling tracking.
Disable spellcheck to release its worker; re-enable to create one on the next use.
