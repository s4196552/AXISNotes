# T-024 handoff: Phase 4 E2E

**Built by:** Claude. Codex's Windows sandbox is unavailable, so a cross-review is owed. **Branch:** `agent/claude/T-024`

## What was built
- **`e2e/specs/ai.e2e.ts`** (5 tests) against the real Tauri build and a mock OpenAI-compatible server started by the spec on 127.0.0.1. It covers:
  - Provider setup through Settings → AI: endpoint, key, "Test connection" and the task model.
  - The key never reaches the webview (`ai_settings` called from the page) or disk, and is sent only as the `Authorization` header to the provider.
  - Ask AI streams an answer about a note, and the note's text reaches the provider.
  - An "AI: never" note is refused before any request, both from the UI and from a direct `ai_run` in the webview. The server receives nothing.
  - The request log holds metadata only.
- **`wdio.conf.ts`**: an `ai` seed, plus `AXIS_CONFIG_DIR` (a throwaway folder per session) and `AXIS_AI_MEMORY_KEYS`, so tests never touch the user's settings or keychain.

## How to test
`pnpm e2e:build && pnpm e2e`: 38 tests in 6 spec files, all passing on Windows / WebView2 153.
