# T-267 handoff: study blocks in notes

## What was built

The human approved the proposal in `docs/proposals/html-in-notes.md` ("Do these": options b
and c). T-267 is option b: three typed fenced blocks rendered as study cards in the live
preview while the cursor is outside them.

- ` ```flashcards `: `Q:` / `A:` cards. Click, Space or Enter flips the card. Again and Got it
  sort it, and the next unsorted card follows. Previous/Next (← →), Shuffle and Start over
  are available. "Study the N again" starts a round with only the missed cards.
  `reverse: true` also asks the answers.
- ` ```quiz `: choose one (radio), select all that apply (more than one `[x]`), and typed
  short answers compared ignoring case and spacing. Check shows Right or Not quite, the
  answer and the explanation. The score and the missed questions appear when every
  question is checked, followed by Try again (shuffled).
- ` ```mindmap `: a nested list drawn with the graph view's tree layout, coloured by main
  branch. Each node folds (−/+N); there are Expand all, Collapse all and Copy as a Mermaid
  mindmap block. Labels wrap to two lines.
- When a block doesn't parse, an error card names the line and offers Edit source.
- The `/` menu has a **Study** section: Flash card block, Quiz block and Mind map block.
  These insert starter blocks. The labels differ from the AI skills of the same names.

## Decisions taken with defaults (proposal §10)

- Q2: Skills writing blocks is T-268, with the Markdown format of each skill switching to
  blocks. The HTML formats are unchanged.
- Q3: No per-card IDs yet. "Send to Deck" will need them when Deck exists.
- Q4: Results follow the existing study-page rule: they are recorded through
  `recordStudy`, so nothing is recorded for "AI: never" notes. The source is the note plus
  the top-level section heading the block sits under (the heatmap's units).
- Q6: Blocks inside `![[Note]]` embeds still show as source, as Mermaid does today.

## How to test

`pnpm vitest run src/features/studyBlocks` runs 19 tests. They cover the parsers and
errors, the editor decorations, flipping and sorting with heatmap reports per round,
progress kept across redraws, HTML in a card shown as text, quiz checking, scoring and
retrying, select-all, and mind-map folding.

In the app, type `/flash`, `/quiz` or `/mind map` in a note, fill in the block, then move
the cursor out of it.

## Known gaps

- `[[links]]` in blocks aren't indexed (backlinks and graph), because the indexer skips
  fenced code.
- Math isn't rendered in card text.
- There is no feature switch yet; it waits for the T-062 module system. Cost when unused is
  one string compare per fenced block.
- Progress is kept in memory per note and block text, up to 60 blocks, and is lost when the
  app restarts. This is by design.
