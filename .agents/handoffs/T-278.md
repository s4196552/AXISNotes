# T-278 handoff: never overwrite a broken settings file

## What was built

- **A file that can't be read is kept.** `load()` keeps an unreadable or invalid `.axisnotes/config.json` as `config.json.bak`, shows the default settings, and sets `problem: {kind: "broken"}`. Nothing is written while it's broken, so the file and its AI privacy rules survive. A missing file is still just the defaults.
- **`ConfigProblemBanner`** (top of the window) shows the problem.
  - Try again reloads the file.
  - Use defaults, after a confirmation, replaces the file with the settings shown. The `.bak` stays.
- **Saves wait for a pause.** `update()` changes the settings at once and saves 300 ms after the last change (0 in tests via `import.meta.env.MODE`). Saves run one at a time.
  - `flush()` saves a waiting change. It runs before switching or creating a vault (`store.ts`), and before closing or installing an update (`saveBeforeExit`).
  - `load()` drops a waiting change rather than writing it over the file it's about to read.
- **A failed save shows.** It sets `problem: {kind: "write"}`, shown in the banner with Try again. `update()` always resolves, so `void update(...)` callers no longer cause unhandled rejections.

## Files

`src/app/config.ts`, `src/app/store.ts`, `src/App.tsx`, `src/features/files/beforeExit.ts`, `src/features/settings/{ConfigProblemBanner.tsx,configProblem.css}`, `src/app/configSafety.test.tsx`.

## Known gaps

- Changes made to `config.json` outside the app while it's open are still overwritten by the next settings change. The in-memory copy isn't reloaded from disk.
- The banner sits over the tab row at the top centre.
