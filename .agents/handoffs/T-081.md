# T-081 handoff: resizable side panels with a sliding animation

## What was built
- `layout.ts`: `leftWidth`/`rightWidth` stored with show/hide in `axisnotes.layout`,
  `clampWidth` (180–600, bad values → default), `setWidth(side, w, { save })`,
  `maxWidth(side)` (keeps 320 px for the note area), `resetPanelWidth`.
- `PanelResizer.tsx`: `role="separator"` handle on each panel's inner edge. Pointer drag
  with pointer capture, saved once on release; arrow keys / Shift / Home / End;
  double-click resets. Ends the drag if the panel is hidden or unmounted mid-drag.
- Sliding: the shell always has three columns and a hidden panel's column animates to
  0 px (`grid-template-columns` transition, 180 ms, `cubic-bezier(0.2, 0, 0, 1)`). The panel
  keeps its full width, pinned to the column's inner edge, so it slides rather than
  squashes. No transition while dragging. It plays even under `prefers-reduced-motion`:
  the user asked for it with Windows "Animation effects" off (2026-10-17).
- Closing panels: `aria-hidden` + `inert` straight away, `visibility: hidden` after the
  slide. The left panel stays mounted (as before, keeps tree/search state); the right one
  unmounts after `SLIDE_MS` via `usePresence` (`panels/presence.ts`).

## How to test
- `pnpm lint && pnpm typecheck && pnpm test`: passed (54 files, 394 tests). New tests: drag
  left/right, min clamp and note-area room, keyboard + reset, hidden-width kept and drag
  ended by hiding, column slides to 0 with the right panel kept until it has slid away,
  quick reopen, saved-width validation.
- Preview (port 1481, real mouse): drag 260→360 and 280→340, saved and restored after a
  reload; double-click reset; no stuck cursor or text selection; a 3000 px panel body
  stays inside the window. Slides measured by seeking the CSS transitions (the pane was
  hidden): ~88% of the way at 90 ms, done at 180 ms, also with reduced motion reported;
  drag has no transition.

## Known gaps
- Shrinking the window doesn't shrink saved widths; the note area shrinks first. The handle
  reports `aria-valuemax` 600 even when less room is available.
- Not checked in the native Tauri window.
