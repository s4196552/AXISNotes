# T-019 handoff: time tracking and computed properties

**Built by:** Claude. Codex's Windows sandbox is unavailable, so a cross-review is owed. **Branch:** `agent/claude/T-019`

## What was built
- **Time tracking** (`src/features/time/`):
  - `timeLog.ts` holds the helpers for the frontmatter `time_log`: append, close, durations and formatting.
  - `timer.ts` is the store for the single running timer. Its state is the open entry in the note, so `restore()` picks it up after a restart.
  - `TimerControls` provides the note-header timer, the per-task ▶ in the tasks view, and the running clock in the status bar.
  - `TimeReport` offers ranges (Today, This week, This month, Last 30 days, All, Custom), grouping by note, tag, project or day, bars and totals, a list of entries, and a "Log time" form for manual entries.
  - Rust `index/time.rs` backs the `time_entries` command, which returns entries with the note's tags and project. The in-memory backend mirrors it.
- **Computed properties** (`src/lib/computed.ts`): a frontmatter value starting with `=` is evaluated with the grid engine against other properties (names are case-insensitive, lists act as ranges, and formulas can chain, with `#CIRC!` on cycles).
- **Properties panel**:
  - A Formula type with a live result (errors shown in red, with the detail as a tooltip).
  - Structured values (for example `time_log`) are shown read-only as "N entries" instead of being corrupted.
- **Entry points**: a sidebar Time button, the "Time report" and "Stop timer" commands.

## Known gaps
- Computed properties are evaluated only in the UI; search `prop:` sees the raw formula.
- There is no editing or deleting of individual time entries except by editing the YAML.
- An entry that crosses midnight counts toward its start day.
