# T-281 handoff: unbypassable "local only" AI check

## What was built

- **`is_local_url` parses the URL** (`src-tauri/src/ai/mod.rs`) with `url::Url` (WHATWG,
  same as reqwest). Local = http/https, no user info, host a loopback IP (127.0.0.0/8,
  `::1`), exactly `localhost`, or `*.localhost`. Unparsable = not local. New helpers
  `is_local(&Url)` and `is_localhost_name`. What counts as local was not widened:
  `localhost.`, `0.0.0.0`, `[::ffff:127.0.0.1]` are not local.
- **Plain http only on this computer** (`src-tauri/src/ai/settings.rs`):
  `endpoint_problem` now also refuses `http://` to another host (`PLAIN_HTTP_REMOTE`
  message). `clear_bad_endpoints` (runs at load) still only clears non-addresses such as
  a pasted key, so an older saved LAN `http://` endpoint stays visible instead of being
  silently swapped for the default.
- **Transport** (`src-tauri/src/ai/transport.rs`): two reqwest clients picked per request
  by `is_local_url`.
  - Local: `redirect(Policy::none())`, `no_proxy()`, and a DNS resolver that maps
    `localhost`/`*.localhost` straight to 127.0.0.1/::1 and fails any other name.
  - Remote: at most 5 redirects, only to the same host and port over https, never to a
    local host.
  - Any 3xx reaching the caller becomes a clear "redirected… set the endpoint to the
    final address" error. Plain-http remote URLs are refused before connecting (covers
    old saved settings).
- **UI** (`src/features/ai/AiSettings.tsx`): an `http://` endpoint for another computer
  is refused on blur with the message in the card's status line, and the box returns
  to the saved value. The backend's own refusal still reaches the panel's alert. The
  folder-privacy hint now says a localhost provider keeps requests on this computer,
  but a local server could pass them on.
- **TS mirror** `src/lib/aiEndpoint.ts` (`isLocalUrl`, `isPlaintextRemote`) is used by the
  UI and by the in-memory backend (`src/ipc/memoryAi.ts`), which had the same string
  bug.

## How to test

- `cd src-tauri && cargo test ai::`: `recognizes_local_endpoints`,
  `rejects_lookalike_and_crafted_endpoints`, `crafted_lookalike_endpoints_are_not_local`,
  `plain_http_endpoints_must_be_on_this_computer`, and `transport::network_tests` (real
  sockets on 127.0.0.1: localhost resolution, a 307 that is not followed, plain-http
  refusal, resolver refusal).
- `npx vitest run src/lib/aiEndpoint.test.ts src/features/ai/AiSettings.test.tsx`.
- In the app: Settings → AI → add Ollama → set the endpoint to
  `http://192.168.1.10:11434/v1` → the card says plain http is only for this computer.

## Known gaps

- The remote redirect policy has no unit test: reqwest's `Attempt` can't be built
  outside reqwest, and a test would need a local https server with a trusted
  certificate. It is a short closure; see the review.
- **Behaviour change the lead should know about:** a LAN AI server over plain
  `http://` (for example Ollama on another PC) can no longer be saved, and requests to
  one saved by an older version fail with the plain-http message. The fix is https, or
  a forwarder on this computer. This follows the brief, and AGENTS.md treats a private
  server as distinct from on-device.
- `subscription.rs` already builds its own client with `Policy::none()` for fixed OpenAI
  URLs; unchanged.
