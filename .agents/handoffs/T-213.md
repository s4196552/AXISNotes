# T-213 — Markdown and AXISNotes blocks in AI output

Implemented at the human's request on 2026-11-10 in `.worktrees/T-213`, branch `agent/codex/T-213`, based on `d8068bb`. No merge, release, installation or remote push is part of this task.

## Behaviour

- Sidebar replies default to **Markdown**. The **Output** selector also offers **Markdown source**, preserving the exact model reply. Switching display makes no AI request and works during streaming and on completed conversation history.
- Shared AI answers (sidebar, Ask AI and AI blocks) use the installed note-editor Markdown parser: semantic headings, nested lists, ordered-list starts, read-only checklists, tables with alignment, quotes, rules and fenced code. AXISNotes highlights, tinted callouts and collapsible callouts/toggles are supported. Heading/callout colours follow the existing theme; coloured code fences use the existing code-colour names.
- The sidebar's system instructions explicitly allow Markdown and AXISNotes callout syntax. Display is separate from the model request and from Suggest edit.
- Existing source/privacy rules, source-relative `[[links]]`, citation validation and Ctrl/Cmd/middle-click opening remain. Raw HTML, images and note embeds are inert text; rendering starts no source reads, note writers, workers, subscriptions or AI runs. Checklists do not edit notes. Proposed edits still require approval and reject stale notes.
- Completed answers are memoized so streaming a follow-up does not repeatedly parse unchanged earlier replies. No dependency or persisted note/config format changes.

## Limits

This is Markdown/AXISNotes text-block rendering, not an editor mounted inside a chat response. It does not execute HTML, load embedded media/notes or render math/diagrams; unsupported constructs stay readable as text/code. Real AI output quality is not evaluated: all generation tests use deterministic local replies and disposable vaults/settings. Original notes and the installed app are preserved. The primary checkout's pre-existing `.claude/launch.json` modification is untouched. Integration remains separate from publishing an update.
