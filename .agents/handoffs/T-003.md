# T-003 handoff: File tree

**Built by:** Claude (fallback — Codex's Windows sandbox failed with `helper_sandbox_lock_failed`, so it could not run commands).
**Branch:** `agent/claude/T-003`

## What was built
- `treeModel.ts`: pure helpers (visible rows, find, unique "Untitled N" names, rename rules that keep `.md`, move validation, remapping expanded paths after renames).
- `useExpanded.ts`: expanded folders, persisted per vault in `localStorage` (try/catch guarded).
- `FileTree.tsx`: nested tree with lazy visible-row flattening and memoized rows; toolbar (new note / new folder / collapse all); inline rename (F2, Enter, Esc, blur commits); context menu; drag-and-drop moves onto folders or the root; keyboard navigation (arrows, Home/End, Enter, F2, Delete); ARIA tree roles.
- `filetree.css`: theme variables only.

## Changes outside `src/features/filetree/` (lead-owned files)
- `src/test/setup.ts`: registers Testing Library `cleanup` (Vitest globals are off, so auto-cleanup never ran).
- `src/ipc/memoryBackend.ts`: error messages now match the Rust `AppError` wording (e.g. `already exists: b.md`).
- `.claude/launch.json`: `axis-web` preview config (Vite with the in-memory backend).

## How to test
- `pnpm test`: 10 component tests + 7 model tests.
- `pnpm dev` and open http://localhost:1420 to use the demo vault in a browser.

## Known gaps
- Deleting asks with `window.confirm` (native Tauri dialog can come later).
- No virtualization; visible rows are memoized, which is fine for thousands of rows but a windowed list may be needed for very large expanded trees.
- Cross-review by Codex is still owed once its sandbox works.
