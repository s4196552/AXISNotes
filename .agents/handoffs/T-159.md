# T-159: Selected-image clipboard shortcuts and selected-folder drags

Built by Codex at the human's explicit request, on `agent/codex/T-159` in
`.worktrees/T-159`, based on main `bec3d52`.

## What changed

- Image selection survives Ctrl/Cmd+C and Ctrl/Cmd+X keydown, allowing the following
  clipboard event to copy/cut the embed instead of the text at the old cursor.
- A drag uses the outermost selected path even when the selection reduces to one
  folder and the gesture starts on a selected child. The drag preview also names
  that folder. Into-folder drops and before/after reordering share this behaviour.
- Seven regression cases cover both modifiers, copy/cut and undo, plus all three
  folder-drop positions and the preview label. All seven failed before the fixes;
  both affected test files passed afterwards (67 tests).

## How to test

From the task worktree, run the package lint/typecheck/test scripts. For the focused
regressions:

```powershell
node node_modules/vitest/vitest.mjs run src/features/editor/media.test.tsx src/features/filetree/FileTree.test.tsx --maxWorkers=1 --pool=threads
```

In the app, select an embedded image while the text cursor is elsewhere, then use
Ctrl/Cmd+C or Ctrl/Cmd+X; paste should yield its embed and cutting must preserve the
unrelated text. Undo restores a cut image. Select an expanded folder and its children
with Shift, start dragging a child, and drop into/before/after another folder: the
whole selected folder should move, and the preview should name it.
