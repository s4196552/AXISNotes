# T-094 handoff: shared dialog styles load with the app

## What was built
- The dialog chrome shared beyond the AI features moved from `src/features/ai/ai.css` into the
  global `src/styles/app.css` (unchanged rules, new section at the end): `.ai-icon` (+ hover),
  `.ai-ok` / `.ai-error`, `.spin` + `@keyframes ai-spin`, `.ask-ai`, `.ask-ai-header`,
  `.ask-ai-footer` (+ `button`), `.ask-ai-header .ai-icon`, `.ask-ai-spacer`, `.ask-ai-body`,
  `.ask-ai-plan`, `.ask-ai-answer`, `.ask-ai-meta`.
- `ai.css` keeps the AI-only rules (settings, `.ask-ai-input`, `.ask-ai-options`, `.ask-ai-confirm`,
  the caret, Fix text's diff).
- Getting Started no longer imports `ai.css` (T-079's per-dialog patch; now redundant).
- So Import, Handwriting, Getting Started and the `ai-icon` / `ai-error` users in Settings
  (Hotkeys, Clipper, Updates), the update banner and the welcome screen are styled however early
  they open.
- Side effect, intended: feature stylesheets now always override these shared rules (app.css loads
  first). Before, the result depended on load order, e.g. the Import dialog was 680 px wide
  (`.ask-ai`) instead of 600 px (`.import-dialog`) when `ai.css` loaded after `import.css`; now it
  is always 600 px.
- Regression test `src/styles/dialogChrome.test.ts`: the shared selectors are in `app.css` and not in `ai.css`.

## Files
`src/styles/app.css`, `src/features/ai/ai.css`, `src/features/vault/GettingStarted.tsx`,
`src/styles/dialogChrome.test.ts`, `.agents/TASKS.md`.

## How to test
`pnpm dev`, reload, and without opening any AI feature: Ctrl+P → "Import from Obsidian…", then
Ctrl+P → "Handwriting to text (pen)" with a note open. Both have header and footer borders and
padding and the close button on the right. Getting Started and Ask AI look as before.

## Known gaps
None. The `ask-ai-*` class names now describe a generic dialog; renaming them (e.g. `dialog-header`)
would touch every dialog and was left out.
