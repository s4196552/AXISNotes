# T-035 handoff: Installers

**Built by:** Claude. **Branch:** `agent/claude/T-035`

## What was built
- `tauri.conf.json` bundle:
  - Targets: msi, nsis, dmg, appimage.
  - Publisher, category and descriptions.
  - The extension as a resource (`dist-extension/` → `extension/`).
  - macOS minimum 10.15, and the AppImage without the media framework.
- `beforeBuildCommand` is now `pnpm build && pnpm build:extension`. `scripts/build-extension.mjs` also writes a clean `dist-extension/`, and `build.rs` makes sure it exists for plain cargo builds.
- New app icon: `src-tauri/icons/app-icon.svg`, with every size generated by `tauri icon`. The extension uses it too.
- `clipper_open_extension_folder` opens the bundled extension folder, or `extension/` in dev builds. It sits behind a new **Open extension folder** button in Settings → Web clipper.
- `.github/workflows/release.yml` (tauri-action) builds on Windows, macOS arm64 and x64, and Ubuntu 22.04, and attaches the installers to a draft release. Triggered by a `v*` tag or by hand.
- package.json version is now 0.1.0 (the same as Cargo and tauri.conf).

## How to test
- Build: `pnpm tauri build --bundles msi nsis` produces `target/release/bundle/msi/AXIS_0.1.0_x64_en-US.msi` (21.7 MB) and `nsis/AXIS_0.1.0_x64-setup.exe` (20.1 MB), both verified locally.
- Contents: an administrative extract of the MSI (`msiexec /a`) shows `axis.exe` plus `extension/` with the manifest, popup, lib and vendor, and no tests.
- The .dmg and AppImage can only be built on macOS and Linux runners; the release workflow does that.
- `pnpm test` covers `ClipperSettings.test.tsx`.

## Known gaps / decisions for the lead
- Nothing is code-signed. That needs certificates or accounts the user would have to obtain.
- The extension isn't published to the browser stores; users load it unpacked from the app's folder.
