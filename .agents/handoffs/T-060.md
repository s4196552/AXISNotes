# T-060 handoff — watcher test macOS flake

Status: in-review (awaiting Codex cross-review). Branch: agent/claude/T-060.

## What was built
- Added a test-only helper `wait_for_path(rx, path, timeout) -> Result<Batches, Batches>` in
  the `watcher.rs` test module. It keeps receiving batches until one contains a change whose
  paths include `path` exactly, or until a single overall deadline passes. `Ok` and `Err`
  both carry every batch received, so the diagnostics are available. A disconnected channel
  returns `Err`.
- `reports_external_edits` now uses the helper with the same 5 s budget as before. On
  timeout it panics with every batch it received. The assertion is unchanged: an event for
  `ext.md` must arrive.
- New deterministic test `wait_for_path_skips_unrelated_batches_and_fails_without_target`:
  - two unrelated batches followed by the target returns `Ok` with all three batches;
  - unrelated batches only, with the sender kept alive, returns `Err` no earlier than the
    deadline and includes the unrelated batch;
  - `sub/ext.md` does not match `ext.md` (exact path, not a substring).

## Files changed

## Evidence that there is no runtime defect
`Vault::open` canonicalizes the root with `dunce::canonicalize`, so macOS
`/var` → `/private/var` event paths still strip to vault-relative paths. `start` only calls
`on_change` with non-empty translated batches, so a batch without `ext.md` is a legitimate
separate event. The failure was the test's assumption about which batch arrives first, not
a missing event.
