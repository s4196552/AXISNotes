1. **P1: startup and re-pairing** (review cites S2_FOUNDATION.md:107).
   - S2-D07 is rewritten as a service side plus launcher steps L1–L4.
   - Liveness is proven with a **bootstrap-signed** `GET /connect/status`. The bootstrap key
     is created before the manifest and read fresh on each attempt. The app's credential is
     checked only afterwards. A client-signed 401 after a bootstrap-signed success therefore
     means "credential invalid", never "dead service".
   - Exit code 3 no longer waits for a new instance: the launcher polls for any verifiable
     manifest for 5 s, then reports `unavailable`/`connect-unverifiable`. Only one spawn
     happens per attempt.
   - Pair outcomes are defined per record state (none, active, pending, revoked). `revoked`
     never auto-retries; the explicit user action sends `reactivate:true`
     (`suitePairAgain`). Pending clients may call status only.
   - Restore keeps the current `clients` table, so revocations survive (S2-D19).
   - Eight named cases are listed in S2-D07: first install, running + unpaired, invalid
     credential, revoked, restore while closed, restore while running, hung lock holder, and
     impostor. They are tested in T-044 AC 13 and T-049 scenario 13; T-045 AC 14 covers the
     Notes side.
2. **P1: legacy config-write control** (review cites :437 and :319). New S2-D29a:
   - Generic `write_file`/`create_file` on `.axisnotes/config.json` natively **preserve** the
     on-disk `ai.folders`, so they cannot widen or narrow it. They refuse invalid incoming
     content or an unreadable current file. Rename and trash are refused.
   - Preserving the key instead of rejecting the write was chosen because `src/app/config.ts`
     writes its whole in-memory copy, and rejecting would break unrelated settings.
   - New native `suiteAiSetLegacyRule` with narrowing/widening classification and
     confirmation.
   - T-046 migrates `AiSettings.tsx` and `FileTree.tsx` (both already T-046-owned).
   - External programs editing `config.json` are stated as out of reach.
   - Six rejection and preservation tests are in S2-D29a, T-045 AC 5 and T-049 scenario 7.
3. **P1: derivative provenance** (review cites :486). S2-D33 is rewritten:
   - Persistent per-resource provenance lives in the authoritative
     `.axisnotes/suite/provenance.json`, which is protected.
   - Effective policy recursively intersects each recorded source's **current** policy.
     Missing, removed or ambiguous sources fall back to an apply-time snapshot ∩ the current
     chain of their last path.
   - Clearing provenance is a confirmed widening; editing the text does not clear it.
   - `suiteAiApply(runId, destinationPath)` commits provenance before the UI inserts, which
     keeps editor undo and canvas inserts unchanged.
   - Limitations are stated: per-resource not per-span, clipboard copies untracked, and an
     engineering rule for Notes' own trusted webview only.
   - The destination-widening and source-change regressions are in T-045 AC 13 and T-049
     scenario 14.
4. **P2: pairing confidentiality** (review cites :144, :176 and SUITE_PROTOCOL.md:224).
   - The "secrets never cross the wire" wording is removed from S2-D09, SUITE_PROTOCOL.md
     (trust section and Pairing) and DECISIONS.md.
   - The pairing response now carries a `sealedSecret`: ChaCha20-Poly1305 under an
     HKDF-SHA256 key derived from the bootstrap key and the request nonce, with AAD binding
     the client ID, generation and installation. Every primitive is in `ring`.
   - The docs state that HMAC gives authenticity, not confidentiality, that bodies are
     plaintext on loopback, that there is no forward secrecy, and that loopback capture is
     out of scope (section 1).
   - Covered by seal vectors (T-044 M1) and T-044 AC 14.
5. **P2: offline file replacement** (review cites :346).
   - The unconditional "new file at old path gets a new ID" claim is withdrawn. It now holds
     only for **watched** delete-then-create.
   - S2-D24 defines `lastSeen` evidence: fingerprint, size, a bottom-64 line-hash sketch (no
     plaintext) and block IDs.
   - Offline changes keep the ID only on an equal hash, a surviving block ID, or sketch
     similarity of at least 0.5 (with at least 3 lines). Otherwise the entry is `ambiguous`,
     with the file as candidate, resolved by explicit `suite_relink` or the new
     `suite_detach`.

## Key decisions (see S2_FOUNDATION.md for all)

- New local sibling repositories: `AXIS-Protocol` (schemas, vectors, `axis-suite-protocol` and
  `axis-connect-client` crates), `AXIS-Connect` and `AXIS-Hub`; later `AXIS-Deck` and
  `AXIS-Calendar`. Notes, Athena and ULAP stay where they are. No remotes until the human says
  so.
- Connect is a headless per-user Rust binary. It uses a lock file, an ephemeral port on
  127.0.0.1, an atomic manifest plus a signed status check for readiness, and exits when idle.
  It needs no admin rights and runs no service.
- Authentication is HMAC-signed requests and responses in both directions. Secrets are derived
  from a keychain master key plus a generation counter. Pairing is native-only through a
  bootstrap key. Capabilities come from a fixed table per app. Adapters authorize mutations by
  originating app.
- Notes identity lives in `.axisnotes/suite/`, which is authoritative, minted lazily and never
  embedded in Markdown. Task anchors use standard `^blockId` markers, added only by an
  explicit command.
- The AI policy lives in `.axisnotes/ai-policy.json`. Parsing is strict, inheritance is
  intersection, and legacy rules are intersected and never rewritten. On-device requires
  runner-probe evidence, and unknown loopback gateways are denied.
- Hub launches by item ID, using argument arrays and `.exe` files only. Website sessions use
  per-session WebView2 data directories, and remote webviews get no capabilities.

## Behaviour changes T-045 will introduce (stricter; need user-visible notice)

1. An unreadable or invalid `.axisnotes/config.json` now denies all AI. Today it silently
   means "no rules" (fail-open, `privacy.rs:30-47`).
2. An unknown legacy value such as `"sometimes"` now denies its subtree. Today it is dropped.
3. Legacy child widening (for example `Journal/Public: any` under `Journal: local`) now
   intersects to local-only.
4. Legacy `local` means verified on-device. Localhost gateways and cloud-proxied local-runner
   models are denied.
5. Generic config saves can no longer change `ai.folders` (they preserve the on-disk value),
   and saving settings is refused while `config.json` is unreadable (S2-D29a).
6. A note that received applied AI output keeps the sources' AI restrictions until the user
   clears provenance (S2-D33).
7. A suite-referenced file heavily rewritten while Notes was closed resolves `ambiguous` until
   the user confirms (S2-D24).
