# T-075 handoff: images, video and audio in notes

## What was built

- **Rendering** (`src/features/editor/embeds.ts`, `MediaWidget`). An embed alone on its line shows inline when the cursor is elsewhere:
  - `![[x.png|300]]`, `![[x.mp4]]` and `![[x.mp3]]` from the vault;
  - Markdown `![alt|300](path)` with `../` and `%20`/`<…>`;
  - web images and video files;
  - YouTube/Vimeo links as their players.
  - Video/audio use native controls. An "Edit link" button (on hover) shows the embed's text, because clicks on a player belong to the player.
- **Input** (`src/features/editor/media.ts`):
  - paste (screenshot → `Pasted image <yyyyMMddHHmmss>.png`; copied files keep their names; Excel/Word text stays text);
  - drag from the file tree (media → embed, note → link);
  - files dropped from Explorer (`installFileDrops`, mounted in `App.tsx`);
  - command menu "Image, video or audio…" (native picker) and "Embed from the web" (`![]()`).
- **Settings → Files & links**: the attachment folder, `attachments.folder`, default `Attachments`, in Obsidian's forms.
- **Media viewer**: opening `.mp4`/`.mp3`… from the file tree plays it (`docKind` "media", a Film icon in the tree).
- **Rust** (`src-tauri/src/attachments.rs`, `commands.rs`, `lib.rs`):
  - `save_attachment` takes raw bytes, with names in percent-encoded headers.
  - `import_dropped` imports only paths Rust itself recorded from `WindowEvent::DragDrop`; `lib.rs` emits `attachments://dropped` with the physical position.
  - `pick_attachments` uses the dialog plugin's native picker.
  - Free names count up (`clip 1.mp4`), copies are atomic, and files already in the vault are linked rather than copied.
- **CSP** (`tauri.conf.json`): `img-src https:`, `media-src` (asset + https), and `frame-src` limited to the YouTube no-cookie and Vimeo players.

## How to test

- `pnpm lint`, `pnpm typecheck`, `pnpm exec vitest run` (`src/lib/attachments.test.ts`, `src/features/editor/media.test.tsx`).
- `cargo test` (`attachments::tests`).
- `pnpm e2e:build && pnpm e2e --spec e2e/specs/media.e2e.ts` covers:
  - a vault WAV loads under the CSP;
  - a vault PNG shows at `|40`;
  - the YouTube embed is a sandboxed no-cookie iframe;
  - a synthetic screenshot paste lands in `Attachments/Pasted image …png` and renders;
  - a WAV opened from the tree plays.
- **By hand:** drop an image/video from Explorer onto a note; use "Image, video or audio…"; play a YouTube link.

## Known gaps

- **Dropping from Explorer and the file picker** are native UI WebDriver can't drive; they're covered by Rust tests of the import logic and by hand.
- **Only whole-line embeds render.** An image in the middle of a sentence stays as text, which matches how note embeds already behave.
- **No resize handles** (set `|width` in the link), and no PDF embeds.
- **Web media loads from its site when shown.** That's the approved exception to the no-network rule; see DECISIONS 2026-10-13.

## Review round 1 (Codex: changes-requested) — fixed

1. **Concurrent imports could share a file.** `attachments::reserve` now claims the name with `create_new`, and `fill` writes into a temporary file unique to the call (process id plus a counter), then renames it over the reservation. On failure both are removed. A Rust test runs 8 imports of `clip.mp4` at once: every file is distinct and holds its own content.
2. **Embeds were lost after switching notes mid-import.** Each import records its target (note, vault, position, text). If the editor is gone or shows another note when the files arrive, `editNote` writes the embeds into the note itself: at the original spot if the note is unchanged, else at the end. `saveAll` (close/update) waits for imports in flight first via `trackPending` in `unsavedWork.ts`, but only when there are any, so documents still flush in the same turn otherwise. Tests cover both cases.
3. **Explicit `./` and `../` paths could pick another same-named file.** `resolveMedia` resolves them exactly (or reports them missing); bare names still use Obsidian's search.
4. **`%` in Markdown embeds.** `embedFor` escapes `%`, `<` and `>`, and the round trip is tested.

Checks after the fixes:
- 397 unit tests and 114 Rust tests pass; clippy and lint are clean.
- E2E: 10 of 11 spec files passed in the full run. The knowledge spec's two typing tests failed under load (the suite took 5 minutes) and passed 12 of 12 when rerun alone on the same build.

## Review round 2 (Codex: changes-requested) — fixed

1. **A failed embed write could let the app close.** Off-editor embeds now go through `trackClosingWrite`, like a closing document's final write. If the note can't be written, its new text is kept in an "(unsaved …)" file next to it and the user is told. If even that fails, `saveAll` reports the note, so closing or updating is held back. If the note was reopened meanwhile, the change goes through its new editor. Tested both ways.
2. **Generated paths could still find a nearer namesake.** On a name clash `embedFor` now writes the vault-absolute `![[/Attachments/clip.mp4]]` (Markdown form `![](</path>)`), the same convention as T-065's `[[/path]]` links. `resolveAttachment` resolves a leading `/` exactly. A test with `Attachments/clip.mp4` and `School/Attachments/clip.mp4` checks that each embed finds its own file.

Checks: 399 unit tests, lint, types and Prettier clean; the media E2E spec passes (4/4) on the rebuilt app.

## Review round 3 (Codex: changes-requested) — fixed

1. **A pasted screenshot that failed to save could be lost on close.** Its bytes are kept (`keepForRetry` in `unsavedWork.ts`). `saveAll` tries it again before flushing documents, saving and embedding it; until that works it reports `Attachments/Pasted image ….png` as unsaved, so closing or updating is held back. Tested failing, then succeeding.
2. **One failure in a batch dropped the rest.** `import_dropped` and `pick_attachments` now return `{ paths, failed }`, with each file succeeding or failing on its own. The files that made it in are embedded and the failures are named in the error. Paste works the same way per file.

Checks: 401 unit tests and 114 Rust tests pass; clippy, lint, types and Prettier are clean; the media E2E spec passes (4/4) on the rebuilt app.
