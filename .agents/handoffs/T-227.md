# T-227 — AI sidebar usability and note position

Human requested the five improvements in AXISNotes and clarified that the left-side action belongs in the file-tree right-click menu. Implemented in `.worktrees/T-227`, branch `agent/codex/T-227`, based on main `ef3ba11` (0.3.86).

## What changed

- **Ctrl+wheel in the AI sidebar** scales the conversation, context and composer with the existing right-panel zoom; header/toolbars retain their usual size. HTML preview wheel gestures are forwarded by a frame-scoped, rate-limited message to the same UI zoom handler. It accepts only a matching focused/hovered frame and the two zoom directions; the injected gesture listener is dormant when a saved draft is opened outside the sidebar. No whole-window zoom change from the wheel gesture.
- **Returning to a note** restores its document-anchored viewport and caret, retaining ordinary folds. The bounded session cache separates vault, pane and path, so matching note names or open split panes do not steal one another's position. Explicit heading/block/line targets take precedence. No note-content rewrite or persistent position schema.
- **Copy answer** copies the exact Markdown/HTML reply; HTML also offers **Copy text**. Text is selectable, and failures keep the answer available. The Rendered/Source view switches without regenerating.
- **File tree → right-click → Send to AI chat** attaches a saved Markdown note, notes in a folder, or the chosen group, without opening the file or generating an answer. Exact note paths are retained as request sources and their strictest rule is carried through the conversation. AI-never, unreadable, or oversized selections fail visibly; maximum 100 notes and 250,000 characters. Late reads from another vault or superseded attachment actions are ignored. Multiple notes cannot be applied as a single-note edit. The existing Ask AI modal action remains available.
- **Format: Markdown / HTML** is remembered per vault on this device. The choice controls new Ask answers; existing turns retain their format and suggested note edits stay Markdown. Completed HTML is saved as a privacy-marked draft using the expected vault root, shown in the existing opaque-origin offline page sandbox and can be opened in a tab. Draft failures retain source/copy and offer a preview retry without rerunning AI. The page is never injected into the app DOM.

Files: sidebar chat, state/output helper, sidebar/global zoom styles, Editor snapshot code, file-tree context menu and their tests; native sidebar and note-position specs. No dependency, Rust/native capability, production identifier, provider, source format, or unrelated T-220/T-223 integration.
