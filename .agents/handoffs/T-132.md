# T-132 — Note headers scroll with the document

## Built

The note cover, large icon, title, tools and properties share the document's scroll surface. They scroll completely out of view and return at the top, including an icon without a cover. The old scroll-triggered compact cover strip and React scroll listener are removed.

React renders metadata through a stable portal target above CodeMirror's editable content. A wrapping flex layout preserves CodeMirror's required flex scroller, full-width page metadata, text width and optional outline gutters. The metadata remains outside the Markdown document and the editor retains its bounded scroll area/virtualization. Conflict/recovery banners remain outside the scroller and the main app's save status remains in its status slot.

Capture cursor/scroll state during layout cleanup, before React removes the portal or detaches the editor; the old passive cleanup can otherwise observe a reset/clamped scroll position. Switching notes now retains the offset in the native regression.

Files: src/features/editor/{Editor.tsx,PageHeader.tsx,editor.css,pageHeader.css,pageHeader.test.tsx}; e2e/specs/scroll-header.e2e.ts; task brief/board/handoff. No dependency, version, file-format or native source changes. User vaults were not edited.

## How to check

Open a long disposable note with a cover and icon. Scroll down: the entire page header should leave the viewport with the content. Return to the top: cover, icon, title and properties should appear above the writing and span the note width. Rename/edit/save the note, remove its cover, enable outline view and repeat. Switch away while scrolled and back: the saved offset should be restored. The new native spec also checks metadata/body geometry and normal editing/saving.
