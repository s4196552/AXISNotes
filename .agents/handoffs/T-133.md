# T-133 — Default heading folding and mixed hierarchy

## Behavior

Standard Markdown headings now have inline, keyboard-accessible collapse/expand controls without enabling Outline view. H1 contains subsequent H2–H6 sections, H2 contains H3–H6, and so on. A same-level or higher-level heading ends the section; skipped levels work. All intervening body content folds with its owning heading, including paragraphs, lists, quotes, tables, images and code blocks. Expanding a parent retains existing child folds.

Built-in `> [!toggle|hN]+/-` headings use the same section boundaries, including unquoted content and ordinary subheadings. Plain toggle lists retain their existing quoted-body boundaries. Their +/- state still saves in Markdown. Standard Markdown heading folding uses CodeMirror's view state and never rewrites the source; it is not new persistent cross-session fold storage.

A shared full-document section scanner handles ATX and Setext headings, ignores frontmatter, fenced code (including unequal fence lengths and quoted fences) and HTML comments, and feeds both fold controls and existing outline section operations. The immutable-document cache avoids repeated scans of the same document during one view update. Nested persisted toggle ranges are combined before applying replacements. Closing a toggle whose cursor is inside its body places the cursor on its title so the explicit close action takes effect.

The existing toggle test fixture now includes an explicit peer heading before the unrelated toggle list, matching the requested heading-boundary rule. Its custom-arrow count excludes the newly added standard-heading arrows.

## Manual acceptance

Create H1 → H2 → H3 (or H6), with paragraphs, lists and attachments between them. Collapse a child, then its parent; expand the parent and confirm the child remains collapsed. Content after the next peer belongs to that peer, and content after the next H1 remains outside the earlier H1. Repeat with `> [!toggle|h1]+ Parent`, ordinary `## Child`, and `> [!toggle|h3]- Nested`. Plain Markdown folds should not dirty the source; custom toggle +/- changes should autosave normally.
