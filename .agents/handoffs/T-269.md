# T-269 handoff: `![[Page.html]]` embeds vault web pages in notes

## What was built

Option c of the approved proposal (`docs/proposals/html-in-notes.md`). A line that is only
`![[Page.html]]` (or `.htm`) now shows the page inline, in the same sandboxed frame as a
page tab. `![[Page.html|600]]` sets the height in pixels: the default is 480 and the
allowed range is 120 to 2000. A bar above the frame shows the page name with Reload, Open
(in a tab) and Edit link. Pages are found the way images are: by name anywhere in the vault,
or by a `./` path relative to the note.

The frame and its message handling now live in one component, `PageFrame`, used by both the
page tab (`WebFileView`) and the embed, so their security settings can't drift apart:

- `sandbox="allow-scripts allow-forms allow-modals"`. There is no `allow-same-origin`, so the
  page has a null origin and Tauri IPC refuses it. There are no popups or top navigation.
- The only source is the `axispage:` URL from `backend.pageUrl`. `srcdoc`, `data:` and
  `blob:` are never used. The page protocol's own CSP (`default-src 'none'`, no
  `connect-src`) still applies, and `pages.rs` is unchanged.
- Links and study results are taken only from that frame's own window, while it has focus
  (as in T-190, T-192 and T-261). The page reloads when the file changes on disk.
- Embeds use `loading="lazy"`, and CodeMirror draws only widgets near the viewport. The
  embed code is a separate chunk, loaded the first time a note has one.

Where frames can't show (the browser preview), the embed offers Open in browser.

## Files

- `src/features/drafts/PageFrame.tsx` (new): the shared sandboxed frame. `PAGE_SANDBOX`
  moved here and is re-exported from `WebFileView`.
- `src/features/drafts/PageEmbed.tsx` (new): the embed card.
- `src/features/drafts/WebFileView.tsx`: uses `PageFrame`.
- `src/features/drafts/drafts.css`: embed styles.
- `src/features/editor/embeds.ts`: `isPageTarget` and `PageWidget`; a page line no longer
  becomes a note embed.
- `src/features/drafts/drafts.test.tsx`: four new tests.

## How to test

`pnpm vitest run src/features/drafts` runs 14 tests: targets and heights, the editor
decoration (not inside code fences), the frame's sandbox, lazy loading, height, reload,
open and edit link, a missing page, and the browser fallback.

In the desktop app, run the Practice test skill as HTML on a note. Then type
`![[<the page name>.html]]` on its own line in any note and move the cursor away.

## Known gaps

- The height is fixed, set by the number. The page doesn't report its own height, so
  `pages.rs` stays unchanged.
- There's no click-to-load setting or cap on frames per note beyond lazy loading and the
  CodeMirror viewport.
- A page embed inside a list item, or in a note shown inside another note's embed, stays as
  text.
