# T-083 handoff: Notion-style page icons and cover banners

## What was built
- **Page header** (`editor/PageHeader.tsx`, `pageHeader.css`) above each note's title:
  - The note's custom icon at 64 px (the same `folderIcons` entry the file tree uses);
    click to change. Hover shows **Add icon** / **Add cover** when missing.
  - A cover banner (26 vh, 120–260 px). Hover actions: **Change cover**, **Reposition**
    (images; drag, or ↑/↓ in 5 % steps, Enter saves, Esc cancels; a `slider` while
    active), **Remove cover**.
  - Cover picker popover: **Gallery** (8 gradients, 9 colours) and **Images** (vault
    images with a filter, plus **Upload image…**).
  - Once the note scrolls more than 24 px, a note with a cover shrinks it to a 28 px strip
    and hides the icon row (CodeMirror owns the scrolling, so the header can't scroll away).
- **Frontmatter format** (`lib/cover.ts`), compatible with the Obsidian Banners plugin:
  `banner: "[[path.png]]"` (also `![[…]]`, `[[…|alias]]`, plain paths), `banner_y: 0–1`
  (1–100 read as %), plus `gradient:<name>` and `#rrggbb`. Web addresses are not fetched;
  the cover explains why. A missing image says "Cover image not found: …". `banner` and
  `banner_y` are hidden from the properties chip. A new cover resets `banner_y`.
- **Image icons:** the icon picker gains an **Image** tab (vault images + upload), stored
  as `image:<path>`; `EntryIcon` renders them (file tree and header) and falls back to the
  default icon if the image is gone.
- **Upload:** `backend.pickImage()` (native dialog, image filter) and
  `backend.importImage(source, folder)` → Rust `import_image`: image extensions only,
  25 MB cap, free name (`x 1.png`), never overwrites, folder resolved inside the vault,
  marked as a self-write and indexed. Goes to `attachments/` beside the note.
- `Editor.changeProps` keeps a cursor that was below the frontmatter below it, so adding
  the first property or a cover no longer unfolds the YAML block.
- Browser preview: `fileUrl` serves SVG files as data URLs; `pickImage` returns null.

## How to test
- `pnpm lint && pnpm typecheck && pnpm test`, Prettier: see the review for results.
  New tests: cover parsing (forms, gradients, colours, web, junk, `banner_y`), gradient →
  colour → remove, vault image cover + keyboard reposition + Esc, upload into
  `attachments/`, web and missing covers, page icon (emoji, picker, image icon), YAML
  stays folded.
- `cargo test`: 113 passed, 2 existing ignored; new tests for free names, copy-in,
  non-images, missing files, folders, escapes, bad names and the size cap. rustfmt and
  clippy clean.
- Preview (memory backend): Welcome → Add cover → Ocean; Add icon → Rocket; YAML stays
  behind its chip; scrolled the note → 28 px strip.

## Known gaps
- Not checked in the desktop app: PNG/JPEG covers through the asset protocol, the native
  image dialog and a real upload. The Rust command is unit-tested and image embeds already
  use the same `fileUrl`, but nobody has clicked through it in Tauri yet.
- Renaming an image doesn't update covers or image icons that point to it.
- Grids and canvases don't get covers (notes only, per the brief).
- With only cover keys in the frontmatter, the folded chip still reads "Properties (edit
  above, or click to show YAML)".
