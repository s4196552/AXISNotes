# T-069 handoff: Translucent theme

## What was built

- **Translucent** (`axis:translucent`), a new built-in theme that makes the window itself see-through, so the desktop shows behind the app. It follows the OS light/dark setting.
- **Settings → Appearance**, while Translucent is the theme:
  - **Window opacity** slider, 20–100% in 5% steps, default 80%.
  - **Blur behind the window** checkbox, default on (Windows acrylic).
  - Both are saved in `.axisnotes/config.json` as `appearance.windowOpacity` and `appearance.windowBlur`. Older configs get the defaults through `mergeConfig`.
- **The theme tile** previews it over a mock wallpaper at the current opacity.
- **When the blur is skipped:**
  - **Windows "Transparency effects" are off** (`prefers-reduced-transparency: reduce`, which WebView2 reports). Windows would otherwise draw acrylic as solid grey. The window stays see-through, unblurred, and Settings explains how to turn the effects on. The app re-checks when the Windows setting changes.
  - **The window can't be see-through** (anything other than Windows, and the browser preview). The theme stays solid, and both settings are disabled with a note.

## How it works

- **`tauri.conf.json` creates the main window with `transparent: true`.**
  - Every other theme paints an opaque page, so they look unchanged.
  - `app.css` paints a solid light/dark page until a theme takes over (not an inline `<style>` in `index.html`: Tauri would hash it into the CSP, which blocks CodeMirror's injected styles).
  - `:root[data-theme="translucent"]` clears it.
- **`applyTranslucency` (`src/app/appearance.ts`) sets `--tl-alpha` on the document** (1 unless Translucent is on and supported). It calls `backend.setWindowBlur` only when the blur state changes; a slider sends many updates.
- **The Tauri backend's `setWindowBlur` calls `getCurrentWindow().setEffects([Acrylic])` or `clearEffects()`.** Both go through `core:window:allow-set-effects`, which is now in the capability. There is no separate clear permission.
- **Only `--app-backdrop` carries the opacity.** `--bg` and `--bg-sidebar` are faint tints, so nested surfaces don't stack into opaque patches. The main area gets one tint, and its editor and graph are transparent. Menus and dialogs are 97% opaque.

## How to test

- `pnpm lint`, `pnpm typecheck`, `pnpm exec vitest run`.
- `pnpm e2e:build && pnpm e2e --spec e2e/specs/knowledge.e2e.ts`. The new test picks Translucent, sets 50%, and checks:
  - the saved config;
  - `--tl-alpha` (0.5 on Windows, 1 elsewhere);
  - the cleared page background;
  - that no window-effect call failed.
- **By hand on Windows:** pick Translucent and move the slider. With Windows transparency effects on, the desktop behind is frosted. With them off, it shows through unblurred.

## Native check (lead, 2026-10-09)

- **Setup:** an OS-level capture of the real debug build over a test-pattern window (not committed).
- **Opaque themes:** unchanged.
- **Translucent at 30%, blur off:** the pattern shows through the whole window as intended.
- **Blur on this machine:** Windows transparency effects are off, so acrylic rendered solid grey. That led to the fallback above.

## Known gaps

- **Not verified natively:** acrylic with transparency effects on. I didn't change the system setting; whether Windows 11 keeps acrylic on an inactive window is also unverified.
- **macOS:** needs Tauri's `macos-private-api` (App Store-incompatible), so the theme stays solid there.
- **Linux:** depends on the compositor; the theme stays solid for now.
- **Custom user themes** that use translucent `--bg` colours now sit on the solid page from `app.css`. Before, they sat on the webview's white.
