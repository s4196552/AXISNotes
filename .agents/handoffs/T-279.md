# T-279 + T-280 handoff

Branch `agent/claude/T-279` (worktree `../axis-T-279`). Both tasks are on one branch.

## What was built

**T-279: only real changes reload panels**

- `Index::update_path` now returns whether the note's structure changed. `upsert_in` hashes what panels show besides the text (`structure_sig`: title, headings, links without their offsets, tags, aliases, block IDs, tasks with their lines, properties). It compares that hash with the one stored in a new `notes.sig` column. Existing indexes get the column with `ALTER TABLE`, not a rebuild. Until a note is saved once, its `sig` is NULL, and that first save counts as a change.
- `write_file` returns `{ modifiedMs, structureChanged }` (`WriteOutcome`). If the index is unavailable or fails, it reports `true`.
- TS `WriteResult.structureChanged`. `memoryBackend` compares a matching signature (`structureOf`).
- Store: `indexVersion` is replaced by `structureVersion` (panels re-query on it) plus `contentVersions[path]` (bumped on each app save of that path). `noteWritten(path, structureChanged)` bumps the note's content version, and the structure version only when the structure changed. `bumpIndex()` and `refreshTree()` keep the old `notes` array when `sameNotes` finds no difference, so editors don't restyle their links.
- Re-query on `structureVersion`: graph and local graph, backlinks and unlinked mentions, search, tags, the tasks view, the time report and the dashboard's tasks.
- Re-read on one note (`useContentVersion(path)`, which is `structureVersion` plus that note's saves): the outline, canvas note cards, dashboard note widgets and the heatmap's notes.
- Writers that report through `noteWritten`: the editor, `useFileDocument` (grid, canvas and other documents), `editNote`, and embed write-backs and block IDs (`embeds.ts`).

**T-280: keep the UI thread free**

- These commands are now `#[tauri::command(async)]`: `list_tree`, `read_file`, `write_file`, `create_file`, `save_attachment`, `import_image`, `import_font`, `import_skill`, `create_dir`, `trash_entry`, `list_tags`, `list_property_keys`, `list_tasks`, `time_entries`, `list_notes`, `resolve_link`, `list_axis_files`, `list_packs`, `updates_check`, and the keychain-touching `ai_settings`, `ai_save_settings`, `ai_set_key`, `ai_delete_key`.
- `Index::sync_subtree(vault, rel)` walks only that folder. A folder change (`update_path` on a directory) uses it instead of a full `sync`. `sync_with_progress` shares the code (`sync_scope`).
- The watcher dedupes each batch with a `HashSet`, keeping the first of each change in order (`dedupe`). `VaultChange` and `ChangeKind` derive `Hash`.
- `list_tree` sorts with `sort_by_cached_key`.

## How to test

- `npx vitest run src/features/panels/typingReloads.test.tsx` mounts the editor with backlinks, outline, tags, search and the local graph, and counts backend calls. Four plain-text autosaves make no `graph`, `backlinks`, `unlinkedMentions`, `search`, `listTags` or `listNotes` call. A new link, tag or heading reloads each panel once.
- `cargo test --lib index::` runs `update_path_reports_structure_changes_only`, `notes_indexed_before_signatures_count_as_changed_once` and `sync_subtree_walks_only_that_folder`. `cargo test --lib watcher` covers `dedupe`.
- In the app: open a note with the right sidebar showing backlinks and the local graph, then type a sentence. Nothing reloads. Type `[[` plus a note name: the graph and backlinks update after the save.

## Known gaps

- Search results and unlinked mentions are refreshed only by structure changes or a new query. A word typed into one note appears in the results of an existing search only after the next structural change or query edit. The same applies to a new mention of the active note typed in another note.
- In split panes, the backlinks panel for note B shows the line text of A's link as it was at A's last structural change.
- Tasks are compared with their line numbers, because the tasks view edits by line. Pressing Enter above a task in a note therefore counts as a structure change.
- Commands that are still synchronous are cheap or need the main thread (`current_vault`, `reveal_entry`, `open_in_browser`, window and clipper commands).
