# T-268 handoff: study skills write study blocks

## What was built

When Markdown is picked, the built-in **Flash cards**, **Practice test** and **Mind map**
skills now write the T-267 study blocks instead of folded callouts or a Mermaid
mindmap:

- Flash cards: a `# ` title and one ` ```flashcards ` block (`Q:` / `A:` pairs).
- Practice test: a `# ` title and one ` ```quiz ` block (`Q:`, `- [ ]` / `- [x]` options or
  `=` answers, `>` explanation).
- Mind map: one ` ```mindmap ` block (`title:` and a nested list).

Each format section shows the model a worked example. A test checks that every example
parses.

`runSkill` now checks a Markdown answer from these skills. If it has no closed block of the
right kind, or a block doesn't parse, the model is asked once more, given the parser's
messages (for example "line 1 of the ```flashcards block: This card has a question but no
answer"). This works the same way as the existing retry for pages and Teach files. If the
second answer is still wrong, it is kept: the note shows the error card naming the line,
and no text is lost.

The check applies only when the skill's instructions ask for the block. Copies of these
skills saved in the vault before this change (callouts, Mermaid) run as they did. The HTML
formats are unchanged.

## Files

- `src/features/skills/builtinSkills.ts`: the Markdown format sections of `mindmap`, `test`
  and `flashcards`, and the mind map's description.
- `src/features/skills/skillRun.ts`: `studyBlockOf`, `studyBlockProblems` and the retry in
  `runSkill`.
- `src/features/skills/skills.test.tsx`: format assertions and new tests (the examples
  parse; missing, unclosed and broken blocks; a retry with the parser's message).
- `src/features/skills/skillDestination.test.tsx`: the sidebar test answers with a valid
  mind map.

## How to test

`pnpm vitest run src/features/skills` runs 71 tests. In the app, run Flash cards with
Markdown on a note: the result is a ` ```flashcards ` block that shows as cards once it's
inserted.

## Known gaps

The HTML pages still report results through `postMessage`, as before, and Markdown blocks
report through the card. The two paths are separate but end in the same `recordStudy`.
